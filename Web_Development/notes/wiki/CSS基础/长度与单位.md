# 长度与单位 · Length & Units

> **一句话**：长度永远是「一个数 + 一个单位」，`18px` 对 `18 px`；绝对单位是固定的名字不是固定的保证，相对单位才是能随屏幕伸缩的那一半。

课件原文见 [Lecture_03_CSS.pptx](<../../raw/Lecture_03_CSS.pptx>)。本篇覆盖 Week 3 的 "Length & Units" 一节：带单位的语法规则、绝对单位的真实比例、相对单位总表、`em` vs `rem` 的区别，以及视口单位。

## 一、长度 = 数 + 单位

| 规则 | 例子 |
|---|---|
| 永远不要裸数字 | `10px`、`2em`、`50%` |
| 长度会出现在哪里 | `width`、`margin`、`padding`、`font-size`、`border-width`…… |
| **数字和单位之间不许有空格** | `18px` 对，`18 px` 错 |
| 零不需要单位 | `margin: 0`，不是 `margin: 0px` |

```html
<div style="font-size: 18px; margin: 2em; width: 50%;">
```

"零不需要单位"是因为 `0` 就是 `0`——加不加单位，值没变，字数却变了。

## 二、绝对单位：名字，不是承诺

课件给了一条换算基准（`1in = 96px = 2.54cm`），并把 10 个单位画成按比例的横条：

| 写法 | 换算 | 相对大小 |
|---|---|---|
| `10in` | = 10.00 in | 最大 |
| `10cm` | ≈ 3.94 in | |
| `10pc` | ≈ 1.67 in | |
| `10mm` | ≈ 0.39 in | |
| `10pt` | ≈ 0.14 in | |
| `10px` | ≈ 0.10 in | 最小 |

从这六个数能直接读出量级差：`in` 是 `px` 的 100 倍量级，`pt` 和 `px` 相差约一截，`pc`（pica）落在中间。

> [!warning] Absolute is a name, not a promise
> 课件的原话：**绝对单位是一个名字，不是一张承诺**——`px` 依然会随屏幕密度（screen density）变化。所以在写死的排版尺寸（例如 `border-width: 1px`）上用绝对单位没问题，但**排版尺寸本身**用绝对单位就锁死了。真正会随屏幕变的是相对单位，那才是响应式的关键，见 [[响应式与媒体查询]]。

## 三、相对单位总表

| 单位 | 相对于 | 典型用途 |
|---|---|---|
| `em` | 元素**自己**的 `font-size` | 可伸缩的、局部的文字 |
| `rem` | 根元素 `<html>` 的 `font-size` | 可预期的全局文字 |
| `%` | 父元素 | 流动的宽度与布局 |
| `vw` | 视口宽度的 1% | 整屏区块 |
| `vh` | 视口高度的 1% | 整屏高度的 hero 区 |

课件的判断是：**相对单位随上下文一起缩放——这是响应式设计的关键**。

## 四、`em` vs `rem`

这是本节最该记牢的一组对照：

| | `em` | `rem` |
|---|---|---|
| 相对对象 | 父元素（parent）的 `font-size` | 根元素 `<html>` 的 `font-size` |
| 会不会叠乘 | **会**——嵌套的 `em` 互相相乘，尺寸可能滚雪球 | **不会**——到处是同一个根值 |
| 控制范围 | 局部（local）：缩放容器即可缩放整个组件 | 全局（global）：改一次根值，全站一起缩放 |

课件给的选择原则：**可预期的文字用 `rem`，需要局部缩放用 `em`**。

叠乘的实际后果：外层 `font-size: 2em`，里面再写 `2em`，得到的是 `2 × 2 = 4` 倍；再嵌一层就是 8 倍。`rem` 不存在这条链，因为它永远只对着 `<html>`。

## 五、视口单位与 `100vh`

| 写法 | 含义 |
|---|---|
| `vw` / `vh` | 视口宽度 / 高度的 1% |
| `100vh` | **正好是可见屏幕的高度** |
| `vmin` / `vmax` | 宽高两者中较小 / 较大的那个 |

```html
<section style="height: 100vh;">
```

`100vh` 的典型用途是**整屏区块**（a section that fills the window）——示例站的 `header` 就是这样撑满第一屏的。

## 六、和字体的关系

`font-size` 本身也吃这套规则。浏览器默认 `16px`，所以**`1em = 16px`**——这条换算是 `em` 后面所有计算的地基，细节在 [[文本与字体]]。

## 七、易错点

- 写成 `18 px`、`50 %`：数字与单位之间的空格是语法错误，不是风格问题。
- 在需要"零"的位置写 `0px`。
- 用绝对单位做**会随屏幕变**的尺寸（字号、行宽、区块高度）。
- 以为 `em` 比 `rem` "更现代"：它是**嵌套会叠乘**，组件里用 `em` 缩放很好，层层嵌套的正文里用 `em` 排版会失控。
