# 容器与语义化 · Containers & Semantics

> **一句话**：`div` 和 `span` 是**不带含义**的通用容器（一个块级、一个行内），而 `header` / `nav` / `main` / `section` / `article` / `footer` / `aside` **自带含义**——课件的判断标准是一句话：**有语义标签就用它，`<div>` 是最后手段。**

课件原文见 [Lecture_02_HTML.pptx](<../../raw/Lecture_02_HTML.pptx>)。本篇覆盖课件的 "Grouping Content"、"Block vs Inline Elements"、"Containers — `<div>` & `<span>`"、"Why Semantic HTML?"、"The Semantic Toolkit"、"`div` vs `section`" 和 "A Semantic Page" 七部分。

## 一、为什么要分组

课件的回答是：**Wrap related elements into one unit you can treat as a single box**（把相关元素包成一个整体，好把它当成**一个盒子**对待）。

于是有了三种容器：

| 容器 | 课件的说法 |
|---|---|
| `<div>` | **块级容器**——为了布局，把整块内容分组 |
| `<span>` | **行内容器**——把行内一段文字分组 |
| 语义容器 | `header`、`nav`、`main`、`section`……——**带含义的分组** |

```html
<div>  <h2> + <p> + <a>  </div>
```

课件用这一行表达意图：一个 `div` 里装一个标题、一个段落、一个链接——**它们从此是一个单元**。

## 二、块级与行内

课件用两张表对照，这是整页的核心：

| 块级元素（block） | 课件的说法 |
|---|---|
| **Start on a new line** | **另起一行** |
| **Take the whole line** | **占满整行** |
| **Stack vertically** | **垂直堆叠**——`p`、`div`、`h1`、`ul`、`section`… |
| **Contain other blocks** | 块级元素**能装块级和行内内容** |

| 行内元素（inline） | 课件的说法 |
|---|---|
| **Flow with the text** | **跟着文字流动**，待在一行文字里 |
| **Take only the room it needs** | **只占它需要的空间**——`span`、`a`、`strong`、`em`、`img`… |
| **Cannot contain blocks** | 行内元素**只能装行内内容** |

> [!important] 最容易出错的那条：行内不能装块
> 这是 HTML 的硬规则。`<span>` 里塞一个 `<div>` 是无效的，浏览器会"纠正"你，结果是 DOM 结构和你写的完全不同——这类错误要到 [[DOM与开发者工具]] 里打开 Elements 面板才看得见。
>
> 课件说 **Week 4's box model builds on this**（Week 4 的盒模型建立在这之上）：块级和行内，正是"盒子怎么摆"的第一道分岔。

## 三、`div` 与 `span`

| | `<div>` | `<span>` |
|---|---|---|
| 课件的说法 | **块级容器**——**另起一行，占满整行** | **行内容器**——**跟着文字流动，只占需要的空间** |
| 用途 | **为布局把整块内容分组** | **标记一段行内文字** |
| 共同点 | **Generic by design**（设计上就是通用的）——**两者都不携带含义**，**是 `class` 和 `style` 给了它们用途** | 同左 |

```html
<div class="container">
  <h2>London</h2>
  <p>The capital city.</p>
</div>
<h1>My <span class="hl">Important</span> Heading</h1>
```

- `div.container` 独占一整行，把标题和段落归成一组。
- `span.hl` 在 `h1` **内部**跟着文字流动，只包住 "Important" 这一个词——**因为 `div` 在这里根本用不了**（`<h1>` 是块级容器，里面不能再放块级元素）。

> [!tip] 那句"class 和 style 给了它们用途"是重点
> `div` 和 `span` 自己什么都不说。**`<div class="container">` 和 `<div>` 在浏览器眼里是同一个东西**——`class="container"` 只是给 CSS 用的名字，让样式表能选中它。
>
> 这带来一个实际的推论：**一个页面如果全是 `div`，那么这份 HTML 里没有任何一处说明了"哪块是什么"。** 这正是下一节要解决的问题。

## 四、为什么需要语义化 HTML

课件的标题是 **Why Semantic HTML?**，副标题 **Meaning, not just boxes**，第一条是：

> **A `<nav>` says navigation — a `<div>` says nothing.**
> （一个 `<nav>` 说明这是导航——一个 `<div>` 什么都不说。）

然后给了三个理由：

| 理由 | 课件的说法 |
|---|---|
| **Accessibility** | 屏幕阅读器**靠 landmark 导航** |
| **SEO** | 搜索引擎**理解你页面的结构** |
| **Maintainable** | 你和你的团队读到的是**意图**，不只是版式 |

```html
<header>  <nav>  <main>  <footer>
```

这一行叫 **Landmarks a screen reader can announce**（屏幕阅读器能念出来的地标）。

> [!note] landmark 是什么意思
> 它是页面上的"区域标记"。屏幕阅读器用户可以问："这个页面有哪些区域？"然后直接跳到"导航"或"主要内容"，**不必从头读到尾**。**只有用了语义标签，这些区域才会存在**——全篇 `div` 的页面，在屏幕阅读器那里是**一片没有结构的文本**。

## 五、语义工具箱

| 标签 | 课件的说法 |
|---|---|
| `<header>` | 顶部横幅——**logo 和标题** |
| `<nav>` | **主导航链接** |
| `<main>` | 主要内容——**每页一个**（one per page） |
| `<section>` | 一段**有主题的内容分组** |
| `<article>` | 一块**自成一体的内容**——一篇文章、一张卡片 |
| `<footer>` | 底部——版权、联系方式、链接 |

课件给的骨架是：`header` → `nav` → `main`（内含 `section` → `article`）→ `footer`。

## 六、`div` vs `section`

| `<div>` | `<section>` |
|---|---|
| **Generic container**——**没有内置含义** | **有含义**——一段有主题的内容 |
| **For layout & styling**——为 CSS 分组，**不为含义** | **Usually has a heading**——通常有一个描述它的标题 |
| **When nothing fits**——**没有任何语义标签适用时的兜底** | **Part of the outline**——**构成页面大纲的一部分** |

课件的判断标准，原话照录：

> **Rule of thumb: if a semantic tag fits, use it; `<div>` is the last resort.**
> （经验法则：**有语义标签合适就用它；`<div>` 是最后手段。**）

判断的顺序可以这样走：**这块是导航？→ `nav`。是独立的一篇文章/卡片？→ `article`。是有主题的一大段，但不是独立内容？→ `section`。只是想把几个元素框起来做样式？→ `div`。**

## 七、一份语义页面

```html
<body>
  <header><h1>My Site</h1></header>
  <nav><a href="/">Home</a>…</nav>
  <main>
    <article><h2>Post</h2><p>…</p></article>
  </main>
  <aside>Related links</aside>
  <footer>© 2026</footer>
</body>
```

课件的说明：

| 课件的说法 | 意思 |
|---|---|
| **Landmarks** | `header`、`nav`、`main`、`footer` **勾出页面轮廓** |
| **One main** | 主要内容待在**唯一一个 `<main>`** 里 |
| **article** | `main` **里面**的一块自成一体的内容 |
| **aside** | **旁注**——相关但独立的内容 |

课件的结论：**This skeleton appears in almost every site you will build this semester**（这个骨架会出现在你这学期做的**几乎每个站点**里）。

> [!important] 这就是示例站的骨架
> 本库全篇共用的那个假想课程主页（「示例站」，设定见 [[课程场景与阅读约定]]）——顶部 `header` + 导航 `nav`、`main`（课程表格 + 报名表单 + 配图）、底部 `footer`——就是上面这一段。
>
> 回头对照就能看出：哪些格子是 `div`（纯排版），哪些是 `section` / `article`（有含义），差别决定了屏幕阅读器能不能在正确的位置停下来。
