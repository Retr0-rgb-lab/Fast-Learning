# 列表与表格 · Lists & Tables

> **一句话**：三种列表（`ul` / `ol` / `dl`）用**嵌套**表达大纲，表格（`table`）有一条不可违反的规矩——**For data only：只放数据，绝不用来做页面布局**。

课件原文见 [Lecture_02_HTML.pptx](<../../raw/Lecture_02_HTML.pptx>)。本篇覆盖课件的 "Lists" 与 "Tables" 两部分。

## 一、三种列表

| 标签 | 名字 | 课件的说法 |
|---|---|---|
| `<ul>` | Unordered list | 无序列表——**项目符号**（bullets） |
| `<ol>` | Ordered list | 有序列表——**编号**（numbers） |
| `<li>` | List item | 列表项，**`ul` 或 `ol` 的子元素** |
| `<dl>` · `<dt>` · `<dd>` | Definition list | 定义列表——**术语 + 描述** |

```html
<ul>
  <li>HTML</li>
  <li>CSS</li>
</ul>
<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language</dd>
</dl>
```

三者分工：

- `<ul>`：只是一串同级的项，顺序不重要。
- `<ol>`：项之间**有先后关系**，编号本身携带信息。
- `<dl>`：每一组是**一对**——`<dt>` 是被解释的术语，`<dd>` 是它的解释。

### 嵌套

课件对嵌套给出的理由是：**Lists can nest for outlines and menus**（列表可以嵌套，用来表达**大纲**和**菜单**）。

```html
<ul>
  <li>HTML</li>
  <li>
    <ul>
      <li>Nested</li>
    </ul>
  </li>
</ul>
```

同一个结构，用来排"大纲"就是章节树，用来排"菜单"就是侧边导航。**HTML 只需要换容器，不用换结构**——这也是为什么用 `<ul>` 排菜单比用一堆 `<div>` 更好：它天然带着"这是一串条目"的信息。

> [!note] 嵌套就是[[元素与标签语法]]那条规则
> "`ul` → `li` → `ul` → `li`"是三级父子，**按相反顺序闭合**、**缩进体现层级**这两条规则在这里第一次真正派上用场。

## 二、表格

### 七个标签

| 标签 | 作用（课件原话） |
|---|---|
| `<table>` | 表格容器 |
| `<tr>` | 一个表格行（row） |
| `<th>` / `<td>` | 表头单元格（**自动加粗**）/ 数据单元格 |
| `<caption>` | 表格**上方**的可见标题 |
| `rowspan` / `colspan` | 让单元格**跨行**或**跨列** |
| `<thead>` / `<tbody>` | 把**表头行**和**正文行**分组 |

```html
<table>
  <caption>Monthly savings</caption>
  <tr><th>Name</th><th>Mark</th></tr>
  <tr><td rowspan="2">Ada</td><td>95</td></tr>
  <tr><td>88</td></tr>
</table>
```

读法：

- `<caption>Monthly savings</caption>` 是**可见**的标题，写在 `<table>` 之后、任何 `<tr>` 之前。
- 第一行是两个 `<th>`，课件注明它们是**加粗的**表头——注意这是**浏览器默认加粗**，不是 `<th>` 故意要粗。
- `rowspan="2"` 让 "Ada" 这个单元格**占两行**，所以第三行只需要再给一个 `<td>`（88）。

课件提到 `<thead>` / `<tbody>` 的用途是**分组**：把表头和正文行分开。上面这个最小例子没写它们，但一旦行数多起来就应该用上——这和"h1 之后接 h2"是同一种分层思路，见 [[文本语义]]。

### 那条规矩

> [!important] For data only — use tables for data, not for page layout.
> （只用于数据——表格是给数据的，不是给页面布局的。）

这是本篇最重要的一句。**表格表示的是二维的、行列之间有对应关系的数据**（一张成绩表、一个价格表）。它不是"排版工具"。

历史上很多网页用 `<table>` 排整个页面——左边一列、右边一列、上面一行下面一行。今天这样做是错的，理由是：

| 用表格排布局 | 用语义标签 |
|---|---|
| 屏幕阅读器读出来是"表格，3 行 2 列"，然后逐格念 | 读出来是"导航 / 主要内容 / 页脚" |
| 页面结构变成一堆隐含的关系 | 结构直接写在标签上 |
| 想改布局就得重排表格 | 换 CSS 即可 |

课件在表格那页还留了一句预告：**Week 4 will style these with CSS — structure first**（Week 4 会用 CSS 给它们上样式——**结构先行**）。这正是本库分节的顺序：Week 2 只管结构，外观是后面几周的事。
