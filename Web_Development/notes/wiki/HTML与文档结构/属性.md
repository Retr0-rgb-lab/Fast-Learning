# 属性 · Attributes

> **一句话**：属性（attribute）写成 `name="value"` 放在**开始标签里**，它是 HTML 留给 CSS 和 JavaScript 的**同一批钩子**——课件那句"Attributes are the first thing CSS and JS reach for"就是本篇的中心句。

课件原文见 [Lecture_02_HTML.pptx](<../../raw/Lecture_02_HTML.pptx>)。本篇覆盖课件的 "Attributes" 一页：属性的写法规则、课件点名的那几个属性，以及它们为什么是 CSS 与 JS 的抓手。

## 一、属性是什么

课件的定义有两句，都很短：

- **Extra information**（额外信息）：属性修改（modify）一个元素。
- **always in the start tag**（永远写在开始标签里）：这是硬规则。**属性不能写在结束标签上。**
- **name="value"**：一个名/值对，值要**加引号**（quoted）。

```html
<a href="https://polyu.edu.hk">PolyU</a>
<img src="logo.png" alt="Logo" width="500" height="600">
<p class="note" id="first" style="color:red">…</p>
```

这三行里出现了九种属性用法，最后一行最典型：**一个元素上可以挂多个属性**，用空格隔开，各自是独立的 `name="value"`。

## 二、课件点名的属性

| 属性 | 作用（课件原话） | 出现在哪 |
|---|---|---|
| `href` | 链接的**目的地**（the link's destination） | `<a>` |
| `src` | 图像的**源文件**（the image's source file） | `<img>` |
| `width` / `height` | 图像尺寸，**默认单位是像素** | `<img>` |
| `style` | **行内样式**（inline styling），只作用于这一个元素 | 任意元素 |
| `lang` | 文档语言，**设在 `<html>` 上** | `<html>` |
| `class` & `id` | **供 CSS 和 JavaScript 找到元素的钩子**（hooks for CSS and JavaScript to find elements） | 任意元素 |

几点需要强调的：

- **`width` / `height` 默认就是像素。** 课件在图像那一页重复了这一点（"Size in pixels by default"），所以写 `width="500"` 表示 500 像素，不是 500 个任何别的单位。
- **`lang` 写在 `<html>` 上**，它声明的是**整份文档**的语言。上一条笔记里骨架的那一行就是 `<html lang="en">`。
- **`class` 和 `id` 什么都不"做"。** 它们不影响外观、不影响内容、不影响行为——它们只是**命名**。作用发生在后面：CSS 用它们选元素，JavaScript 用它们抓元素。

## 三、为什么课件说"属性是 CSS 和 JS 首先够到的东西"

课件这页的收尾是一句加重的话：

> **Attributes are the first thing CSS and JS reach for — learn them well.**
> （属性是 CSS 和 JavaScript 首先伸手去拿的东西——好好学。）

这句话可以拆成两步看：

1. **HTML 本身不 styling。** 上一条笔记里那条常见错误——"styling in HTML instead of CSS"——反过来看就成立：**一旦你要改变外观，你必须有一个办法让 CSS 指名道姓地找到那个元素。** 这个办法就是 `class` / `id`。
2. **JavaScript 同理。** JavaScript 不能"看见"一个元素，它只能按名字去拿。`document.querySelector('.note')` 里的 `.note`，对应的正是属性里写的 `class="note"`。

所以 `class` 和 `id` 这两个属性，是**HTML 交给后两门技术的接口**。HTML 负责结构和命名，CSS 与 JavaScript 负责表现和行为——它们之间的握手全靠属性。

> [!important] `class` 与 `id` 的分工，HTML 就已经定了
> 课件只说了它们都是"钩子"，没有展开两者的区别（那是 [[简单选择器]] 的内容）。但从 HTML 这边已经能看出方向：`id` 在一份文档里唯一（所以配 `<label for>` 时要靠它定位），`class` 可以重复使用（所以一个元素上可以写多个）。这个区别在 [[表单验证与可访问性]] 里会立刻派上用场。

## 四、`style` 属性的位置

`style` 是一个普通属性，值是一小段 CSS：

```html
<p class="note" id="first" style="color:red">…</p>
```

它**只作用于这一个元素**，写在标签里，跟着标签走。

> [!warning] 它的代价写在另一门课上
> 课件把"在 HTML 里写样式"列为语法错误之一。理由不只是"不好看"：写在 `style` 里的规则优先级最高、最难被覆盖、改一个颜色要翻遍全页，而且和外部样式表无法协作。这条留到 [[样式声明与内联]] 和 [[层叠与优先级]] 展开，本篇只需要记住它的位置：**属性里可以写 style，但那是例外，不是常规。**

## 五、易错点小结

| 易错 | 正确 |
|---|---|
| 属性写在结束标签上 | 属性**只在开始标签里** |
| 值不加引号 | `name="value"`，**值加引号** |
| 在标签里写样式充当常规 | 常规是外部/内嵌 CSS；`style` 是一次性的 |
| 以为 `class` 会改变样子 | `class` 只是一个名字，**它自己不产生任何效果** |
| `width="500"` 理解成"500 什么" | 默认**像素** |
