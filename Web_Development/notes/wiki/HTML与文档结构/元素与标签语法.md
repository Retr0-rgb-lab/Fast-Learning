# 元素与标签语法 · Elements & Tags

> **一句话**：HTML 的一切都从**一个元素的解剖**开始——开始标签、属性、内容、结束标签；成对或空元素，嵌套要按开启的相反顺序闭合，而一份完整文档是那七个固定行。

课件原文见 [Lecture_02_HTML.pptx](<../../raw/Lecture_02_HTML.pptx>)。本篇覆盖课件的 "Anatomy of an Element"、"Elements & Syntax Rules"、"A Complete Document" 和 "Nesting & Hierarchy" 四部分。

## 一、一个元素的解剖

课件给了一个例句式的读法：**One element — read it like a sentence.**

```html
<p class="note">Hello, web</p>
```

课件在这页的小标题写的是 **"one element, five parts"**，但它实际标注出来的只有**四个部分**。这四个被标注的部分是：

| 标注名 | 对应片段 | 课件的说法 |
|---|---|---|
| **Start tag**（开始标签） | `<p` | 打开这个元素 |
| **Attribute**（属性） | `class="note"` | 提供额外信息 |
| **Content**（内容） | `Hello, web` | 可见的文本 |
| **End tag**（结束标签） | `</p>` | 关闭这个元素 |

课件随后又用一句公式重述了它：**An element = start tag + content + end tag**（元素 = 开始标签 + 内容 + 结束标签）。

> [!warning] 课件这里有个对不上的地方
> 标题说 **five parts**，标注只画出 **four**，公式也只有三项。属性本身已被单列出来，所以本笔记不替它补一个第五部分——**照课件读，别自己加料**。复习时若被问"五部分是哪五部分"，正确答法是：课件只标注了这四个。

课件给 Week 2 lab 的任务也在这页：**写一个页面，然后把它弄坏，看 DevTools 抱怨。**

## 二、元素与语法规则

课件一次列了六条规则：

### 1. Elements come in pairs（元素成对）

开始标签和结束标签把内容夹在中间：`<p>…</p>`。

### 2. Void / self-closing tags（空元素 / 自闭合标签）

没有内容，所以**没有结束标签**。课件点名的四个：`<img>`、`<br>`、`<input>`、`<hr>`。

### 3. Case-insensitive（不区分大小写）

`<P>` 和 `<p>` 意思相同——但**小写是惯例**（lowercase is the convention）。

### 4. Nest in reverse order（按相反顺序嵌套）

关闭标签的顺序，要和你打开它们的顺序**相反**。

### 5. Indent to show depth（缩进体现层级）

缩进让这棵树**对人可见**。

### 6. Common pitfalls（常见错误）

- **Unclosed tags**（标签没关）
- **Mis-nesting**（嵌套错位）
- **Styling in HTML instead of CSS**（在 HTML 里写样式，而不是写进 CSS）

最小成对例子：

```html
<p><strong>Hi</strong></p>
```

> [!tip] 第三条常见错误值得单独记
> "在 HTML 里写样式"是初学者最常犯的：想变红就往标签里塞东西。课件把它列为语法错误，是因为它属于**结构层的越界**——外观是 CSS 的活。这条错误的另一面见 [[样式声明与内联]]。

## 三、嵌套与层级

课件接着把"成对"这件事展开成**一棵树**：

- **Elements inside elements**：一个 `<li>` 活在 `<ul>` 里面——内容因此成了一棵树。
- **Parent & child**（父与子）：外层那个是父（parent），里面那个是子（child）。
- **Correct order**：按相反顺序闭合。
- **Indent to show it**：缩进让树对人可见。

```html
<!-- nesting: ul → li → ul → li -->
<ul>
  <li>First</li>
  <li>
    <ul>
      <li>Nested</li>
    </ul>
  </li>
</ul>
```

这是三级嵌套：`ul` → `li` → `ul` → `li`。**"ul is parent, li is child"** —— 在最外层那个 `ul` 的意义上，两个 `li` 是它的子元素。

> [!important] 缩进不是装饰，是免费的结构检查
> 写 HTML 时保持缩进，等于让人眼持续验证"父—子"关系是否成立。当闭合标签的位置和缩进对不上时，几乎一定有一处错位——而这正是上面那三条常见错误里的 mis-nesting。

## 四、一份完整文档

课件给出一份可以直接保存运行的完整骨架，逐行解释了每个部分：

| 那一行 | 课件的解释 |
|---|---|
| `<!DOCTYPE html>` | 声明这是 HTML5——**这是一条指令，不是一个标签** |
| `<html lang="en">` | 根元素（root element）；`lang` 设置文档语言 |
| `<head>` | 元数据（metadata）——**不在页面上显示** |
| `<meta charset="utf-8" />` | 字符编码（utf-8） |
| `<meta name="viewport" content="width=device-width, initial-scale=1.0" />` | 配置移动端的响应式设计 |
| `<title>` | 浏览器标签页的标题 |
| `<body>` | 用户真正看到的一切 |

完整写出来是这样：

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, COMP3421!</h1>
</body>
</html>
```

课件的收尾提示：**Save as index.html, double-click it — the browser renders it instantly.**（存成 index.html，双击，浏览器立刻渲染出来。）

> [!note] `<!DOCTYPE html>` 特意不是标签
> 课件特意点出它"是一条指令，不是一个标签"，所以它没有结束标签，也不在 DOM 树里出现一个节点。这个区分在 [[DOM与开发者工具]] 里会再用到一次——那里列的树是从 `html` 开始的。

## 五、写 HTML 需要什么

课件紧接骨架之后给了工具的最低要求：

| 方式 | 课件的说法 |
|---|---|
| **Any text editor**（任意纯文本编辑器） | Notepad（PC）或 TextEdit（Mac）——纯文本就够了 |
| **Save as `.html`** | 扩展名告诉浏览器"这是个网页" |
| **VS Code** | 有语法高亮（syntax highlighting）和代码补全（code completion）的代码编辑器 |
| **Live preview** | 编辑、保存、刷新——立刻看到变化 |

结论句：**You need only a text editor and a browser.**
