# 响应式与媒体查询 · Responsive Design & Media Queries

> **一句话**：响应式是**一份文档应付所有屏幕**，而 `@media` 是那条「按条件换样式」的规则 —— **断点来自内容开始难看的那个宽度**，不是来自任何设备的尺寸。

课件原文见 [Lecture_05_CSS.pptx](<../../raw/Lecture_05_CSS.pptx>)。本篇覆盖其中「Responsive Web Design」「Media Queries」「Media Query Operators」「Mobile-First Breakpoints」「Media Query Recipes」两页与「Layout Cheatsheet」。

## 一、响应式是什么

> **One page, every screen. Not a separate mobile site** —— 同一份 HTML，**按它拿到的宽度重新上妆**。

| 原则 | 说明 |
|---|---|
| **一份文档** | **不是**另做一个手机站 |
| **viewport 标签排在最前** | 少了它，手机**假装自己是 980px 宽**，然后把整页缩小 |
| **流式，不是定值** | 百分比、`max-width: 100%`、**会重排的文字**（而不是裁切） |
| **断点来自内容** | **不是来自设备尺寸** —— 在**布局开始显得难看**的那个宽度切 |
| **会伸缩的布局是免费的** | 常规流和换行的行**自己就会适应**；查询只做剩下的那部分 |

## 二、先把 viewport 标签放在最前面

```html
<!-- 一行，让手机别再说谎 -->
<meta name="viewport"
      content="width=device-width, initial-scale=1">
```

```css
img { max-width: 100%; height: auto; }

/* 一行流体卡片 —— 不需要媒体查询 */
.cards { display: flex; flex-wrap: wrap; }
.cards > * { flex: 1 1 220px; }
```

> [!important] 没有这一行，后面所有媒体查询都会失准
> 浏览器会**假设**页面有 980px 宽，再把它缩小到手机屏幕上。于是你写的 `min-width: 768px` 在手机上也会命中，而页面看着是缩小版的桌面布局。**viewport 标签必须放在 `<head>` 的最前面** —— 它的作用就是先把「屏幕到底多宽」这件事说清楚。

课件对流式的那句总结：**"Responsive design is one document plus rules that adapt — media queries are the half that reacts."**（响应式 = **一份文档 + 一堆适应规则**；媒体查询是其中**会反应的那一半**。）

## 三、`@media` 的组成

| 部件 | 取值 |
|---|---|
| `@media` | 把条件样式包起来的规则 |
| `min-width` | 从这个宽度**往上** —— `600px` · `768px` · `992px` · `1200px` |
| `max-width` | 到这个宽度为止 —— `600px` · `992px` |
| **媒体类型** | `screen`（通常用这个）· `print` · `all` —— **可选，写在特性前面** |
| **其他特性** | `orientation: landscape` · `prefers-color-scheme: dark` 等 |

```css
/* 基础样式 —— 所有屏幕 */
body { font-size: 16px; }

/* 从 768px 宽，往上 */
@media (min-width: 768px) {
  body { font-size: 18px; }
}

/* 只在屏幕宽度 ≤ 600px 时 */
@media (max-width: 600px) {
  .card { padding: 8px; }
}
```

## 四、四个操作符

| 操作符 | 含义 | 例子 |
|---|---|---|
| `and` | **两个条件都要成立** | `(min-width: 768px) and (orientation: landscape)` |
| 逗号 `,` | 一串查询，**任意一个**成立即可。**这是最初的 OR** | `(max-width: 600px), (orientation: portrait)` |
| `or` | 和逗号**同义**，只是写出来了（Media Queries 4 关键字） | `(max-width: 600px) or (orientation: portrait)` |
| `not` | **反转整条查询** | `not (orientation: landscape)` 即竖屏 |
| `only` | 给**从来不懂媒体特性**的老浏览器设的护栏 —— **今天无害** | `only screen and (min-width: 768px)` |

支持情况（课件给的数字）：

| 语法 | 支持 |
|---|---|
| `and` · 逗号 · `not` | **到处都支持** |
| `or` 与范围语法 `(width >= 768px)` | Chrome **104+** · Firefox **102+** · Safari **16.4+**（2022–23 年） |

```css
/* AND —— 两个条件都要真 */
@media (orientation: landscape) and (min-width: 768px) { }

/* OR —— 逗号表示任意其一 */
@media (max-width: 600px), (orientation: portrait) { }

/* 同一个 OR，写出来（Media Queries 4） */
@media (max-width: 600px) or (orientation: portrait) { }

/* NOT —— 除横屏以外的一切 */
@media not (orientation: landscape) { }
```

> [!tip] 范围语法是更短的写法
> `(width >= 768px)` 与 `(min-width: 768px)` 意思相同，但只在 2022–23 之后的浏览器里可用。需要兼容更老的环境时，`min-width` 仍然是稳妥选择。

## 五、移动优先（Mobile-First）

| 步骤 | 做什么 |
|---|---|
| **从小开始** | **基础样式就是手机布局** —— 此时还没有任何条件 |
| **往上加** | `min-width` 在屏幕变宽时**添布局** |
| **覆盖更少** | 你是**搭积木**，不是在拆桌面版 |
| 典型档位 | **600px** 大手机 · **768px** 竖屏平板 · **992px** 笔记本 · **1200px** 桌面 |

```css
/* 移动基础样式 —— 一列 */
.cards { display: block; }

/* 竖屏平板及以上 */
@media (min-width: 768px) {
  .cards { display: flex; }
}

/* 笔记本及以上 —— 间距再宽一点 */
@media (min-width: 992px) {
  .cards { gap: 24px; }
}
```

课件那句总结就是全部要点：**"Mobile-first = base for the small screen, then add up."**（移动优先 = 先给小屏的基础样式，再往上加。）

> [!important] 为什么移动优先省事
> 用 `max-width` 写就得**先把桌面写好，再一条条推翻**；用 `min-width` 写则**基础样式直接可用**，条件规则只负责往上加。你要覆盖的东西越少，样式表就越难烂掉 —— 这和「少写 `!important`」是同一条工程直觉。

## 六、配方表：按条件换样式

**标记结构一个字节都不改**，只有**哪条规则生效**在变。

### 常见配方

| 你想要 | 查询 | 里面的规则 |
|---|---|---|
| **列堆叠** | `@media (max-width: 600px)` | `.row { flex-direction: column; }` |
| **藏掉某样东西** | `@media (max-width: 600px)` | `.ads { display: none; }` |
| **更大的标题** | `@media (min-width: 992px)` | `h1 { font-size: 48px; }` |
| **换个背景** | `@media (min-width: 768px)` | `body { background: #eef3fb; }` |
| **仅横屏** | `@media (orientation: landscape)` | `body { background: #dbe9fb; }` |
| **少些动效** | `@media (prefers-reduced-motion: reduce)` | `* { animation: none !important; }` |

### 更多配方

| 你想要 | 查询 | 里面的规则 |
|---|---|---|
| **深色模式** | `@media (prefers-color-scheme: dark)` | `body { background: #10151c; }` |
| **打印** | `@media print` | `.nav, .ads { display: none; }` |
| **触屏** | `@media (hover: none)` | `.tooltip { display: none; }` |
| **高分屏** | `@media (min-resolution: 2dppx)` | `.logo { background-image: url(logo@2x.png); }` |
| **矮屏** | `@media (max-height: 500px)` | `.hero { padding: 8px; }` |
| **更高对比** | `@media (prefers-contrast: more)` | `a { border-bottom: 2px solid; }` |

> [!important] 媒体特性不只问宽度
> 课件这张表的副标题是 **"Ask the device and the reader's settings — not only the width."**（问设备和**读者的设置**，不只是问宽度。）
> - `prefers-reduced-motion: reduce` → 把运动去掉，**不是把意思去掉**，见 [[动效与可访问性]]
> - `prefers-color-scheme: dark` → 一整套色值要跟着换，用 [[CSS变量]] 最省事
> - `prefers-contrast: more` → 给链接加可见下划线，这是 [[对比度与可读性]] 的实务
> - `@media print` → 打印样式通常还要配合 [[颜色表示法]] 里提到的打印色 considerations
> - `hover: none` 判定触屏时别忘了用 `@media (hover: hover)` 给桌面补上 hover 效果

## 七、布局速查表

课件的 Layout Cheatsheet：

| 主题 | 干什么 | 一行记法 |
|---|---|---|
| `position` | 把一个盒子提出文档流 | `position: sticky; top: 0;` |
| `z-index` | 给**已定位**的盒子定叠放次序 | `z-index: 10;` |
| **Flexbox** | 排**一根轴** | `display: flex; gap: 16px;` |
| **Grid** | 排**行和列** | `display: grid; gap: 16px;` |
| 媒体查询 | 在断点处**适应** | `@media (min-width: 768px) { }` |

课件的收尾句：**"Normal flow, then leave it on purpose — and describe the layout you want."**（先有常规流，再**有意识地**离开它 —— 然后去描述你想要的布局。）
