# 层叠顺序与z-index · Stacking Order & z-index

> **一句话**：盒子叠在一起时**数字大的画在更靠近观者的地方**，但这条规则有两条硬性前提 —— **static 盒子完全无视 `z-index`**，而**数字只在一个层叠上下文（stacking context）内部才互相比较**。

课件原文见 [Lecture_05_CSS.pptx](<../../raw/Lecture_05_CSS.pptx>)。本篇覆盖其中「z-index & Stacking」一页。

## 一、为什么需要一条规则

> **Layers on layers** —— 叠着的盒子需要一条**「谁在前」**的规则。

不写任何 `z-index` 时，重叠是按**盒子类型**排定的（有定位的、浮动的、行内的在不同层）。但一旦你**自己**造出重叠，就得**自己**给个说法，否则「我以为图片在后面」这种问题会一直发生。

## 二、四条规则

| 规则 | 内容 |
|---|---|
| **数字大的在前** | 一个更大的 `z-index` 被**画得离观者更近** |
| **只对定位盒有效** | **`static` 盒子完全无视 `z-index`** |
| **一个上下文内才比** | 这个数字**只和同一个层叠上下文里的其他数字竞争** |
| **留出空档** | 用 **10 · 100 · 1000** 这种间隔，便于日后插进一层 |

`z-index` 本身也接受**负值**（见下面的技巧）。

## 三、把东西压到后面去的技巧

```css
/* 图在文字后面 */
img {
  position: absolute;
  left: 0px;
  top: 0px;
  z-index: -1;      /* 负数 = 压到最底层 */
}
```

> [!important] 一个 `z-index: -1` 就够了
> 背景图 / 装饰图压在文字下面的标准做法，就是**负数 + 定位**。注意两条前提缺一不可：必须**已经定位**（`position` 不是 `static`），因为 static 盒子的 `z-index` 不起作用。
>
> 代价是：负数会把它压到**所在层叠上下文的背景**之下。如果它意外地沉到了整个页面背景的后面而看不见，多半是它落在了某个意料之外的上下文里 —— 这时候应该给预期的父级加上 `isolation: isolate` 把它圈住（见 [[背景与混合模式]]）。

## 四、留空档的实践

课件的建议是留 **10 · 100 · 1000** 的间隔：

| 层 | z-index | 用途 |
|---|---|---|
| 底 | （不设或负） | 背景装饰、背景图 |
| 基础内容层 | `10` | 正常内容、卡片 |
| 浮层 | `100` | 下拉菜单、tooltip |
| 模态遮罩 | `1000` | 对话框、侧边抽屉 |

这样中间随时能插一层 `500`，而**不需要重排所有已有的数字**。如果一开始就用 `1 2 3`，中间要塞东西就得全部重编号。

## 五、和「更便宜的重叠」手段对比

不一定非要 `z-index` + 定位。渲染上的重叠还有别的做法：

| 手段 | 是否引起重排 | 适合 |
|---|---|---|
| `z-index` + 定位 | 会（定位本身是重排） | 真正的层级控制（模态、浮层） |
| `transform: translateZ()` | **不引起重排** | 只是要「看起来在上面」 |
| `opacity` / 半透明层 | 不涉及层序 | 要的是**透**而不是**盖**（见 [[透明度与叠加层]]） |

`position` 与 `transform` 共享的家族特征是**不必为视觉结果付出重排的代价** —— 这也是 `z-index` 用多了会让人觉得「页面变卡」的直觉来源（定位真的会引起重排）。
