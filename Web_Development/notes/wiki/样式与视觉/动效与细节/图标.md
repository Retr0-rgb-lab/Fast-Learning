# 图标 · Icons

> **一句话**：图标只有三条路 —— **图标字体、内联 SVG、图片文件**；前两条是**画出来的**，能任意缩放、跟着文字颜色走，只有图片是**采样出来的**，所以图标要**少用**。

课件原文见 [Lecture_05_CSS.pptx](<../../../raw/Lecture_05_CSS.pptx>)。本篇覆盖其中「Miscellaneous」一节的图标部分：Icons 一页与 Icon Fonts 一页。

## 一、三条路

```html
<!-- 1 · 图标字体：一个 <link>，然后一个 class -->
<i class="fa-solid fa-star"></i>

<!-- 2 · 内联 SVG：形状就在页面里 -->
<svg viewBox="0 0 24 24">
<path d="M12 1.2 L14.82 8.6 L22.73 8.99
L16.57 13.96 L18.63 21.61 L12 17.28
L5.37 21.61 L7.43 13.96 L1.27 8.99
L9.18 8.6 Z" />
</svg>

<!-- 3 · 图片：一个尺寸一个文件、一个颜色一个文件 -->
<img src="icon-star.png" width="24" alt="">
```

| 路线 | 图标本体是什么 | 怎么写 |
|---|---|---|
| **图标字体** | 一个**字形就是一张图**的字体文件 | 引样式表 + 一个 class |
| **内联 SVG** | 一段**在页面里的标记** | `<svg>` + `<path>` |
| **图片文件** | 一张位图 | `<img src="…">` |

## 二、决定性的一条差别

课件把三条路摆在一起，为的是突出这一件事：

> **Font and SVG scale** — 两者都是**画出来的**（drawn）：任意尺寸都行，而且**跟着文字颜色走**。
> **A picture cannot** — 图片是**采样出来的**（sampled）：像素是固定的，**一个尺寸一个文件、一个颜色再来一个文件**。

| | 图标字体 | 内联 SVG | 图片文件 |
|---|---|---|---|
| 怎么来的 | **画**（字形） | **画**（路径） | **采样**（像素） |
| 任意缩放 | ✅ | ✅ | ❌ 一个尺寸一个文件 |
| 跟着 `color` 走 | ✅ | ✅ | ❌ 一个颜色一个文件 |
| 换了颜色要改 | 只改 `color` | 只改 `color` | 换文件 |
| 换了尺寸要改 | 只改 `font-size` | 只改 `width` | 换文件 |
| 加载成本 | 整个字体文件 | 无额外请求 | 每个图标一次请求 |

一行 CSS 就说明了前两条路为什么好用：

```css
.icon { color: #B93A33; }   /* 同一个图标，三种颜色只改这一行 */
```

> [!important] 所以要**少用**图标
> 课件的结论是 *「So use few — a logo, a favicon, one glyph; not a toolbar of twenty.」* 一个 logo、一个 favicon、一个字形 —— **不是二十个图标的工具条**。
>
> 理由不只是「好看」：二十个图标就是二十个文件要请求、二十份要维护、两三种尺寸两三种颜色就是上百个文件。图标越多，这些成本越不成比例。

## 三、图标字体

> 一句话定义：**一个网页字体，它的字形是图片 —— 所以图标本身就是文字。**

```html
<!-- 一张样式表带来整套图标 -->
<link rel="stylesheet" href="…/font-awesome.min.css">

<!-- class 名就是图标 -->
<i class="fa-solid fa-cloud"></i>
<i class="fa-solid fa-heart"></i>
<i class="fa-solid fa-bars"></i>
```

| 步骤 | 做什么 |
|---|---|
| 加载 | 引那张样式表 |
| 标记 | 在 `<i>` 或 `<span>` 上写 class |

> [!important] 它是文本，所以文本 CSS 全都能用
> 课件原话：*「It is text — so `font-size` and `color` work on it; the glyph paints itself.」* 这正是它最大的好处：`font-size: 1.5em;` 和 `color: #B93A33;` 两行普通文字样式，就把图标调大了、调成红色了。文字相关的样式怎么写，见 [[文本与字体]]。

> [!warning] 代价有两个
> 1. **整个字体文件都要下载** —— 哪怕你只用了一个星形，浏览器也要拿到整份字库。**要做子集化（subset）**，只留下真正用到的那几个字形。
> 2. **要把它对辅助技术藏起来** —— 一个图标字体在读屏软件那里可能念成一串无意义的字母。装饰性图标应当对辅助技术**保持沉默**（见下面第三节的 `aria-hidden`）。

## 四、内联 SVG

```html
<svg viewBox="0 0 24 24" width="24" height="24" aria-hidden="true" focusable="false">
<path d="M12 1.2 L14.82 8.6 L22.73 8.99
L16.57 13.96 L18.63 21.61 L12 17.28
L5.37 21.61 L7.43 13.96 L1.27 8.99
L9.18 8.6 Z" />
</svg>
```

- **形状就住在页面里**，不是采样来的点阵，而是**用坐标描述出来的**。
- `viewBox="0 0 24 24"` 是它自己的坐标系；`width` / `height` 决定它画多大。
- 改颜色改 `fill` 或 `currentColor` —— 跟着文字走。

> [!tip] 这就是 Week 2 的那套东西
> `viewBox`、`<path>` 的 `d` 命令，一条都和 [[SVG矢量图形]] 里讲的完全一样。**内联 SVG 图标 = 一段很小的 SVG。** 选它的理由不只是「图标」，而是「这条路的工具你已经学过了」。

## 五、图片：那个例外

```html
<img src="icon-star.png" width="24" alt="">
```

| 点 | 说明 |
|---|---|
| 像素固定 | 放大就糊 |
| 一个尺寸一个文件 | `icon-star-16.png`、`icon-star-24.png`、`icon-star-32.png`… |
| 一个颜色一个文件 | 深色主题要再来一套 |
| **`alt=""`** | **装饰性图标应该是沉默的** |

> [!important] `alt=""` 是刻意的，不是漏写
> 空的 `alt` 表示**「这个图不携带信息」** —— 读屏软件会跳过它，不念出来。写了描述反而会多出一段和旁边文字重复的朗读。
>
> 判断标准很简单：**去掉这个图标，意思少了吗？** 少 → 它是装饰，`alt=""`。不少（它是那个唯一的信息）→ 才需要描述。`<img>` 的各种情形见 [[链接与图像]]。

### 背景图连 `alt` 都没有

```css
.icon { background-image: url(icon-star.png); }
```

用 CSS `background-image` 放的图标**连 `alt` 的机会都没有** —— 它根本不是一个元素，读屏软件没有地方读它。这不是缺陷，是选这条路时就接受的代价：这条路上的图标只能是装饰性的。

> [!warning] 别把可访问性押在图片图标上
> 课件点名的做法是**少用**图标；而真正承载信息的地方（状态、提示、说明），**不要只靠图标或颜色**。这条规矩和对比度那一篇是同一件事，见 [[对比度与可读性]]。
