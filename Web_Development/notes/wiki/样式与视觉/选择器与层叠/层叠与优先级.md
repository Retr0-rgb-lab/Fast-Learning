# 层叠与优先级 · The Cascade

> **一句话**：一个元素同时被很多条规则命中时，浏览器**只画一个值**——先比**权重**（ID > class > 标签），权重完全相同才比**谁写在后面**，而 `!important` 直接越过全部常规规则。

课件原文见 [Lecture_04_CSS.pptx](<../../../raw/Lecture_04_CSS.pptx>)。本篇覆盖 Week 4 "The Cascade" 一节：层叠是什么、**来源顺序表**、Rule 1 外链→内嵌→行内、Rule 2 标签→class→ID 与 `(0,0,1)` / `(0,1,0)` / `(1,0,0)` 计分、以及 `!important`。

## 一、层叠是什么

| 事实            | 含义                                   |
| ------------- | ------------------------------------ |
| **一个元素，多条规则** | 同一个 `<p>` 常常同时被标签规则、class 规则、id 规则命中 |
| **但只能有一个赢**   | 浏览器只画一种颜色，**它必须挑出唯一一条声明**            |
| **每条规则都带权重**  | 层叠把它们的权重加起来，**最重的赢**                 |
| **平手时看顺序**    | 只有两条规则**权重相同**，**后写的**才赢             |

```css
p     { color: black; }     /* 标签规则 */
.note { color: #185fa5; }    /* class 规则 */
```

同一个元素上，这两条都能命中 `<p class="note">`。谁赢？`.note`——它权重更大。这一步的完整机制在 [[简单选择器]] 里已经出现过一次，这里是把它系统化。

> [!note] 课件里的 `#185fa5`、`#2e7d32`、`#d9534f`
> 这几个十六进制值是 Week 4 讲"规则互相竞争"时随手配的**演示对比色**，**不属于课程调色板**（见 [[颜色表示法]]）。本篇保留它们是因为它们正是课件里用来说明层叠的那几行。

## 二、来源顺序（Order of Preference）

**样式从哪儿来**，以及**实际怎么赢**：

| 来源 | 实际情形 | 权重 |
|---|---|---|
| Browser default | 根本没有 CSS——`<h1>` 也照样又大又粗 | weakest |
| User stylesheet | 读者自己装的，比如把默认字号调大 | ↓ |
| Our external file | `style.css`，用 `<link>` 拉进来 | ↓ |
| Our `<style>` block | 嵌在页面 `<head>` 里的 | ↓ |
| Our `style="…"` | 行内，就写在元素自己身上 | strongest |

课件的总结：**列表越往下越赢，浏览器自己的样式是其中最弱的。**

这一列正是 [[CSS引入方式]] 那张表的排序：外链、内嵌、行内。**"三种引入方式的强弱顺序"和"层叠的第一条规则"是同一件事的两种说法。**

## 三、Rule 1：外链 → 内嵌 → 行内

```css
/* style.css — linked from the head */
h1 { color: #2e7d32; }
```
```html
<!-- <style> — later in the head -->
<style>
h1 { color: #185fa5; }
</style>
<h1 style="color: #d9534f;">Hello</h1>
<!-- renders red: the inline style wins -->
```

三条规则给**同一个 `color` 属性**同一个 `<h1>`，结果是**红**。课件的解释只有一句：

> **Closer to the element, stronger**：越靠近元素越强——行内压过内嵌，两者都压过外链文件。

三条的选择器**完全相同**（都是 `h1`），所以权重这一项打平，胜负由**来源**决定：内嵌的 `<style>` 写在 `<link>` 之后，行内又贴在元素上。

## 四、Rule 2：标签 → class → ID

> 两个问题决定胜负：**每条规则有多重？两条一样重时谁写在后面？**

### 权重不同时——强者赢

```css
p      { color: black; }     /* (0,0,1) */
.note  { color: #185fa5; }    /* (0,1,0) */
#intro { color: #d9534f; }    /* (1,0,0) */
```
```html
<p class="note" id="intro">Hello</p>
<!-- renders red -->
```

**红色——id 规则赢。**

### 怎么读这个三位数

课件的说法是**数部件**：*Count the pieces: 1 ID (100) beats 1 class (10) beats 1 tag (1).*——数出各有多少个部件，一个 id 值 100，一个 class 值 10，一个标签值 1。

| 选择器 | 括号里那三位数 | 拆开看 |
|---|---|---|
| `p` | `(0,0,1)` | 没有 id、没有 class、**1 个标签** |
| `.note` | `(0,1,0)` | 没有 id、**1 个 class**、没有标签 |
| `#intro` | `(1,0,0)` | **1 个 id**、没有 class、没有标签 |

按 (id, class, 标签) 三个位置摆好，**先比左边**：

| 对比 | 结果 |
|---|---|
| `(1,0,0)` vs `(0,1,0)` vs `(0,0,1)` | id 赢（左边第一个位就大） |
| `(0,1,0)` vs `(0,0,1)` | class 赢（第一位都是 0，比第二位） |
| `(0,2,0)` vs `(0,1,0)` | 两个 class 赢（第一位、第二位都更大） |
| `(0,1,1)` vs `(0,1,0)` | 第一个赢（class 相同，比标签数） |

数值上 `100 > 10 > 1`，所以**10 个 class 也压不过 1 个 id**。这就是"用 id 上样式很难被覆盖"的算术根据。

### 权重相同时——后面的赢

```css
p { color: black; }     /* written first */
p { color: #185fa5; }   /* written last  */
```
```html
<p>Hello</p>
<!-- renders blue -->
```

**蓝色——后写的规则赢。** 课件的解释：*Tied? The browser reads top to bottom*，浏览器从上往下读，**最后一条赢**。

课件最后那句话是本节的收口：

> **Weight first — source order only decides when two rules weigh exactly the same.**
> 权重优先——来源顺序只在两条规则**权重完全相同**时才起作用。

> [!warning] 用 `#id` 上样式是最常见的层叠错误
> id 权重 `(1,0,0)` 高到几乎无法被覆盖（除 `!important`）。用 id 做样式，等于提前把后面所有调整的路堵死。课件在 class vs id 对照里给的那句 **"Too specific — styling by id makes overrides painful"** 说的就是这件事。

## 五、`!important`：最后手段

| 性质 | 内容 |
|---|---|
| **The nuclear option** | 一条声明**越过所有常规规则**，不管它多重 |
| **它仍然要竞争** | 两条 `!important` 之间，照样**比权重、比顺序**，规则不变 |
| **它会升级** | 一旦有规则被强制，**越过它的唯一办法是更强制** |
| **最后手段** | 通常意味着**选择器写错了——该改选择器，而不是加感叹号** |

```css
p { color: red !important; }
```

课件还留了一个演示提示：层叠那个例子里这条规则**默认是注释掉的**——把它取消注释，上面每一条规则都输给它。

> [!tip] 正确顺序：先怀疑选择器
> 规则不管用时，依次问三个问题：
> 1. **它真的命中了这个元素吗？**（选择器写对了吗——类型、class、id 对得上吗）
> 2. **有别的规则比它重吗？**（算一遍 (id, class, 标签)）
> 3. **还有同权重的规则写在它后面吗？**（挪位置）
>
> 三问都排除了，才轮到 `!important`——而那时通常意味着：**正确答案不在"更用力"，而在"更精确"**（见 [[规则结构与选择器分类]] 里 precision 那条）。

## 六、四步判定的完整顺序

把三条笔记的规则串起来，浏览器对每条声明的处理顺序是：

1. **继承**——父元素给了值吗？（见 [[继承]]，这是"值从哪来"的第一个环节）
2. **来源**——`!important` 压过所有常规规则；常规规则之间按 **外链 → 内嵌 → 行内** 比强弱（Rule 1）
3. **权重**——同来源比 (id, class, 标签)（Rule 2）
4. **顺序**——权重也相同，**后写的赢**

## 七、写在示例站上

示例站（约定见 [[课程场景与阅读约定]]）的 `main` 里，段落都带 `class="note"`。于是：

```css
/* 权重 (0,0,1) */
p { color: #0E3F8C; }         /* Navy */

/* 权重 (0,1,1) —— 赢 color 那一场 */
p.note { color: #1E4FA8; }    /* Primary */

/* 权重 (0,2,0) —— 比上面更重：两个 class 对一个 class + 一个标签 */
.note.large { font-size: 20px; }
```

> [!warning] 这三行里没有一处是靠「写得靠后」赢的
> `p.note` 是 `(0,1,1)`、`.note.large` 是 `(0,2,0)`——**两者权重并不相同**，`.note.large` 赢在权重更重，与在文件里的位置无关。
> 真正「同权重比顺序」的例子在本文第四节：两条一模一样的 `p { color: … }`。
> 另外注意 `p.note` 的权重是 **(0,1,1)** 而不是 (0,1,0)：**标签也要计分**，别把带标签的 class 选择器少算一位。

若想让某一段**例外地**用 Alert：

```css
/* 不要这样写 */
#urgent { color: #D9534F; }   /* (1,0,0)，几乎无法被覆盖 */

/* 这样写：一个专门的 hook，同一量级、可控 */
.alert { color: #D9534F; }
```

## 八、易错点

- 以为来源顺序比权重优先——**权重优先**，来源顺序只在常规规则之间且同权重时起作用。
- 把 `!important` 当修选择器的手段。
- 靠"改文件里的位置"来解决问题，结果下一个人调整顺序后全乱。
- 用 id 上样式，然后抱怨"什么都覆盖不掉"。
