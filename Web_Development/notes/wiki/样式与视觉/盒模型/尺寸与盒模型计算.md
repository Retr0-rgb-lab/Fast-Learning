# 尺寸与盒模型计算 · Sizing & Box Model Math

> **一句话**：`width` / `height` 默认可不算内边距和边框，**全由 `box-sizing` 决定** —— 在 `*` 上设一次 `border-box`，你就再也不用手算总宽了。

课件原文见 [Lecture_04_CSS.pptx](<../../../raw/Lecture_04_CSS.pptx>)。本篇覆盖其中「Width & Height」「box-sizing — What a Size Means」两页，以及 Key Takeaways 里 box-sizing 那一条。

## 一、width / height 到底算哪一段

| 写法 | 含义 |
|---|---|
| 声明一个长度或百分比 | **默认只管 content 区域**，除非 `box-sizing` 另有规定 |
| `auto`（两者的默认值） | 盒子**长到内容那么大** |
| 百分比 | 是**包含块（containing block）的一份**，所以盒子随父级一起缩放 |
| `max-width` | 给它一个上限：盒子在窄屏上**收缩**，而不是硬撑出滚动条 |

```css
div {
  height: 200px;
  width: 50%;
  background-color: powderblue;
}
div.ex2 {
  max-width: 500px;      /* 同一个盒子，多一个 500px 的天花板 */
  margin: auto;
  border: 3px solid #73AD21;
}
```

课件在这两页之间做了一次对照：`ex1` 是**固定 500px**（窄屏上溢出、出现滚动条），`ex2` 是**同样的盒子但有 500px 的上限**（窄屏上收缩，桌面居中）。

> [!important] `max-width` 赢过 `width`
> 两者冲突时 **`max-width` 生效**。这正是「让布局不溢出」的那道保险。

## 二、`box-sizing`：你声明的尺寸**含什么**

同一个 `240px`，两种答案：

| | `content-box`（默认） | `border-box` |
|---|---|---|
| 尺寸指的是 | **只有 content 区** | **整个盒子**（content + padding + border） |
| padding 与 border | **额外加在外面** | 全部**含在里面** |
| 声明 240px、padding 20px、border 6px | 240 + 40 + 12 = **292px** | **240px**，你加什么都不变 |
| 代价 | **每次都要先做减法**才能算准一个尺寸 | 不用算 |

课件的对照数字（`width 240px · padding 20px · border 6px · margin 24px`）：

| | 盒子本身 | 加上 48px 的 margin 之后在页面上 |
|---|---|---|
| `content-box` | 240 + 40 + 12 = **292px** | **340px** |
| `border-box` | **240px** | **288px** |

## 三、总宽 / 总高的公式

无论 `box-sizing` 怎么设，**元素真正在页面上占的地方**是这个：

```
总宽 = width  + 左/右 padding + 左/右 border + 左/右 margin
总高 = height + 上/下 padding + 上/下 border + 上/下 margin
```

注意 margin **永远在外面**，两种 `box-sizing` 都不改变这一点 —— 它是盒子与邻居之间的距离，不是盒子自己的尺寸。

### 算一遍课件的 292px

`width: 240px; padding: 20px; border: 6px solid; margin: 24px`

| 步骤 | `content-box` | `border-box` |
|---|---|---|
| 声明的 width | 240 | 240 |
| 左右 padding | + 20 + 20 = +40 | （已在 240 之内） |
| 左右 border | + 6 + 6 = +12 | （已在 240 之内） |
| **盒子总宽** | **292px** | **240px** |
| 左右 margin | + 24 + 24 = +48 | + 48 |
| **页面上占的总宽** | **340px** | **288px** |

## 四、一次设定，全局生效

```css
* { box-sizing: border-box; }
```

课件 Best Practices 页的措辞是 **"Set it once on `*` — predictable sizes"**（设一次，尺寸就可预测了），`box-sizing` 那页也说 **"most projects start here"**（多数项目从这里开始）。

设完之后：

- 写 `width: 300px`，拿到的就**真的是 300px**，不用心算 `240 - 40 - 12`。
- 和 `padding` 搭配时不再需要**减法**，直接把 padding 往里压。
- **`flex` 与 `grid` 里算得对** —— 见下面那条重要提示。

> [!important] 这是 Flexbox 和 Grid 能算得对的前提
> 现代布局里大量使用 `width: 100%` 再配 `padding`。`content-box` 下 `100% + padding` 必然溢出（外宽比容器还宽），`border-box` 下才刚好装得下。课件把这称为 **"This is the fix for the arithmetic the box model used to force on everyone"**（这就是对盒模型强加给每个人的那笔算术的修正）。所以 Flexbox / Grid 教程里默认 `border-box`，不是巧合。

`box-sizing` 可以逐个元素设，也可以只给某几个设 —— 但既然它是个**纠错**性质的决定，课件的建议就是全局统一，别一半一半。

## 五、易错点与调试

课件 Common Mistakes 把 **Forgetting border-box** 列为第一条常见错误：**"Widths add up unexpectedly and the layout breaks."**（宽度意外地加起来，布局就崩了）。

DevTools 里的排查顺序（课件给的排查线索）：

```
border-box  →  margin  →  specificity  →  !important
```

即：先确认尺寸算法对不对，再看外边距，再回去查规则竞争。
