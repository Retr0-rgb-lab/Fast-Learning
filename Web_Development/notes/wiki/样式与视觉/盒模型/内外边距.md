# 内外边距 · Padding & Margin

> **一句话**：padding 在边的**内侧**、**会被绘制**、点击也算命中元素、**永不折叠**；margin 在边的**外侧**、**永不绘制**、点击不命中，而**垂直方向的相邻 margin 会合并成较大的那个**。

课件原文见 [Lecture_04_CSS.pptx](<../../../raw/Lecture_04_CSS.pptx>)。本篇覆盖其中「Padding」「Margin」「Margin Collapsing」三页。

## 一、padding：在边的内侧

| 特性 | 说明 |
|---|---|
| 位置 | border **以内**，在 content 周围清出一圈空间 |
| 会被绘制吗 | **会** —— 背景色会画满 padding，这是它与 margin 最大的区别 |
| 点击命中吗 | **会** —— 点在 padding 上仍然算点中了元素 |
| 四个具名属性 | `padding-top`、`padding-right`、`padding-bottom`、`padding-left`，一条一个 |
| 会折叠吗 | **永远不会** —— 两块 padding 相遇就**直接相加** |

```css
div {
  border: 1px solid black;
  background-color: lightblue;
  padding-top: 50px;
  padding-right: 30px;
  padding-bottom: 50px;
  padding-left: 80px;
}
```

1–4 值的写法当然同样成立：

```css
div { padding: 50px 30px 50px 80px; }   /* 上 右 下 左 */
```

## 二、margin：在边的外侧

| 特性 | 说明 |
|---|---|
| 位置 | border **以外**，在元素周围清出一圈空间 |
| 会被绘制吗 | **绝不会** —— 那里的东西永远透明 |
| 1–4 顺序 | 与 padding **完全一样**：上、右、下、左 |

```css
p { margin: 100px 150px 100px 80px; }
```

> [!important] 一句话自检
> **如果你能看见背景，那你看到的一定是 padding。** margin 里没有颜色，只有下一个元素的背景（或者页面的背景）。

### `auto`：用 margin 居中一个块

```css
div {
  width: 300px;
  margin: auto;          /* 在父容器里水平居中 */
  border: 1px solid red;
}
```

原理：**已声明的宽度 + `margin: auto`** = 剩下那段空间被**均分**到左右两边，于是居中。

> [!tip] 为什么必须先有 `width`
> `auto` 分的是「剩下的空间」。如果宽度也是 `auto`，就**没有剩下的空间可分**，居中不成立。所以 `width` 与 `margin: auto` 是一对。

### `margin-left: inherit`：左外边距可以继承

margin 是**盒属性、不随文本继承**（见 [[继承]]）—— 但**具体某一条可以显式要求继承**：

```css
div.container { border: 1px solid red; margin-left: 100px; }
p.one        { margin-left: inherit; }   /* 拿到父级的 100px */
```

这是那条「盒属性留在原地」规则里少见的、**可以主动打破**的例子。

## 三、margin collapsing（外边距合并）

这是本篇最容易考、也最容易在调试时困惑的机制。核心只有一句：

> **横向的 margin 相加；纵向的 margin 合并。**

### 并排：相加

`margin-right: 50px` 遇到 `margin-left: 20px` → **加起来 = 70px 的间隔**。

```
 [box 1] ──── 50px ──── [20px] ──── [box 2]
          50px + 20px = 70px 的间隔
```

### 上下堆叠：合并，取大的

`margin-bottom: 50px` 遇到 `margin-top: 20px` → **不是 70px，而是 50px**。

```
 [box 1]
      ↓ 50px ↓   ┄┄┄ 两个 margin 重叠了 ┄┄┄
   [box 2]  ↑ 20px ↑
  间隔 = 50px，不是 70px —— 较大的那个赢
```

课件把差别画得很清楚：并排那两个标着 `50px` 和 `20px` 相邻；堆叠那两个标着 **"one margin"** 与 **"two, overlapping"**。

```css
h1 { margin: 0 0 50px 0; }
h2 { margin: 20px 0 0 0; }
/* h1 的 50px 遇到 h2 的 20px → 实际间隔 50px */
```

> [!warning] 最常见的实测场景：堆叠的标题
> 「两个标题之间为什么不是我以为的 50 + 20？」—— 因为纵向 margin **合并**，大的那个（50px）赢了。课件在 Common Mistakes 里也把 Margin collapsing 列为高频错误：*Vertical margins between siblings merge — don't double them*（别把两边的 margin 都调大来「补」那 10px）。

### 谁会折叠，谁不会

| 情形 | 会不会折叠 | 原因 |
|---|---|---|
| 两个**纵向相邻兄弟**的 margin | **会** | 合并，取大 |
| 两个**横向相邻兄弟**的 margin | 不会 | 横向本来就是**相加** |
| **父元素与它的第一个子元素** | **会** —— 前提是**中间没有 border、没有 padding** | 没有东西隔开，子的 margin 就「逃」出父级 |
| 两个 **padding** | 不会 | padding 永不折叠 |
| **浮动**的盒子 | **不会** | 浮动盒自己保住自己的空间 |
| **脱离文档流**（absolute 等）的盒子 | **不会** | 同上 |

「逃出父级」这一条要单独说清：父与第一个子之间一旦有一丁点 `border` 或 `padding`，那条隔断就存在了，折叠不再发生。
