# 规则结构与选择器分类 · Rule-sets & the Five Categories

> **一句话**：无论选择器有多复杂，每条规则（rule-set）的形状永远是 `selector { property: value; }` 一个样——**只有花括号左边那一串在变**，五类选择器只是五种"怎么找到元素"的找法。

课件原文见 [Lecture_04_CSS.pptx](<../../raw/Lecture_04_CSS.pptx>)。本篇覆盖 Week 4 "Selectors" 一节：规则集的解剖、第一个样式表、**五类选择器总表**、选择器速查表，以及注释和空白。

## 一、什么是规则集

> **CSS 选择器（selector）用来"找到"你想上样式的 HTML 元素。**
> 一条规则集（rule-set）= **一个选择器 + 一个声明块**。

```
selector { property: value; }
```

规则集里的东西，正好是 Week 3 那句 `property: value;` 加了一层外壳——见 [[样式声明与内联]]。

## 二、解剖一条规则

```css
h1 { color: blue; }
```

| 部件 | 例子 | 是什么 |
|---|---|---|
| Selector | `h1` | 你想上样式的那个 HTML 元素 |
| Declaration block | `{ … }` | 一条或多条声明，夹在**花括号**里 |
| Property | `color` | 要改的名字 |
| Value | `blue` | 设成的值 |

课件提醒的两条硬规则：**每条声明都以分号结束，整个声明块放在 `{ 花括号 }` 里。**

课件另一句同样重要：**"花括号之前的一切，就是选择器。"** 找元素这件事，全部发生在左边。

## 三、第一个样式表

```html
<!-- index.html -->
<link rel="stylesheet" href="style.css">
```
```css
/* style.css */
h1 { color: #1E4FA8; }
p  { font-size: 18px; }
body { font-family: sans-serif; }
```

拆开看这三行各自在干什么：`<link>` 把样式表拉进页面；**selector** 决定这条规则管谁（这里是 `h1` 和 `p`）；**property + value** 决定改什么、设成什么；**cascades**——规则会叠加，一页里可以有很多条规则。

课件的结论：**浏览器同时读两个文件——HTML 负责结构，CSS 负责样式。**

## 四、五类选择器总表

| 类别 | 按什么选 | 例子 |
|---|---|---|
| **Simple**（简单） | 按名字、id、class——或选全部 | `p` · `#para1` · `.center` · `*` |
| **Combinator**（组合） | 按元素之间的**关系** | `div p` · `div > p` · `h1 + p` · `h1 ~ p` |
| **Attribute**（属性） | 按某个属性，或属性的值的一部分 | `a[target]` · `a[href$=".pdf"]` |
| **Pseudo-class** `:` | 按某种**状态** | `a:hover` · `input:checked` |
| **Pseudo-element** `::` | 按元素的**一部分** | `p::first-line` · `h2::after` |

课件对这张表下的判断值得背下来：

> **五类选择器共用同一条规则集的形状——只有左边的选择器在变。**

这是本节真正的收束。`div > p` 和 `p::first-line` 在语法难度上差得很远，但它们产生的都是同一个东西：一条 `selector { … }`。所以 Week 3 那句 `property: value;` 学会了，CSS 的**全部**语法就学会了；剩下的全是"左边那串怎么写"。

课件还给了一条关于选择器好坏的判断：

> **Precision（精确度）——选得越精确，要写的 CSS 越少。**

## 五、选择器速查表

| 选择器 | 匹配什么 | 例子 |
|---|---|---|
| `element` · `class` · `id` | 按标签、class 或 id——或匹配全部 | `p` · `.note` · `#header` · `*` |
| `A, B` | 分组——一条规则，多个选择器 | `h1, h2, p { }` |
| `A B` · `A > B` | 后代 · 直接子代 | `ul li` · `ul > li` |
| `A + B` · `A ~ B` | 下一个兄弟 · 之后所有兄弟 | `h1 + p` · `h1 ~ p` |
| `[attr]` · `[attr^="v"]` | 按属性，或按值的**一部分** | `a[href$=".pdf"] { }` |
| `:hover` · `:nth-child(2)` | 按状态，或按在兄弟中的**位置** | `a:hover` · `li:nth-child(2)` |
| `::before` · `::first-line` | 元素的一个**部分** | `p::before` · `p::first-line` |

课件的用法建议：**这五类在这一页上，把这张表留着备查。** 后面四篇就是把其中五类各展开一页——[[简单选择器]]、[[组合选择器]]、[[属性选择器]]、[[伪类与伪元素]]，最后是它们如何互相竞争（[[层叠与优先级]]）。

## 六、注释与空白

| 要点 | 内容 |
|---|---|
| Comments | `/* … */`——**浏览器完全忽略**的笔记 |
| 解释 why | 代码本身已经说了 what |
| 空白是免费的 | 空格和换行**不改变结果** |
| 可读 = 可维护 | 约定是**一条声明一行** |

```css
/* site-wide colours */
:root {
  --blue: #1E4FA8;
  --navy: #0E3F8C;
}
h1 {  /* one per line */
  color: var(--blue);
}
```

课件的判据是：**注释解释的是 why，不是 what——代码已经说了 what。** 上面那条 `/* site-wide colours */` 合格，它说的是"这组变量是全站配色"；如果写 `/* set the colour */` 就没有信息量。`/* one per line */` 同理，它记录的是一条**约定**而不是这一行的含义。

因为空白不影响结果，排版可以完全按可读性来：

```css
h1,
h2,
p {
  text-align: center;
  color: #1E4FA8;
}
```

上面这段和 `h1 { text-align: center; color: #1E4FA8; } h2 { … } p { … }` 结果完全相同。变量语法见 [[CSS变量]]。

## 七、易错点

- 忘记花括号末行的分号，或者忘写分号——后面那条声明会整条失效。
- 把注释写在"这行设置了颜色"的位置上，白写。
- 认为把选择器拆成多行会改变规则——只有 `{` 之后那部分对空白敏感。
- 在注释里写"见课件第 X 页"式的指引：笔记要自足，注释要解释 why。
