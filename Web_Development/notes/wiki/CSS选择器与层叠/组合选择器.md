# 组合选择器 · Combinator Selectors

> **一句话**：组合选择器靠**元素之间的关系**找目标——`A, B` 是"**而且还有**"，`A B` 是"**在里面**"，**这一对差别是本篇最该记牢的**；其余三种只是把"里面"收紧成"直接子级"或"相邻兄弟"。

课件原文见 [Lecture_04_CSS.pptx](<../../raw/Lecture_04_CSS.pptx>)。本篇覆盖 Week 4 "Selectors" 一节的四种组合器：分组、后代、子代、相邻兄弟、通用兄弟。

## 一、分组（Grouping）`A, B`

**用逗号隔开每个选择器**，一个声明块给列表里所有人：

```css
h1 { text-align: center; color: #1E4FA8; }
h2 { text-align: center; color: #1E4FA8; }
p  { text-align: center; color: #1E4FA8; }

h1, h2, p { text-align: center; color: #1E4FA8; }
```

- **One block for all**：列表里每个选择器都拿到同一批声明。
- **Less code**：课件的判断很直接——*it is better to group the selectors, to minimise the code*（把选择器分组、让代码更少，总是更好的）。

> [!warning] 逗号不是空格
> **逗号 = "and also"（而且还有），空格 = "inside"（在里面）。**
>
> 下面这行会被理解成"`h2` 里面的 `p`，在 `h1` 里面"：
>
> ```css
> /* a space would mean: p inside h2 inside h1 */
> h1 h2 p { text-align: center; }
> ```
>
> `h1, h2, p` 是"这三类都居中"，`h1 h2 p` 是"三层嵌套里的那段 `p` 居中"——**一个逗号的差别，完全是两件事**。

## 二、后代选择器（Descendant）`A B`

> 选中 A 的**后代**里的 B——**任意深度**。

```html
<div class="abc">
  <div>
    <p>Hello there!</p>
  </div>
</div>
```
```css
.abc p { font-weight: bold; }
```

| 特点 | 说明 |
|---|---|
| 写法 | **一个空格**：`div p` |
| 范围 | 孩子、孙子……**整棵子树** |
| 读法 | **从右往左读**——最后一段才是被上样式的那个元素 |
| 课件的措辞 | 不只是 children，是 descendants；空格够到所有层 |

上面那段 HTML 里，`<p>` 外面包着**两层** `div`。`div p` 一样能选中它——后代不看深度，只看"是不是在里面"。

## 三、子代选择器（Child）`A > B`

> 选中 A 的**直接子元素** B。

```html
<div class="abc">
  <p>a direct child</p>
  <div><p>a grandchild</p></div>
</div>
```
```css
.abc > p { font-weight: bold; }  /* 1 match */
```

| 特点 | 说明 |
|---|---|
| 写法 | **`>`** |
| 范围 | **只有直接子级**——孙子不算 |
| 严格程度 | 比空格**更严格** |
| 用途 | **Stops leaks**：不让规则渗进嵌套的列表和卡片里 |

**这正是上面那个例子的重点**：`.abc` 下有两个 `p`，一个直接子级、一个孙子。`.abc p` 选中 2 个，`.abc > p` **只选中 1 个**（课件注释写着 `/* 1 match */`）。

**这就是"防渗漏"的实际意义**——课程表格里每个单元格里都可能有嵌套结构，用后代选择器会把最深处那个 `p` 也一起改掉。

## 四、相邻兄弟（Adjacent Sibling）`A + B`

> 选中**紧跟在 A 后面**的那个 B。

```html
<div>
  <div class="abc">Message</div>
  <p>Hello there!</p>
</div>
```
```css
.abc + p { font-weight: bold; }
```

| 特点 | 说明 |
|---|---|
| 写法 | **`+`** |
| 同一个父元素 | A 和 B **必须共享父元素** |
| 只有一个邻居 | 中间**插入任何东西**，就什么也不匹配 |
| 经典用途 | **`h2 + p`**——把标题下面那段正文的间距收紧 |

"紧跟"是硬条件：`.abc` 和 `p` 之间若插进别的元素，`+` 就断了。`h2 + p` 之所以经典，是因为"标题 + 说明段"几乎总是一前一后相邻出现的结构。

## 五、通用兄弟（General Sibling）`A ~ B`

> 选中 A **之后**的**每一个** B。

```html
<div>Title</div>
<p>first</p>
<p>second</p>
```
```css
div ~ p { background: #FDF3C8; }  /* both */
```

| 特点 | 说明 |
|---|---|
| 写法 | **`~`**（读作 a tilde，波浪号） |
| 范围 | **不只是下一个，是之后所有的兄弟**（课件注释 `/* both */`——两个都中） |
| 方向 | **只往前**——在 A **之前**的兄弟不会被匹配 |
| 读法 | `div ~ p` = "每一个在 `<div>` 之后的 `<p>`" |

上面两段 `<p>` 都在 `<div>` 之后，所以两条都吃到背景色。`+` 只会命中第一段。

## 六、四种 + 分组总表

| 写法 | 名字 | 含义 |
|---|---|---|
| `A, B` | 分组 | A **而且还有** B |
| `A B` | 后代 | B 在 A **里面**（任意深度） |
| `A > B` | 子代 | B 是 A 的**直接**子元素 |
| `A + B` | 相邻兄弟 | B **紧接在** A 之后 |
| `A ~ B` | 通用兄弟 | B 在 A 之后的**每一个**兄弟 |

## 七、写在示例站上

示例站（约定见 [[课程场景与阅读约定]]）的 `main` 里，课程表格下方是报名表单。典型的嵌套结构：

```html
<main>
  <h2>Course table</h2>
  <p>Weekly timetable and workload.</p>
  <div class="card">
    <p>Inside a card, nested one level deeper.</p>
  </div>
</main>
```

四种组合器在这段结构上的不同表现：

```css
/* 分组：三类都收紧一下 */
h2, main > p { margin-bottom: 4px; }

/* 后代：卡片里那段 p 也会中招 */
main p { font-size: 16px; }

/* 子代：只命中直接的那个 p，嵌套层不中 */
main > p { font-weight: bold; }

/* 相邻兄弟：紧跟 h2 之后的第一段 */
h2 + p { color: #4A5568; }

/* 通用兄弟：h2 之后的所有 p，包括卡片里那段 */
h2 ~ p { text-decoration: none; }
```

## 八、易错点

- 把 `,` 和空格搞混：前者是"而且"，后者是"里面"。
- 以为 `A B` 只管一层——它够到整棵子树。
- 在中间插了元素还指望 `+` 生效。
- 指望 `A ~ B` 能往回匹配——它**只向前**。
- 子元素混用中英文：本库 HTML 侧的容器用语义标签（`main`、`div`），钩子统一用英文 class，规则写在 [[容器与语义化]] 那一套里。
