# 表单验证与可访问性 · Form Validation & Accessibility

> **一句话**：一个合格的表单有两件事必须做对——**每个控件都用 `<label for>` 挂上标签**，**校验交给浏览器的原生属性**（required / min / max / minlength / pattern），一行 JavaScript 都不用写。

课件原文见 [Lecture_02_HTML.pptx](<../../raw/Lecture_02_HTML.pptx>)。本篇覆盖课件的 "Labels & Accessibility"、"Built-in Validation" 和 "A Complete Form" 三部分。

## 一、标签：`<label for>`

课件给的三条：

| 课件的说法 | 展开 |
|---|---|
| **`<label for="…">`** | 通过 **`id`** 把文字和它的控件**绑在一起** |
| **Click the label** | 点标签会**让输入框获得焦点**——**点击区更大** |
| **Screen readers** | 屏幕阅读器会**念出每个控件是干什么用的** |

```html
<label for="em">Email</label>
<input id="em" type="email">
<!-- clicking the label focuses the input -->
```

配对的机制就是属性那一篇说的"钩子"：**`for="em"` 和 `id="em"` 靠字符串匹配。** 一个 `id` 在一份文档里唯一，所以它正好够用来定位一个控件。

### 点标签能聚焦，这件事的实际价值

鼠标点输入框，只能点到框**里面**那个小矩形。点标签文字则整行文字都是热区——**a bigger click area**。对任何人都是省事的操作，对手抖、精细动作困难、或者用触控设备的人尤其明显。

> [!important] Placeholder ≠ label
> 课件用一条规则单独点出它：**Placeholder ≠ label — hints vanish; labels stay**（提示会消失，标签会留下）。
>
> 原因很直接：`placeholder` 写在输入框**里面**，用户一开始打字就被顶走了。**字段一填满，提示就永久消失了。** 而 `<label>` 在框外面，永远在那个位置。
>
> 更糟的情况是：只写 placeholder 的话，输入框**没有名字**——屏幕阅读器念出来是空白的，用户不知道这一栏要填什么。课件在表单输入那篇就提前写了 "placeholder — not a substitute for a label"。
>
> ```html
> <!-- 不好：提示会被顶掉，且没有可访问名称 -->
> <input type="email" placeholder="you@polyu.edu.hk">
>
> <!-- 正确：标签常驻，placeholder 只是补充提示 -->
> <label for="em">Email</label>
> <input id="em" type="email" placeholder="you@polyu.edu.hk">
> ```

## 二、内置校验

课件给的一整组，**全部是原生属性**：

| 属性 | 课件的说法 |
|---|---|
| `required` | 这个字段**必须填** |
| `min` / `max` / `minlength` | **范围**与**长度**检查 |
| `pattern` | 值必须匹配的**正则表达式**（regular expression） |
| `placeholder` | 期望值的灰色提示 |
| `autocomplete` | 从**之前的输入**里建议值 |
| **Browser enforces** | **基础检查不需要 JavaScript** |

```html
<input type="email" required>
<input type="number" min="0" max="100">
<input type="text" pattern="[A-Za-z]{3,}">
<!-- the browser blocks invalid submits -->
```

课件的结论句：**The browser blocks the submit until it is valid**（浏览器会**拦住提交**，直到它合法）。

### `pattern` 里的那个正则

`pattern="[A-Za-z]{3,}"` 拆开读：

| 片段 | 含义 |
|---|---|
| `[A-Za-z]` | 字符集合：**大小写字母**各一个 |
| `{3,}` | 前面的东西**至少重复 3 次** |

合起来：**至少三个英文字母**。这是最容易读懂的一条例子，课件就是拿它演示"校验逻辑可以写多复杂而仍然不用 JS"。

> [!tip] 为什么这件事值得强调
> 初学者的默认假设是"校验 = 写 JavaScript 判断"。课件把这一点明确否掉了：**浏览器已经内建了一整套校验，`<input>` 上加个属性就生效。** 表单可访问性那一页的第一条是 **Label every control**，第四条是 **Validate: required and type do the checks for free**（`required` 和 `type` 免费做完检查）。
>
> JavaScript 该管的是浏览器**管不了**的东西——比如"这个学号在数据库里存不存在"。

## 三、一份完整表单

课件把前面所有点合成一个例子，标题就叫 **A Complete Form**：

```html
<form action="/signup" method="post">
  <label for="n">Name</label>
  <input id="n" name="name" required>
  <label for="e">Email</label>
  <input id="e" type="email" required>
  <button type="submit">Sign up</button>
</form>
```

课件列出的四条要求，逐条对上：

| 课件的要求 | 例子里的体现 |
|---|---|
| **Label every control**（每个控件都配标签） | `<label for="n">` / `<label for="e">` |
| **Group with `fieldset`**（用 `fieldset` 分组） | 课件点名的分组手段 |
| **Submit button**（提交按钮） | `<button type="submit">Sign up</button>`，**触发发往 action 的发送** |
| **Validate**（校验） | 两个 `required` + `type="email"` —— **免费** |

这份例子里没有 `placeholder`，因为**标签已经说清了每个字段是什么**。

课件在这份表单底下留了一句：**Week 11: an Express route will receive this form's fields**（一条 Express 路由会收到这个表单的字段）。这条属于 Week 11，本库目前只有 [[后端技术栈]] 的 Week 1 概览层级可以对应。

> [!note] 把它放到示例站上
> 那个假想课程主页（设定见 [[课程场景与阅读约定]]）的 `main` 里就有一块"报名表单"。上面这段 `<form action="/signup" method="post">` 就是它可以长成的样子：`action` 指向报名接口，`method="post"` 因为要提交邮箱属于敏感信息，每个字段都有 `label`，必填项都带 `required`——**没有一行 JavaScript**。

## 四、检查清单

写完一个表单，对着这五条过一遍：

1. 每个 `<input>` 旁边都有 `<label for="对应 id">`？
2. `for` 的值和 `id` 的值**一字不差**？
3. 有没有哪个字段只靠 `placeholder` 说明用途？→ 补 label。
4. 该限制的都限制了吗（`required` / `min` / `max` / `minlength` / `pattern`）？
5. 敏感内容（密码、邮箱、学号）走的是 `method="post"` 吗？
