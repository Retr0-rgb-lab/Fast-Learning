# 链接与图像 · Links & Images

> **一句话**：`<a>` 的 `href` 是唯一必需属性、写法有五种形态，`<img>` 必须**永远写 `alt`**、**永远同时写 `width` 和 `height`**，而 `<picture>` 让同一张图在不同屏幕上有不同版本。

课件原文见 [Lecture_02_HTML.pptx](<../../raw/Lecture_02_HTML.pptx>)。本篇覆盖课件的 "Links — the `<a>` Element"、"Images — the `<img>` Element" 和 "The `<picture>` Element" 三部分。

## 一、链接：`<a>`

课件给这页的结论是：**Links are what make the web a web — one page points to another**（链接是让 Web 成为 Web 的东西——一个页面指向另一个页面）。

| 属性 / 形态 | 课件的说法 |
|---|---|
| `href` | 目的地（destination）——**唯一必需的属性** |
| **Absolute URLs** | 完整地址：`https://polyu.edu.hk/…` |
| **Relative paths** | `about.html`、`../index.html`——相对于**当前页** |
| `mailto:` | `href="mailto:you@polyu.edu.hk"` 打开邮件客户端 |
| `target` | `_blank` 新标签页 · `_self` 同一标签页（**默认**） |
| **Bookmarks** | `href="#id"` 跳到**同一页内**某个元素 |

```html
<a href="https://polyu.edu.hk">PolyU</a>
<!-- relative links -->
<a href="about.html">About</a>
<a href="../index.html">Home</a>
<a href="mailto:you@polyu.edu.hk">Email me</a>
<a href="#top">Jump to top</a>
<h2 id="top">Top</h2>
```

### 三种路径写法怎么选

| 写法 | 例子 | 什么时候用 |
|---|---|---|
| 绝对 URL | `https://polyu.edu.hk/` | 指向站外页面 |
| 相对路径 | `about.html` | 同目录的另一个页面 |
| 相对路径（上一级） | `../index.html` | 站内的父目录，用 `..` 回退一层 |

注意最后两行：`<a href="#top">` 里的 `#top` 与 `<h2 id="top">` 里的 `id="top"` 是一对。**这里的 `id` 正是 [[属性]] 那一篇说的"钩子"——它同时是链接的锚点、`<label for>` 的连接对象、JavaScript 的定位方式。**

## 二、图像：`<img>`

| 属性 | 课件的说法 |
|---|---|
| `src` | 要加载的图像文件 |
| `alt` | **图像失败时显示的文字**——同时**被屏幕阅读器读出来** |
| `width` / `height` | 尺寸**默认单位是像素**——**两个都写**，以避免布局偏移（layout shift） |
| （元素本身） | **void element**——没有结束标签，自成一体 |
| **Always set `alt`** | 可访问性和 SEO **都依赖它** |

```html
<img src="logo.png"
alt="PolyU logo" width="500" height="600">
<!-- an image can be a link -->
<a href="home.html"><img src="logo.png" alt="Home"></a>
```

课件的强调句：**alt text is not optional — it is what a screen reader speaks**（alt 文本不是可选项——它是屏幕阅读器会念出来的东西）。

### 为什么 `width` 和 `height` 必须成对写

这是图像这页最实用的一条。原因不在图片本身，在**布局**：

图片加载需要时间。**如果只写 `width` 不写 `height`（或都不写），浏览器在图片出现之前不知道该给它留多高的位置**，于是先按"零高度"排好版，图片一到，下面所有内容整体往下跳一次。这个跳动就是 layout shift。

把两个数字都写上，浏览器立刻就知道预留空间，**页面从头到尾不跳**。

> [!warning] 这两个数字改不得太离谱
> 课件给的例子是 `width="500" height="600"`，这两个数是**这张图片文件本身的像素尺寸**。写错了不会让图片变形（浏览器会按你给的盒子缩放），但会给排版错误的信号。下一个话题 [[图像映射]] 会把这条要求提到硬性程度：那里连一个像素都不能错。

### 图像也可以是链接

```html
<a href="home.html"><img src="logo.png" alt="Home"></a>
```

`<a>` 里套 `<img>`，就得到一个可点的 logo。两个元素都是 void 元素时也不需要额外处理。

## 三、`<picture>`：按屏幕挑图

| 机制 | 课件的说法 |
|---|---|
| Responsive images | **按屏幕尺寸加载不同的图像** |
| `<source media=…>` | 一条**媒体查询**决定用哪张图 |
| `<img>` fallback | 当**没有任何一条 source 匹配**时，用最后那个 `<img>` |
| **Art direction**（艺术指导） | 为小屏和大屏**裁切或替换**不同的图 |

```html
<picture>
  <source media="(min-width: 650px)"
    srcset="large.jpg" />
  <source media="(min-width: 465px)"
    srcset="medium.jpg" />
  <img src="small.jpg" alt="A responsive image" />
</picture>
```

读法：**从上往下**看三条 source。屏幕宽度至少 650px → `large.jpg`；否则至少 465px → `medium.jpg`；再小 → 落到 `<img>` 的 `small.jpg`。

课件的结论：**The browser picks the right image — one `<picture>`, any device**（浏览器挑对图——一个 `<picture>`，适配任何设备）。

> [!note] art direction 和"缩放"不是一回事
> 课件用的词是 **crop or swap**（裁切或替换）——不同屏幕给的是**不同的图**，而不是同一张图的不同尺寸。这和 CSS 里的响应式是两件事：那边改的是**盒子的大小**，这边换的是**图片文件本身**。CSS 那边怎么写媒体查询，见 [[响应式与媒体查询]]。
