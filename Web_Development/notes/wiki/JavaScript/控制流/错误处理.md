# 错误处理 · try, catch, finally

> **一句话**：错误是在**运行时**才发生的（输入不合法、元素不存在、标识符拼错），`try` 圈出可能出错的代码、`catch` 接住被抛出来的东西、`finally` **无论成败都跑**（收尾放这儿）；而 `throw` 可以由你自己抛——**抛一个字符串也行**，`catch` 收到的就是它。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §4 Statements 中 Errors — try, catch, finally 一页：三个关键字的职责、运行时错误的来源，以及那个 `check()` 校验函数的逐行解读。

## 一、错误为什么在运行时才炸

JavaScript 只有在**代码真的执行到那一步**时才会发现问题。典型的三个来源：

| 来源 | 具体表现 |
|---|---|
| **输入不对** | 用户在要求数字的字段里填了 `"abc"`；`isNaN` / 类型判断会失败 |
| **元素不存在** | `getElementById` 返回 `null`，再读它的属性就出错 |
| **标识符拼错** | 变量名少一个字母，读出来是 `undefined`，用到它时才崩 |

这类错误**没法靠通读代码全部避免**——只有当用户真的在那个框里打了 `abc` 时，问题才出现。所以处理方式不是"保证不出错"，而是"**出错时别让整页死掉**"。这就是 `try` / `catch` / `finally` 的职责。

## 二、三个关键字的职责

```js
try {
  可能出错的代码
} catch (err) {
  出错了怎么办
} finally {
  收尾，无论成败都跑
}
```

| 关键字 | 职责 | 课件的说法 |
|---|---|---|
| `try` | 圈出**有风险的那段**。块里的每一步都在监视之下 | *marks the risky code* |
| `catch (err)` | 出错时执行；**被抛出来的东西作为参数送到这里** | *handles the failure* |
| `finally` | 一定执行，不管有没有出错 | *always runs* |
| `throw` | 你自己抛一个值出去 | *A string, an Error object — anything you can describe the problem with* |

`catch` 和 `finally` **都可以省略**，但 `try` 里的 `catch` 省略了就等于没保护。`throw` 可以出现在 `try` 块里的任何地方——**一执行到就立刻跳出整个 `try`**，剩下的语句（包括后面的 `throw` 检查）都不再跑，直接进 `catch`。

## 三、`check()` 逐行解读

课件的例子是一个表单校验函数：

```js
function check() {
  let x = document.getElementById("demo").value;
  try {
    if (x.trim() === "") throw "empty";
    if (isNaN(x))        throw "not a number";
    x = Number(x);
    if (x < 5)  throw "too low";
    if (x > 10) throw "too high";
  } catch (err) {
    message.innerHTML = "Input is " + err;
  }
}
```

逐行看：

| 行 | 做什么 | 什么时候中断 |
|---|---|---|
| `let x = ...value;` | 从输入框读出原始文本 | —— |
| `if (x.trim() === "") throw "empty";` | `trim()` 去掉首尾空格，若结果为空串说明只填了空格 | 抛 `"empty"` |
| `if (isNaN(x)) throw "not a number";` | `isNaN` 判断文本能不能当数字看 | 抛 `"not a number"` |
| `x = Number(x);` | 通过检查，**转成真正的数字**往下走 | —— |
| `if (x < 5) throw "too low";` | 范围下界 | 抛 `"too low"` |
| `if (x > 10) throw "too high";` | 范围上界 | 抛 `"too high"` |
| 全部通过 | **`try` 正常结束，函数什么都不输出**（值合法） | —— |
| `catch (err)` | 接收刚才抛出的那个**字符串** | —— |
| `message.innerHTML = "Input is " + err;` | 把标签拼进提示语 | —— |

**每一个 `throw` 抛的都是一个字符串标签**，`catch` 的 `err` 收到的就是这个字符串。`"Input is " + err` 拼出来的结果分别是：

| 输入 | 抛出的字符串 | 页面提示 |
|---|---|---|
| `"   "` | `"empty"` | `Input is empty` |
| `"abc"` | `"not a number"` | `Input is not a number` |
| `"3"` | `"too low"` | `Input is too low` |
| `"20"` | `"too high"` | `Input is too high` |
| `"7"` | —— 什么都不抛 | 没有提示（合法） |

注意**四道检查是短路的**：填 `"abc"` 时第二个 `throw` 就中断了，后面的 `Number(x)`、范围检查根本不会执行。所以"多个错误同时存在"时，页面只会显示**最先发现的那一个**。

> [!warning] `try` 只保护"运行到的那几行"
> `try` 块外面出错（比如函数还没被调用就少了个分号导致的解析错误）一样会中断页面。而且如果 `try` 块里第一行 `document.getElementById(...)` 拿到的是 `null`，那 `.value` 本身就会出错——**保护代码得从"可能失败的第一个操作"开始写**，见 [[查找元素]]。

## 四、这个例子里两个需要留意的写法

### 1. `getElementById` 返回的值

课件示例直接从输入框读 `.value`。一个 `<div>` 没有 `value` 属性——只有 `<input>`、`<textarea>`、`<select>` 才有。所以**这行代码要求那个元素是表单控件**；如果它指向一个 `div`，读出来是 `undefined`，紧接着的 `x.trim()` 就会出错，而**这个错误本身也发生在 `try` 块内**，所以会被同一个 `catch` 接住、显示成 `Input is undefined`。

在示例站上照着这个函数跑一遍时（见 [[课程场景与阅读约定]] 里 `demo` 元素那条约定），把取值目标换成一个真正的输入框即可：

```html
<input id="answer" value="">
<p id="message"></p>
```

```js
function check() {
  const field = document.getElementById("answer");
  let x = field.value;                    // 读的是 input，拿到的是字符串

  try {
    if (x.trim() === "") throw "empty";
    if (isNaN(x))        throw "not a number";
    x = Number(x);
    if (x < 5)  throw "too low";
    if (x > 10) throw "too high";
    // 全部通过：把转换后的数字显示出来
    const out = document.getElementById("message");
    if (out) out.innerHTML = "Got " + x;
  } catch (err) {
    const out = document.getElementById("message");
    if (out) out.innerHTML = "Input is " + err;   // Input is empty / too low / …
  }
}
```

### 2. `message` 是怎么被找到的

课件写的是 `message.innerHTML = ...`——**没有 `document.`**。浏览器会把页面上 `id="message"` 的元素当作一个全局变量名暴露出来（这是 HTML 规范里 Window 对象的具名访问）。它能用，但**依赖了浏览器的这个便利行为**，稳妥的写法是显式 `document.getElementById("message")`，并且按本库约定先检查它不是 `null` 再改属性（见 [[修改元素]]）。

## 五、`throw` 该抛什么

课件说得很宽：*A string, an Error object — anything you can describe the problem with*。两种常见做法：

| 抛什么 | 例子 | 优点 | 缺点 |
|---|---|---|---|
| 字符串 | `throw "too low";` | 短、直接、`catch` 里拼字符串最省事 | 没有堆栈信息；拼出来的提示语变成 `Input is undefined` 这种没头没脑的句子 |
| `Error` 对象 | `throw new Error("too low");` | 自带 `message` 和堆栈（`console` 里能查到出错位置） | 拼接时要写 `err.message` |

本课以课件的**字符串**版本为主。两者的控制流完全一样：都是**立刻跳出 `try`、进入 `catch`、`finally` 照跑**。区别只在于 `catch` 拿到的对象的形状。
