# 条件语句 · Conditional Statements

> **一句话**：`if` / `else if` / `else` 就是"按顺序试一串条件"——**条件可以是任何表达式，由它的真值（truthiness）决定走不走**；`else if` 链里**第一个成立的分支赢，后面的全跳过**；花括号**永远写**，哪怕分支里只有一行。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §4 Statements 中 Conditional Statements 一页：三个分支各自的职责、条件的真值判断、`else if` 链的短路，以及花括号为什么不能省。

## 一、三个分支的职责

| 关键字 | 干什么 | 什么时候写 |
|---|---|---|
| `if` | 条件为真时执行一个代码块 | 第一个判断 |
| `else` | 上面都不成立时的**兜底** | 一定要有"其他情况" |
| `else if` | 追加一个判断，接着往下排 | 需要区分第三、第四种情况 |

关键是**从上往下读**的顺序：先 `if`，不成立看 `else if`，再不成立看 `else`。

```js
if (条件1) {
  A
} else if (条件2) {
  B
} else {
  C
}
```

- 条件 1 成立 → 只做 A，B 和 C 都不执行
- 条件 1 不成立、条件 2 成立 → 只做 B
- 两个都不成立 → 只做 C

## 二、条件是"任何表达式"，真假由真值转换决定

括号里**不需要**是一个布尔。写任何表达式都行，JavaScript 会问它一个问题：**"你算是真的吗？"**

| 表达式 | 答案 | 说明 |
|---|---|---|
| `15 < 10` | `false` | 比较的结果是布尔 |
| `"BMW"` | `true` | 非空字符串算真 |
| `""` | `false` | 空字符串算假 |
| `0` | `false` | 零算假 |
| `-1` | `true` | **只有 0 算假**，负数是真的 |
| `cars.length` | 看情况 | 0 时假，非 0 时真 |
| `null` / `undefined` | `false` | 见 [[数组与空值]] |
| `NaN` | `false` | "不是一个数"这个结果也算假 |

**只有七种"假"**：`false`、`0`、`""`、`null`、`undefined`、`NaN`，以及文档里的 `document.all`（本课不涉及）。**其余一切都为真**，包括 `[]`、`{}` 和 `"-0"` 这样的反直觉值。

> [!warning] `[]` 和 `{}` 是真值
> 空数组和空对象**为真**——它们确实是一个存在的东西。写成 `if (items)` 来判断"有没有东西"时，拿到一个空数组会进分支。想要判断"数组里有没有东西"，必须写 `if (items.length)`。

课件里"比较的结果就是布尔"这一点，和真值转换是配套的：见 [[运算符]] 与 [[比较与typeof]]。

## 三、`else if` 链：第一个成立的赢

`else if` 可以排很多个，但它们是**短路的**（short-circuit）：一旦某个条件成立，**后面的条件根本不求值**，后面的分支全部跳过。

```js
let time = 15;
let greeting;
if (time < 10) {
  greeting = "Good morning";
} else if (time < 20) {
  greeting = "Good day";
} else {
  greeting = "Good evening";
}
```

`time = 15` 一步步走：

| 步骤 | 判断 | 结果 |
|---|---|---|
| 1 | `15 < 10` | `false` → 不进第一个分支 |
| 2 | `15 < 20` | **`true`** → 进第二个分支 |
| 3 | — | `else` **被跳过** |
| 结果 | — | `greeting` 是 `"Good day"` |

注意判断 2 依赖判断 1 不成立——**顺序有意义**。把两个条件调换过来，`time = 15` 就会在第一个分支被 `15 < 20` 接走，得到 `"Good morning"`，语义完全变了。**所以 `else if` 链要按"从窄到宽"或"从具体到笼统"来排。**

| 排法 | 例子 | 适合 |
|---|---|---|
| 从具体到宽泛 | 先 `=== 6` 周六，再 `< 10` 上午 | 有明确特例要单独处理 |
| 从宽到窄 | 先 `< 10`，再 `< 20` | 纯粹的数值区间划分（像上面这段） |

## 四、花括号永远写

> **Always write the braces** —— even for a single statement.

课件给的理由是：它挡住了 *the classic edit that silently changes meaning*（那个悄悄改变含义的经典改动）。

```js
// 能跑，但危险
if (time < 10)
  greeting = "Good morning";
  console.log(time);        // ← 永远执行！它不在 if 里面
```

花括号是**代码块的边界**。上面 `console.log` 那一行看起来"缩进不对"（和 `greeting` 对齐了），但它确实是独立的语句，会无条件执行——**缩进只是给人看的，JavaScript 只认花括号**。这种代码一旦被人加一行、删一行或者调整缩进，就彻底变了意思，而且**不会报任何错**。

## 五、写进示例站

```js
let time = 15;
let greeting;

if (time < 10) {                        // 15 < 10 → false
  greeting = "Good morning";
} else if (time < 20) {                 // 15 < 20 → true，第一个成立的分支
  greeting = "Good day";
} else {                                // 跳过
  greeting = "Good evening";
}

const demo = document.getElementById("demo");
if (demo) {
  demo.innerHTML = greeting;            // Good day
}
```
