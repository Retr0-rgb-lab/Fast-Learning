# 位运算符 · Bitwise Operators

> **一句话**：位运算符直接看数据的二进制位（`&` 与、`|` 或、`^` 异或、`~` 取反、`<<` `>>` `>>>` 移位）；`>>` **保留符号位**、`>>>` **高位补零**，这是两者唯一的区别；它们在页面代码里很少见，你是在**标志位、哈希和颜色计算**里遇到它们的。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §4 Statements 中 Bitwise Operators 一页：七个运算符的完整表格，以及 `>>` 与 `>>>` 的差别。

## 一、完整表格

| 运算符 | 名称 | 做什么 |
|---|---|---|
| `&` | AND | 两位**都是** 1 时结果为 1 |
| `\|` | OR | 两位**任意一个**是 1 时结果为 1 |
| `^` | XOR | **恰好一个**是 1 时结果为 1（两个都是 1 时反而是 0） |
| `~` | NOT | 每一个位取反（1↔0） |
| `<<` | left shift | 左移，右侧**补零** |
| `>>` | signed right shift | 右移，**保留符号位** |
| `>>>` | zero-fill right shift | 右移，左侧**补零** |

注意前三个是**逐位独立**运算的：结果里的每一位，只由输入的对应那两位决定。移位则是把整个数的位往一个方向挪。

## 二、逐位运算举例

用 4 位的数看最清楚。设 `a = 12`（二进制 `1100`）、`b = 10`（`1010`）：

| 运算 | 二进制 | 结果（十进制） |
|---|---|---|
| `a & b` | `1100` 与 `1010` → `1000` | `8` |
| `a \| b` | `1100` 或 `1010` → `1110` | `14` |
| `a ^ b` | `1100` 异或 `1010` → `0110` | `6` |
| `~a`（4 位下） | `1100` → `0011` | `3` |

`^` 那行值得多看一眼：`1100` 和 `1010` 的前两位**都是 1**，异或把它们消成 0；后两位一 0 一 1，保留 1。**"恰好一个"就是异或的全部定义。**

## 三、`>>` 和 `>>>` 的唯一区别

两者都是右移，区别在**左边空出来的位置填什么**：

| | 填什么 | 遇到负数 |
|---|---|---|
| `>>` | **保留符号位** | 一直是负数，除以 2 向下取整 |
| `>>>` | **补零** | 变成一个很大的正数 |

关键在于 JavaScript 的负数用**补码**（two's complement）表示：正数的最高位是 `0`，负数的最高位是 `1`。"符号位"就是最高位。

看一个负数（32 位）：

```
-8 的二进制： 1111 1111 1111 1111 1111 1111 1111 1000
```

- `-8 >> 1`：最高位是 `1`，右移时**把它带下来补到左边** → 结果还是负数，等于数学上的 `-8 / 2` 向下取整 = **`-4`**
- `-8 >>> 1`：右移后左边**一律补 0**，最高位变成 `0` → 结果是个正数 **`2147483644`**

| 表达式 | 结果 |
|---|---|
| `-8 >> 1` | `-4` |
| `-8 >>> 1` | `2147483644` |

用 `>>>` 的典型场景是**把一个带符号的数当作无符号的位容器来看**——比如手动做哈希（hash）或者拼接标志位时，你要的是"这些位"，不是"这个数算出来是多少"。反过来，如果你**就是想要除以 2**（正负都算），那必须用 `>>`：`-7 >> 1` 给出 `-4`（向负无穷取整），而 `-7 >>> 1` 会给出一个两亿量级的正数，完全不是你要的。

> [!warning] `>>>` 在负数上会得到"莫名其妙的大数"
> 它的行为完全正确（就是"右移补零"），但用错地方时症状是**一个几十亿的正数**，看起来像溢出。写右移之前先问一句：**这个数可能为负吗？** 会为负就用 `>>`；只在明确想看位的时候才用 `>>>`。

## 四、什么时候真的会遇到它们

课件在这一页的最后给了一句判断：

> Rare in page code — you meet them in flags, hashes and colour arithmetic.

也就是"页面代码里很少用"，但有三类地方是它们的正经位置：

| 场景 | 用法 | 为什么非它不可 |
|---|---|---|
| **标志位**（flags） | 每一个位代表一个开关：`FLAG_EDIT = 1`、`FLAG_VIEW = 2`、`FLAG_ADMIN = 4`；用 `&` 测有没有、用 `\|` 打开、用 `^` 翻转 | 一整个整数装下一堆开关，省内存也省网络 |
| **哈希**（hashes） | 把字符串或内容压成一个整数做比较 | 位运算比算术便宜得多 |
| **颜色计算**（colour arithmetic） | 在 RGB 分量上直接算明暗：`color & 0x00ffffff` 去掉 alpha 通道 | 分量之间互不干扰，逐位处理最省事 |

前三行之外，位运算**几乎总是多余的**。普通的加、减、乘、除足够时，不要为了"显得底层"而写 `<< 1` 代替 `* 2`——可读性换不来任何性能。

## 五、和算术运算符的关系

| | 算术运算符 | 位运算符 |
|---|---|---|
| 例子 | `+` `-` `*` `/` `%` | `&` `\|` `^` `~` `<<` `>>` `>>>` |
| 作用对象 | 数值大小 | 二进制的**每一个位** |
| 结果的 `typeof` | `"number"` | `"number"`（位运算的结果仍然是原始值） |
| 需要懂二进制吗 | 不需要 | 需要——这是位运算门槛高的原因 |

它们返回的仍然是原始值 `number`（原始值不可变的规则一样适用），这一点见 [[原始值与引用值]]。至于"这些运算符和 `+` `===` 混在一起时怎么解析"，见 [[运算符]]；结果的真假判断见 [[条件语句]]。
