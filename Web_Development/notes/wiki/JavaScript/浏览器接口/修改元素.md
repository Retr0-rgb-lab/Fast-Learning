# 修改元素 · Changing Elements

> **一句话**：改一个元素就三条路——改内容（`innerHTML` / `textContent`）、改属性（`setAttribute` 或直接赋值）、改外观（`element.style`），而走这三条路之前必须先**确认节点不是 `null`**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇对应 §7 *The DOM & the BOM* 里的 "Changing Elements" 一页。

## 一、四条课件要点

| 动作 | 成员 | 课件的说法 |
|---|---|---|
| 改内容 | `innerHTML` | **parses markup** —— 会把里面的标记**解析**成真的节点 |
| 改内容 | `textContent` | **is plain text and safer** —— 纯文本，更安全 |
| 改属性 | `element.setAttribute(name, value)` | 或者**直接给属性赋值** |
| 改外观 | 赋值给 `element.style` | 写入的是一条**内联声明**（inline declaration） |
| 前提 | 先读后写 | 确认元素找到了：`null` 没有属性，而这个错误**在发作前一直是沉默的** |

课件原文那条 *Read before you write* 是这一页的中心，下面「先读后写」一节专门展开。

## 二、改内容：`innerHTML` 与 `textContent`

```js
const el = document.querySelector("#demo");
el.innerHTML = "<b>Hello</b>";   // 解析标记：页面上出现一个真的 <b>，字是粗的
el.textContent = "Hello";        // 不解析：页面上出现的是字面量 "<b>Hello</b>" 七个字符
```

同一个字符串，写进 `innerHTML` 得到的是**一棵新的子树**，写进 `textContent` 得到的是**一个字面文本节点**。区别在 [[DOM树]] 那一页讲得很直接：浏览器把标记解析成节点，而 `textContent` 根本不给你走这一步。

> [!warning] `innerHTML` 会解析不可信的标记
> `innerHTML` 把字符串当 HTML 解析。如果你写进去的内容来自用户输入或服务器返回，而里面夹带了一段标记，那段标记**会被当成真节点插进页面**——这就是把不可信内容塞进 `innerHTML` 的风险。课件因此说 `textContent` **safer**：它只当字符串，永远不会解析出标记。默认拿不准的时候用 `textContent` 是更稳的选择。

## 三、改属性：两条路

```js
const el = document.querySelector("#demo");

// 路 1：setAttribute，写的是 HTML 里的那个属性名
el.setAttribute("class", "urgent");

// 路 2：直接给属性赋值，写的是 JS 那个属性名
el.setAttribute("id", "demo");
el.id = "demo";
```

两条路得到的结果一样，但**名字的写法不一样**，这是初学时最容易卡住的地方：

| | `setAttribute` 里写的名字 | 直接赋值时写的名字 |
|---|---|---|
| `class` | `setAttribute("class", "urgent")` | `el.className = "urgent"` |
| `id` | `setAttribute("id", "demo")` | `el.id = "demo"` |
| 通用规则 | **和 HTML 里写的一模一样** | 和 JS 里那个属性名一致 |

`class` 是 HTML 保留字，在 JS 里不能写成 `el.class`，所以它对应的属性叫 `className`。课件这一页没有展开这条命名规则，只给了 `setAttribute(name, value)` 和"直接设属性"两种方式；两者的差别就在上面这张表里。

## 四、改外观：`element.style` 写的是内联声明

```js
const el = document.querySelector("#demo");
el.style.color = "red";
```

这一句产生的效果，等价于你在这个元素的 HTML 标签上手写了一条：

```html
<div id="demo" style="color: red;"></div>
```

也就是说它落在**内联样式**这一档，来自 [[样式声明与内联]] 讲的"一条声明由什么组成"。内联声明的优先级高于外链样式表里的同属性规则，这是 [[层叠与优先级]] 的第一条来源顺序——所以从 JS 写的这个 `color` 会赢过样式表里的 `color`。

具体怎么用 `style`、`classList` 和 `getComputedStyle`，在 [[JavaScript改样式]] 里展开。

## 五、先读后写（Read before you write）

课件的第四句：*Check the element was found: `null` has no properties, and that error is silent until it is not*。

"silent until it is not" 的意思是——**代码写得再错，页面也不会当场报错**。查找失败返回的 `null` 不会在写代码时提醒你，它只是安静地待在那里；直到某一行真的执行到 `null` 的属性上，脚本才抛 `TypeError` 停在那儿。

```js
const el = document.querySelector("#demo");
// 假如这个 id 打错了：
el.textContent = "Hello";
// TypeError: Cannot set properties of null (setting 'textContent')
```

为什么查找会失败？课件在 Common Mistakes 一页给的解释是 **Running the script too early**：元素还没被解析到，`querySelector` 就返回了 `null`。解法是把 script 放最后或者加 `defer`（详见 [[脚本放在哪里]]）。查找失败的其他情形见 [[查找元素]]。

## 六、本库统一写法

`demo` 指「示例站」`main` 区域里的 `<div id="demo"></div>`，是课堂演示的结果输出框（设定见 [[课程场景与阅读约定]]）。**本库所有 DOM 例子一律按下面这个顺序写，不省略任何一步**：

```js
// ① 先 querySelector 拿到节点
const el = document.querySelector("#demo");

// ② 检查它不是 null
if (el) {
  // ③ 再改属性
  el.innerHTML = "<b>Hello</b>";       // 解析标记
  el.textContent = "Hello";            // 纯文本，不解析
  el.setAttribute("class", "urgent");  // 改属性
  el.style.color = "red";              // 改外观，写一条内联声明
}
```

课件示例本身就是这四行的连续写法：

```js
const el = document.querySelector("#demo");
el.innerHTML = "<b>Hello</b>";
el.textContent = "Hello";    // no HTML parsing
el.setAttribute("class", "urgent");
el.style.color = "red";
```

课件为了讲得紧凑省掉了 `if`，实际代码里加上这一步是必要的。
