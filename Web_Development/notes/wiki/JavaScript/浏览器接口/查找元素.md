# 查找元素 · Finding Elements

> **一句话**：课件给了五个查找方法，分成 classic 与 modern 两派，最该记的分水岭是 **`getElementsBy*` 返回活的集合、`querySelectorAll` 返回静态的快照**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇对应 §7 *The DOM & the BOM* 里的 "Finding Elements" 一页。

## 一、五个方法

| Method | What you get | Style |
|---|---|---|
| `document.getElementById("x")` | the one element with that id | classic |
| `document.getElementsByTagName("p")` | a **live** collection of tags | classic |
| `document.getElementsByClassName("c")` | a **live** collection by class | classic |
| `document.querySelector("sel")` | the **first** match of any selector | modern |
| `document.querySelectorAll("sel")` | a **static** list of every match | modern |

课件在表下面特意点了一句：**querySelectorAll is static — the list is taken once and does not grow with the page**（`querySelectorAll` 是静态的：列表取一次，不会随页面增长）。

## 二、classic 与 modern 到底差在哪

"两派"的分界不在写法，而在**能力**：

| | classic (`getElementById` / `getElementsBy*`) | modern (`querySelector` / `querySelectorAll`) |
|---|---|---|
| 能用什么定位 | 只有 id、标签名、class 三种入口 | **任意 CSS 选择器**：`.card > p`、`input[name="q"]`、`li:first-child` |
| 返回什么 | 单个元素，或同类的**集合** | 单个元素，或任意选择器的**全部命中** |
| 集合是否活的 | `getElementsBy*` 是活的 | `querySelectorAll` 是静态的 |
| 代码里还会不会出现 `NodeList` 这类词 | 会（集合对象，不是普通数组） | 同样会（也是集合对象） |

现代派最大的价值是**选择器统一**：[[简单选择器]] 和 [[属性选择器]] 讲的那套 CSS 定位规则，原封不动就是 `querySelector` 的参数。CSS 选 `.card > p`，脚本就能写 `querySelector(".card > p")`，不必退回"先按 class 拿，再在结果里挑"。

```js
// classic 做不到的：按属性挑
document.querySelector('input[name="q"]');          // 属性选择器
document.querySelector(".card > p");                 // 组合选择器
document.querySelector("li:first-child");            // 结构伪类

// classic 的写法：只能按名字
document.getElementsByClassName("card")[0];          // 拿到的是全部，不是"第一个匹配"
```

## 三、活的 vs 静态：本页最该记的一条

两种集合对页面变化的反应完全不同。

假设「示例站」里有这样一段列表：

```html
<ul id="week-list">
  <li>Week 1</li>
  <li>Week 2</li>
</ul>
```

```js
const live  = document.getElementsByTagName("li");   // 活的
const still = document.querySelectorAll("li");       // 静态的
live.length;   // 2
still.length;  // 2

// 之后页面自己变出一条新的（也可以是别的脚本加的）
const item = document.createElement("li");
item.textContent = "Week 3";
document.getElementById("week-list").appendChild(item);

live.length;   // 3  ← 同一个对象，内容自己变了
still.length;  // 2  ← 还是当初那份快照
```

差别不在"哪个更对"，而在**你要的是集合本身，还是集合当时的样子**：

- 写 `while (live.length)` 这类循环时，**静态反而更安全**——循环过程中元素还在增删，活集合会边遍历边变形。
- 只是想一次性遍历当前内容、或者想用数组方法，静态快照更省心。
- 活集合占着页面的引用，元素删了它会跟着收缩，这正是它的特性而不是 bug。

> [!warning] 活的 vs 静态：考的就是这一句
> `getElementsByTagName` 和 `getElementsByClassName` 返回**活集合**，`querySelectorAll` 返回**静态列表**。课件把 `live` 三个字母加粗写在表格里，并在表下单独重申 static，原因是初学者最常见的错就是"以为 `querySelectorAll` 的结果会自动跟着页面长"——它不会。

## 四、`null`：查不到时会发生什么

三个 single-element 方法（`getElementById`、`querySelector`）在**没找到时返回 `null`**，而不是返回空集合：

```js
const el = document.querySelector("#demo");
// el 是 null 时：
el.textContent = "hi";     // TypeError: Cannot set properties of null
```

`null` **没有属性**，所以任何属性读写都会抛 `TypeError`。课件把这件事写成 **Read before you write — Check the element was found: `null` has no properties, and that error is silent until it is not**（写之前先读：确认元素找到了，`null` 没有属性，而这个错误在它发作之前一直是沉默的）。

"silent until it is not" 指的是：脚本不会在你写代码时报错，页面看着也正常，只有当这一行真的执行到的时候才炸。所以本库所有 DOM 例子统一按下面「本库统一写法」一节的顺序写。

### 为什么会是 `null`——课件自己给的答案

课件 Common Mistakes 一页列了 **Running the script too early**：`querySelector returns null if the element is not parsed yet: put the script last, or defer it`（脚本跑得太早：元素还没被解析到，`querySelector` 就返回 `null`——把 script 标签放到最后，或者给它加 `defer`）。

原因在 [[DOM树]]：浏览器是**边解析 HTML 边建树**的，而 `<script>` 默认在解析到它的那一刻就执行。如果脚本写在 `<body>` 里、目标元素在它**后面**，执行那一刻那个节点根本还不存在。

```html
<!-- 会拿到 null：#demo 还没解析到 -->
<script src="app.js"></script>
<div id="demo"></div>

<!-- 两种解法 -->
<script src="app.js" defer></script>   <!-- defer：等解析完再执行 -->
<div id="demo"></div>
```

这条实践的完整讨论（`defer` / `async` / 放 `body` 末尾）在 [[脚本放在哪里]]。

## 六、本库统一写法

`demo` 指「示例站」`main` 区域里的 `<div id="demo"></div>`——课堂演示的结果输出框，正式功能页面上不会用这个 id 名（设定见 [[课程场景与阅读约定]]）。本库所有 DOM 例子一律按这个顺序：

```js
// 先 querySelector 拿到节点
const el = document.querySelector("#demo");
// 检查它不是 null
if (el) {
  // 再改属性
  el.textContent = "Hello";
}
```

三个词在本库里的含义固定下来：**先 `querySelector` 拿到节点 → 检查不是 `null` → 再改属性**。这条顺序出自课件的 *Read before you write*，写在 [[修改元素]] 那一页。

## 关联

- 同一个字符串 → [[简单选择器]]（`querySelector` 的参数就是 CSS 的标签/id/class 选择器，规则完全共用）
- 定位能力 → [[属性选择器]]（`input[name="q"]` 这类只有 modern 方法能用，classic 三个方法都表达不了）
- 根因 → [[DOM树]]（元素要被解析进树里才存在，脚本跑得太早就查不到）
- 位置决定 → [[脚本放在哪里]]（`defer` 与"script 放最后"是课件给的两个解法）
- 写法的来源 → [[修改元素]]（「先查 `null` 再改属性」的完整写法在那里）
- 报错处理 → [[错误处理]]（拿到 `null` 之后，可以用 `try/catch` 让程序不至于整段停掉）
