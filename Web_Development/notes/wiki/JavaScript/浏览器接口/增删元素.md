# 增删元素 · Adding and Removing Elements

> **一句话**：`createElement` 只在内存里造出一个节点，**挂到已经在树上的东西下面它才会出现在页面上**——这就是新增元素的全部秘密。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇对应 §7 *The DOM & the BOM* 里的 "Adding and Removing Elements" 一页。

## 一、五个成员

| Method | What it does |
|---|---|
| `document.createElement("li")` | builds a new element **in memory** |
| `parent.appendChild(node)` | attaches it — **now it is on the page** |
| `parent.removeChild(node)` | detaches one child node |
| `parent.replaceChild(new, old)` | swaps one child for another |
| `node.remove()` | removes the node itself |

课件在表下面单独加了一句：**A new element is invisible until it is attached to something already in the tree**（一个新元素在挂到已经在树里的东西上之前是不可见的）。

## 二、内存 vs 页面

这是本篇唯一需要真正想清楚的事：**造出来 ≠ 出现**。

```js
const item = document.createElement("li");
item.textContent = "Week 3";
// 此时页面上什么都没有变化 —— item 只是个躺在内存里的对象
```

`document.createElement("li")` 的返回是一个**节点对象**：你可以给它设 `textContent`、设 `class`、改 `style`，它都照单全收——因为 [[DOM树]] 讲过，每个节点就是这样一个对象，有属性可读、方法可调。但它**还没有父亲**，也就是还不在这棵树里，因此不渲染、不占位、看不见。

挂上去的那一刻才有区别：

```js
document.getElementById("week-list").appendChild(item);   // 现在它在页面上了
```

```js
const item = document.createElement("li");
item.textContent = "Week 3";
document.getElementById("week-list").appendChild(item);
```

树上发生的变化可以直接画出来：

```text
挂之前                          挂之后
<ul id="week-list">            <ul id="week-list">
  <li>Week 1</li>                <li>Week 1</li>
  <li>Week 2</li>                <li>Week 2</li>
</ul>                             <li>Week 3</li>   ← 新增
                                </ul>
```

> [!warning] 新元素在挂上去之前是不可见的
> 忘了 `appendChild`，页面毫无反应，而控制台也不会报错——节点对象确实建好了、属性也确实设上了，它只是不在树上。这属于和 `null` 同一类的问题：**代码全部执行成功，效果却没出来**。写法上一律「先 `querySelector` 拿到节点 → 检查不是 `null` → 再改属性」，见 [[修改元素]]。

## 三、增：挂上去

`appendChild(node)` 把节点挂到 `parent` 的**末尾**。

```js
const list = document.querySelector("#week-list");
if (list) {
  const item = document.createElement("li");
  item.textContent = "Week 3";
  list.appendChild(item);
}
```

这个顺序——**先选父、再造子、最后挂**——是新增元素的固定三步：

| 步骤 | 用什么 | 为什么不能颠倒 |
|---|---|---|
| 1. 拿到要挂进去的父节点 | `querySelector` / `getElementById` | 父节点必须在树上，才谈得上"挂进去" |
| 2. 造出新节点 | `document.createElement("li")` | 只造出来还不够 |
| 3. 挂上去 | `parent.appendChild(node)` | 这一行才让它出现在页面上 |

`createElement` 的参数是**不带尖括号的标签名**：`document.createElement("li")`，不是 `"<li>"`。

## 四、删：两种写法

| 写法 | 视角 | 代码 |
|---|---|---|
| `parent.removeChild(node)` | **站在父亲上**，说"把你这个孩子拿掉" | `list.removeChild(item)` |
| `node.remove()` | **站在孩子自己身上**，说"把我拿掉" | `item.remove()` |

```js
const list = document.querySelector("#week-list");

// 路 1：从父亲那边删 —— 必须知道 item 是 list 的孩子
list.removeChild(item);

// 路 2：从孩子自己那边删 —— 只需要拿到 item 自己
item.remove();
```

路 2 更少事：它不用你先证明"这个节点确实是 list 的孩子"，只要节点本身在手就能删。所以课件把 `node.remove()` 单列成一条方法。两者效果相同：节点从树上摘下来，页面上就没有了。

> 节点被删掉之后，它就回内存了。此时再对它做 DOM 属性赋值不会有任何页面效果——和上面「内存 vs 页面」一节里刚造出来还没挂的情形完全一样。

## 五、换：`replaceChild`

`parent.replaceChild(new, old)` 用 `new` 顶掉 `old` 原来的位置，`old` 被摘下来：

```js
const list  = document.querySelector("#week-list");
const first = list.firstElementChild;      // "Week 1" 那个 <li>

const item = document.createElement("li");
item.textContent = "Week 1 · Overview";
list.replaceChild(item, first);
```

树上只多了一个节点、少了一个节点，**位置不变**——`replaceChild` 换的是"那个位置上是谁"，不是"有几个"。它和"先 `appendChild` 再 `removeChild`"的结果在页面上一样，区别是 `replaceChild` 一次完成，中间状态不会出现。

## 六、`demo` 元素

`demo` 指「示例站」`main` 区域里的 `<div id="demo"></div>`——课堂演示的结果输出框（设定见 [[课程场景与阅读约定]]）。往它里面追加内容，就是这一页全部成员最直接的用武之地：

```js
const demo = document.querySelector("#demo");
if (demo) {
  const p = document.createElement("p");
  p.textContent = "New paragraph";
  demo.appendChild(p);          // 现在页面上能看到它了

  demo.replaceChild(p, demo.firstElementChild);   // 换掉第一个子节点
  p.remove();                                    // 把它摘掉
}
```
