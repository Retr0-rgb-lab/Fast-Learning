# 事件基础 · What Is an Event?

> **一句话**：**某件事发生了**，浏览器把这个事实连同一个**事件对象（event object）**交给你的代码，由你决定做什么；事件还会**从被点中的元素一路向上冒泡给它的祖先**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇对应 §8 *Events* 的节封面（"An event is something that happens to the page / A handler is the code that answers it / Attributes for one-offs, addEventListener for real pages"）与 "What Is an Event?" 一页。

## 一、事件的三个要素

| 要素 | 课件的说法 | 含义 |
|---|---|---|
| 某件事发生 | Something happens | 一次点击、一次按键、页面加载完、一次表单提交 |
| 浏览器告诉你的代码 | The browser tells your code | 它递过来一个**事件对象（event object）**，描述发生了什么 |
| 你决定做什么 | You decide what to do | 改页面、校验输入、发请求 |

课件第一节的原话串起来是这样：**An event is something that happens to the page — A handler is the code that answers it**（事件是页面上发生的一件事，处理器（handler）是回应它的代码）。

三者的分工是固定的：

```text
某件事发生  →  浏览器递给你一个事件对象  →  你的 handler 决定做什么
（点击）        （event，描述发生了什么）      （改页面 / 校验 / 发请求）
```

**事件对象**是关键：它不是让你去猜发生了什么，而是把事实作为数据交给你。事件对象上有什么、能读到哪些字段，见 [[事件监听器]]。

## 二、两种监听方式

课件第四句：**Two ways to listen — An attribute in the tag, or `addEventListener` from a script**（两种听法：在标签里写属性，或者在脚本里用 `addEventListener`）。

```html
<!-- 路 1：属性写在标签里 -->
<button onclick="myFunction()">Call a function</button>
```

```js
// 路 2：脚本里挂监听器
button.addEventListener("click", myFunction);
```

课件的节封面给了取舍的判断：**Attributes for one-offs, addEventListener for real pages**（一次性的小事用属性，正式页面用 `addEventListener`）。两种写法的完整对照和各自局限在 [[事件处理与常见事件]]，`addEventListener` 的细节在 [[事件监听器]]。

## 三、事件会冒泡

课件第五句：**Events bubble — From the element that was hit upwards to its ancestors**（事件冒泡：从被击中的那个元素，向上传给它的祖先）。

用「示例站」的一段结构来看。页面骨架里的 `header` 里有一个 `h1`：

```html
<header id="site-header">
  <h1>COMP3421</h1>
</header>
<main>
  <div id="demo"></div>
</main>
```

用户点在 `h1` 上（`<h1>` 文字被选中）时，事件走的方向是：

```text
用户点在 h1
   ↓
① h1            ← 被击中的元素，事件从这里开始
   ↓ 冒泡
② header#site-header   ← 祖先
   ↓ 冒泡
③ body → html → document   ← 一路到根
```

因为 `h1` 是 `header` 的子节点、`header` 是 `body` 的子节点（这正是 [[DOM树]] 里的父子关系），所以祖先们都会收到这个事件。

| 方向 | 名称 | 说明 |
|---|---|---|
| 被击中的元素 | target（目标） | 事件真正发生的地方 |
| 向上到祖先 | bubble（冒泡） | 每一层父节点依次收到同一个事件 |

冒泡的直接后果是**祖先可以替孩子做决定**：只要在 `header` 上挂一个监听器，`h1`、`a`、`button` 被点到时它都会跑——这正是 [[事件监听器]] 里"事件委托"能成立的原因，也是"给列表做逐行响应"不用给每一行都挂一个监听器的原因。

## 四、一个完整的小例子

按本库统一写法（「先 `querySelector` 拿到节点 → 检查不是 `null` → 再改属性」，见 [[修改元素]]），在「示例站」的 `#demo` 上挂一个监听器：

```js
const demo = document.querySelector("#demo");
if (demo) {
  demo.addEventListener("click", () => {
    demo.textContent = "demo was clicked";
  });
}
```

浏览器检测到 `demo` 上的点击 → 递过来一个事件对象 → 箭头函数（handler）读到它 → 改 `demo` 的文本 → 页面立刻更新（因为 DOM 是活的）。

如果把监听器挂在 `header` 上（祖先），那么点 `h1` 也会触发它：

```js
const header = document.querySelector("#site-header");
if (header) {
  header.addEventListener("click", () => {
    console.log("clicked somewhere in the header");
  });
}
```

`demo` 指「示例站」`main` 区域里的 `<div id="demo"></div>`，课堂演示的结果输出框，设定见 [[课程场景与阅读约定]]。
