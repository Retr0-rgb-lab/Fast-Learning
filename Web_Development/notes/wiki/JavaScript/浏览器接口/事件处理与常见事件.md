# 事件处理与常见事件 · Event Handlers & Common Events

> **一句话**：写 handler 有三种形式，越往后越像正常的代码，但**属性形式（`element.onclick =`）会顶掉原有的、而且一个事件只能挂一个**；真要挂多个，就得换 [[事件监听器]] 里的 `addEventListener`。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇对应 §8 *Events* 里的 "Event Handlers" 与 "Common Events" 两页。

## 一、三种 handler 形式与各自的代价

| 形式 | 代码 | 课件的评价 |
|---|---|---|
| 内联属性 | `onclick="…"` | 写在标签里，**quick but it mixes behaviour into markup** —— 快，但把行为混进了标记 |
| 属性里调函数 | `onclick="myFunction()"` | **keeps the code where code belongs** —— 代码留在代码该在的地方 |
| 脚本里赋值 | `element.onclick = handler` | **but it replaces whatever was there** —— 但它会**顶掉原有的那个** |

课件把第三种形式的局限单独点明：**One handler per event. `addEventListener` is the answer when you need more**（一个事件只能有一个 handler；需要更多时，答案是 `addEventListener`）。

### 课件的两个例子

```html
<button onclick="document.getElementById('demo').innerHTML = Date()">
  What time is it?
</button>
<button onclick="myFunction()">
  Call a function
</button>
```

第一个把整段代码直接塞进属性里——能跑，但代码埋在了 HTML 里。第二个只留一个函数名，真正的代码写在别处（JS 文件里）。**属性形式永远应该写成 `onclick="myFunction()"` 而不是 `onclick="…一整段…"`，这是同一个形式内部的正确用法与偷懒用法的区别。**

> [!warning] 属性形式是「替换」而不是「叠加」
> `element.onclick = handler` 给的是**这个事件在这一行上的当前值**——再赋一次，第一个就被顶掉了：
>
> ```js
> const btn = document.querySelector("#save");
> btn.onclick = saveDraft;    // 第一次赋值
> btn.onclick = showDialog;   // 顶掉了 saveDraft
> ```
>
> 需要同时挂多个时，`addEventListener` 才是答案——它**会叠加**，见 [[事件监听器]]。

## 二、常见事件表

| Event | Fires when | Typical use |
|---|---|---|
| `onclick` | the user clicks | buttons, links |
| `onchange` | a field changes and **loses focus** | validation |
| `oninput` | a field changes **as you type** | live search |
| `onkeydown` | a key goes down | shortcuts, games |
| `onmouseover` | the pointer enters | hover effects, tooltips |
| `onsubmit` | a form is submitted | validate before sending |
| `onload` | the page and its resources finish | start-up code |

课件在表下面说：**The full list is long; these seven cover most page code you will write**（完整清单很长；这七个覆盖了你写的绝大多数页面代码）。

## 三、`onchange` 与 `oninput`：本表最该分清的一行

两者的**触发时机**不同，这是这一页最值得记的区分：

| | `onchange` | `oninput` |
|---|---|---|
| 触发时机 | 字段的值变了**并且失去焦点** | 值一变就触发，**边打边触发** |
| 打五个字会触发几次 | 一次（离开字段时） | 五次 |
| 典型用途 | validation（校验） | live search（实时搜索） |

```js
// onchange：改完并且离开这个字段才跑
field.addEventListener("change", () => {
  console.log("最终值：" + field.value);
});

// oninput：每敲一个键都跑
field.addEventListener("input", () => {
  console.log("当前值：" + field.value);
});
```

选哪一个取决于**你要的是"最终确认的值"还是"过程中的值"**：

- 校验"邮箱格式对不对"——用 `onchange`，用户打了一半的时候判断没意义。
- 输入框上方实时显示筛选结果——用 `oninput`，用户还在打就已经在更新。

## 四、课件七行之外不展开的部分

课件明确说完整清单很长，上面这七行之外它没有逐项展开——本篇不代为补写其余事件成员。表里两个值得回头看的用法：

| 用法 | 为什么 |
|---|---|
| `onmouseover` → hover effects, tooltips | 和 [[伪类与伪元素]] 里的 `:hover` 是同一件事的两种做法：CSS 伪类不需要 JS，而 `onmouseover` 能在鼠标移入时执行任意代码（比如延迟显示 tooltip） |
| `onsubmit` → validate before sending | 表单本身有浏览器**免 JS** 的原生校验（见 [[表单验证与可访问性]]），`onsubmit` 是在这之上再加一层脚本校验 |

`onkeydown` 的 `key` 取值、`onmouseover` 的坐标、事件对象的字段，属于"handler 收到了什么"，在 [[事件监听器]] 里讲。

## 五、一个完整例子

按本库统一写法（「先 `querySelector` 拿到节点 → 检查不是 `null` → 再改属性」，见 [[修改元素]]）：

```js
const demo = document.querySelector("#demo");
const btn  = document.querySelector("#save");
const field = document.querySelector("#name");

if (demo && btn && field) {
  btn.onclick = () => {
    demo.textContent = "saved at " + Date();
  };

  field.addEventListener("change", () => {
    demo.textContent = "name is now " + field.value;
  });
}
```

`demo` 指「示例站」`main` 区域里的 `<div id="demo"></div>`，课堂演示的结果输出框，设定见 [[课程场景与阅读约定]]。
