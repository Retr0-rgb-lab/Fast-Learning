# 事件监听器 · Event Listeners

> **一句话**：`addEventListener` 是现代的通用做法，它和 `element.onclick =` 最大的区别是**会叠加不会替换**；摘掉监听器必须传**同一个函数引用**，而列表类界面应该把监听器**委托给父元素**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇对应 §8 *Events* 里的 "Event Listeners" 一页。

## 一、五条课件要点

| 要点 | 展开 |
|---|---|
| `element.addEventListener("click", handler)` | 现代的、通用的做法 |
| **Handlers stack** | 加第二个监听器**不会顶掉**第一个 |
| `removeEventListener` | 要**传同一个函数引用**才能把监听器摘掉 |
| **The handler receives the event** | `event.target` 是**被击中的那个元素**；`key`、`clientX` 和字段的文本都跟着来 |
| **Delegate for lists** | 父元素上挂一个就覆盖所有孩子，**包括后来才加的孩子** |

## 二、会叠加，不会替换

```js
const btn = document.querySelector("#save");
btn.addEventListener("click", handler);
```

课件这一页的例子就叫 **One element, many listeners**（一个元素，很多监听器）。

对比 [[事件处理与常见事件]] 里的属性形式：

```js
btn.onclick = handler;     // 属性形式：再赋值一次，顶掉上一个
btn.addEventListener("click", handler);   // 监听器：再挂一个，两个都跑
```

| | `element.onclick = handler` | `element.addEventListener("click", handler)` |
|---|---|---|
| 挂第二个会怎样 | **替换**掉第一个 | **两个都跑** |
| 能挂几个 | 一个事件一个 | 同一个事件可以挂很多个 |
| 能接收事件对象 | 能，但容易漏掉参数 | handler 第一个参数就是它 |
| 能不能摘掉 | 赋 `null` | `removeEventListener` |

## 三、摘掉要传同一个引用

课件第三句：**Pass the same function reference to detach a listener again**。

```js
const handler = () => { console.log("clicked"); };

btn.addEventListener("click", handler);
btn.removeEventListener("click", handler);   // ✅ 摘掉了
```

为什么强调"同一个引用"？因为 `removeEventListener` 是靠**函数本身**来认出"要摘哪一个监听器"的。如果你挂的时候传的是 `() => {...}`（一个当场建出来的匿名函数），摘的时候再写一个 `() => {...}`——两段代码长得一样，但它们是**两个不同的函数对象**，浏览器认不出来，摘不掉。

```js
btn.addEventListener("click", () => { /* A */ });
btn.removeEventListener("click", () => { /* 看着一样，其实是 B */ });   // ❌ 摘不掉

const h = () => { /* A */ };
btn.addEventListener("click", h);
btn.removeEventListener("click", h);          // ✅
```

> [!warning] `removeEventListener` 需要同一个函数引用
> 匿名函数挂上去之后就"没有名字"了，摘的时候无法再指向它。挂监听器时把 handler 存进一个变量，这是让监听器可以被摘掉的唯一办法。
>
> 这和 [[定时器与Cookie]] 里 "always keep the handle it returns" 是同一类问题：**开始之前先把回头要用的那个凭证存起来**。

## 四、handler 收到了什么

课件第四句：**`event.target` is the element that was hit; `key`, `clientX` and the field's text come along**。

handler 的第一个参数就是**事件对象**（event object，见 [[事件基础]]）。它带着这些事实：

| 拿到的 | 是什么 |
|---|---|
| `event.target` | **被击中的那个元素**——注意不是绑监听器的那个元素 |
| `key` | 这次按键的键（键盘事件时） |
| `clientX` | 指针在视口中的横坐标 |
| 字段的文本 | 事件发生所在字段当前的文本 |

```js
document.addEventListener("click", (event) => {
  console.log(event.target);          // 实际被点到的那一个元素
  console.log(event.clientX);         // 点击位置
});
```

`event.target` 与绑监听器的元素**可以不是同一个**。演示办法就是事件委托（下一节）：监听器绑在 `ul` 上，点到的是里面的 `li`，两者差了好几层。

## 五、事件委托

课件最后一句：**One listener on the parent covers every child — including children added later**。

```js
const list = document.querySelector("#week-list");
if (list) {
  list.addEventListener("click", (event) => {
    console.log("点到的是：" + event.target.textContent);
  });
}
```

这段代码只有一个监听器，但列表里**每一个孩子被点都会触发它**——因为事件会从被击中的元素向上冒泡（[[事件基础]]）。于是"用户点的是哪一条"这个问题，就由 `event.target` 来回答。

**including children added later** 是这一条真正值钱的地方：

```js
list.addEventListener("click", onPick);       // 只挂一次

// 后来又加了一条 —— 不需要再为它挂监听器
const item = document.createElement("li");
item.textContent = "Week 7";
list.appendChild(item);                       // （增删方法见 增删元素）

// 点 "Week 7"，onPick 照样跑
```

对照逐个挂的写法：

| | 每条挂一个 | 委托给父元素 |
|---|---|---|
| 挂几次 | 列表有多长挂多久，**加一条就再挂一次** | **只挂一次** |
| 后来加的孩子 | 忘了挂就不响应 | **自动响应** |
| 想知道点了哪条 | 每个 handler 里自己知道 | 看 `event.target` |
| 适合 | 孩子固定、并且每个要不同逻辑 | 列表、动态内容 |

"后来加的孩子自动响应"这件事成立的前提是**事件冒泡**；而"点的是哪一条"由 **`event.target`** 回答。这两点是委托能用的全部理由。

## 六、一个完整例子

按本库统一写法（「先 `querySelector` 拿到节点 → 检查不是 `null` → 再改属性」，见 [[修改元素]]）：

```js
const demo = document.querySelector("#demo");
const list = document.querySelector("#week-list");

if (demo && list) {
  const onPick = (event) => {
    demo.textContent = "你点了：" + event.target.textContent;
  };

  list.addEventListener("click", onPick);

  // 一秒钟之后撤掉这个监听器
  setTimeout(() => {
    list.removeEventListener("click", onPick);   // 传的是同一个引用
  }, 1000);
}
```

`demo` 指「示例站」`main` 区域里的 `<div id="demo"></div>`，课堂演示的结果输出框，设定见 [[课程场景与阅读约定]]。上面那个 `setTimeout` 的行为见 [[定时器与Cookie]]。
