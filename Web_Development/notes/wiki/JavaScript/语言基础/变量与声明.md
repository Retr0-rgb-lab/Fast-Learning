# 变量与声明 · Literals and Variables

> **一句话**：**优先 `const`，必须会变才用 `let`，`var` 只留给不得不看的旧代码**——因为 `var` 看不见块边界，会从 `{ }` 里漏出去，而 `let` / `const` 不会。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。§2 *Syntax* 的 "Literals and Variables" 与 "let, const and Block Scope" 两页。

## 一、字面量与变量

| 概念 | 含义 |
|---|---|
| **字面量**（literal） | **直接写在代码里**的值，程序跑到那儿它就是那个值 |
| **变量**（variable） | 一个**有名字的容器**，你把什么东西放进去，它就装着什么 |

**`=` 是赋值（assign），不是比较**——等号的意思是"把右边的东西放进左边的变量"。这一点和比较运算符正好相反，后者见 [[比较与typeof]]。

课件的三条：

- **声明了但没赋值 → 变量存在，值是 `undefined`**
- **在声明处直接赋值**，一行做完两件事，这是通常的写法

```js
var x;             // undefined
x = 6;
var carName = "Volvo";
x = x + 5;         // 11
```

`var x;` 那一行不是废话：它**先让名字存在**。少了它，后面单独写 `x = 6;` 是在创建一个你没打算创建的全局变量——这个坑在 [[作用域与严格模式]] 里展开。

## 二、三个声明关键字

`var` / `let` / `const` 都是关键字（见 [[语句与标识符]]），区别集中在**作用域**、**能不能重复**、**能不能重新赋值**三件事：

| | `var` | `let` | `const` |
|---|---|---|---|
| **作用域** | **函数级（function scope）** | **块级（block scope）** `{ }` | **块级（block scope）** `{ }` |
| 能否重复声明 | 同作用域内可以重复 | **不能**——`let x = 1; let x = 2;` 是 SyntaxError | **不能** |
| 能否重新赋值 | 能 | 能 | **不能**——绑一次就定死 |
| 声明前读取 | 会拿到 `undefined` | **报错**，不是 `undefined` | **报错** |
| 课件的定位 | 留给不得不看的旧代码 | 确实要变的值 | **首选**——不变的东西用它 |

### 块作用域

课件用一行代码讲完了这件事：

```js
{ let x = 2; }   // x does not exist here
```

花括号外面，`x` **根本不存在**。而 `var` 不一样：

> **var ignores blocks** — A `var` declared inside a block leaks out to the whole function — the classic bug this fixed.
> （`var` 无视块——在块里声明的 `var` 会漏到整个函数里去，这正是块作用域被引入要修的那个经典 bug。）

> [!warning] `var` 会从块里漏出去
> ```js
> if (true) {
>   var leaked = "I escaped";
> }
> console.log(leaked);   // "I escaped" —— var 越过了 { } 的边界
> ```
> `if` 明明只执行了一次，`leaked` 却活到了函数结束处。换成 `let leaked`，出了 `}` 就被回收，读它直接 ReferenceError。**块的边界对 `var` 根本不起作用。**

### `const` 绑一次就定死

`const` 不能被**重新赋值**——它适合那些"必须永远不变"的东西：常量名（对应 [[语句与标识符]] 里的 `UPPER_CASE` 约定）、函数声明、一旦确定就不再改的配置。

## 三、课件的推荐顺序

课件的措辞是 **Prefer const, then let**——先考虑 `const`，确实要变才降到 `let`，**`var` 只留给必须维护的旧代码**（*Leave var to the legacy code you have to read*）。

这个顺序背后的理由就是上面那张表：`const` 和 `let` **把"这个值会不会变"这件事写在了代码里**，而 `var` 什么都不说、也拦不住你。同一份变量在两种写法下，改起来要动的地方完全不同——这就是为什么课件的总结页把 `const` 和 `===` 并列称为"让这门动态类型语言保持可预测"的两样东西。

## 四、这份表里没写的：值的类型

上面三行讲的都是**变量本身**（名字能不能重复、值能不能换），没讲**装进去的是什么**。装进去的东西有哪几种、装进去之后还能不能改，是 [[类型系统]] 和 [[原始值与引用值]] 的内容：

- 同一个变量可以先装数字、后装字符串——**类型属于数据，不属于变量**
- 装进去的如果是数组或对象，**换变量里的名字不影响那个值本身**，两个名字会指向同一个东西
