# 类型系统 · Data Types

> **一句话**：JavaScript 是**动态类型**语言——同一个变量现在装数字、待会儿装字符串都合法，因为"种类（kind）属于数据本身"，不属于你声明的那个变量；想问一个值是什么类型，唯一办法是 `typeof`。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §3 Data Types 的开头两页：JavaScript 的动态类型立场、值携带自己的种类、`typeof` 能给出的八种回答，以及 `object` 这个回答同时覆盖普通对象、数组和 `null` 这件事。

## 一、动态类型是什么意思

其他语言里，声明一个变量往往就等于声明了它的类型：`int age = 20;` 里 `age` 从头到尾只能是整数。JavaScript 不这样：

| 写法 | 换成别的类型 | 合法吗 |
|---|---|---|
| `let n = 42;` | `n = "forty two";` | 合法 |
| `let n = 42;` | `n = true;` | 合法 |
| `let n = 42;` | `n = ["BMW"];` | 合法 |

课件的原话是：**the data carries its own kind**——种类是跟着数据走的。变量名只是一个可以随时改指向的标签，标签本身没有类型。

这带来一个直接的工程后果：**声明变量的那一行保证不了任何东西**。`let n = 42;` 之后第 20 行，`n` 完全可能已经变成字符串了，因为中间某处有人重新赋值过。所以不要"看一眼声明就推断后面所有用法"。

## 二、`typeof` 是唯一的提问方式

想确认一个值是什么，只能在运行的时候问它：

```js
typeof 42        // "number"
```

注意返回的是**一个字符串**，不是类型名本身。这一点很关键：后面拿它做判断时比的是字符串。

`typeof` 一共能给出八种回答：

| `typeof` 的回答 | 对应的数据 | 说明 |
|---|---|---|
| `"undefined"` | 声明了但从未赋值的变量 | 引擎的"还没有东西" |
| `"object"` | 普通对象、数组、**以及 `null`** | 三者给的是**同一个**回答 |
| `"boolean"` | `true` / `false` | 任何一次比较的结果都是它 |
| `"number"` | 整数和小数**共用**的一种 | 只有一个数字类型 |
| `"string"` | 引号包起来的文本 | 单引号、双引号都算 |
| `"function"` | 函数 | 数组、函数、普通对象都属于"对象"这一侧 |
| `"symbol"` | 唯一标识 | 现代引擎补上的类型 |
| `"bigint"` | 任意精度整数 | 现代引擎补上的类型 |

课件的类型总表重点讲了前五个的语义；`"function"`、`"symbol"`、`"bigint"` 三项是在讲原始值那一页顺带交代的（见 [[原始值与引用值]]）。**真正需要背下来的是 `typeof` 那一列**，因为写代码时你拿到的就是这个字符串。

## 三、`"object"` 这个回答有多宽

这是这张表里最容易踩的地方。`typeof` 只有八个出口，其中一个出口要同时接住三类完全不同的东西：

```js
const plain = { firstName: "John" };   // 普通对象
const list  = ["Saab", "Volvo"];      // 数组
const gone  = null;                   // 空

typeof plain   // "object"
typeof list    // "object"
typeof gone    // "object"
```

普通对象是一堆键值对、数组是一串有序的值、`null` 是"我故意不给值"——三者在语言里是三种东西，却在 `typeof` 这一个出口上撞成了同一个字符串。**所以 `typeof` 能告诉你"这是一个对象"，不能告诉你"这是哪种对象"。** 想分清数组和普通对象，得用别的办法（见 [[数组与空值]]）。

## 四、怎么把结果写到页面上

JavaScript 的输出在这个知识库里统一写进示例站 `main` 区域的 `demo` 输出框。按"先拿到节点 → 检查它不是 `null` → 再改属性"的顺序写：

```js
let n = 42;
n = "forty two";                 // 动态类型：换成字符串，完全合法

const demo = document.getElementById("demo");
if (demo) {                      // 没拿到节点就什么都不做，而不是让页面报错
  demo.innerHTML = typeof n;     // 写出 "string"
}
```

这一次 `typeof` 回答 `"string"`，因为赋值那一刻 `n` 里装的是字符串——**问的是当前的数据，不是声明时的意图**。

> [!warning] `typeof` 查不到变量名，浏览器才替你"报 undefined"
> `typeof someName`（连 `someName` 都没声明）不会报错，它返回 `"undefined"`。这在"检查一个可能没定义的东西"时很好用，但在别处会**掩盖拼写错误**——变量名打错一个字母，代码会安静地走进 `undefined` 分支，而不是大声失败。所以 `typeof` 用在**值**上，别用它来确认变量名拼对了。
