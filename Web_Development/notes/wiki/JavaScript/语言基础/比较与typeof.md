# 比较与typeof · Comparison Operators and typeof

> **一句话**：**新代码一律用 `===` 和 `!==`**——`==` 会先把两边转成同一种类型再比，`"5" == 5` 因此是 `true`；而 `typeof` 是你反过来问引擎"这是什么"的工具，返回的是一个**字符串**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。§2 *Syntax* 的 "Comparison Operators" 与 "The typeof Operator" 两页。

## 一、八个比较运算符

下表按课件的写法，设 `x = 5`：

| 运算符 | 含义 | 例子（`x = 5`） | 结果 |
|---|---|---|---|
| `==` | 相等，**先转换再比** | `x == "5"` | `true` |
| `===` | **值和类型都相等** | `x === "5"` | `false` |
| `!=` | 不相等（值） | `x != 8` | `true` |
| `!==` | 值或类型不相等 | `x !== "5"` | `true` |
| `>` | 大于 | `x > 8` | `false` |
| `<` | 小于 | `x < 8` | `true` |
| `<=` | 小于等于 | `x <= 8` | `true` |
| `>=` | 大于等于 | `x >= 5` | `true` |

`<` `>` `<=` `>=` 这四个是**大小比较**，两侧都得是数字才有意义（字符串比大小按字符编码排，本课不展开）。前四个是**相等比较**，分两套。

## 二、`==` 与 `===`

| | `==` 松散相等（loose） | `===` 严格相等（strict） |
|---|---|---|
| 比较什么 | **先转换类型，再比值** | **类型和值都一致才算相等** |
| `x = 5` 时 `"5" == 5` | **`true`** | |
| `x = 5` 时 `x === "5"` | | **`false`** |
| 课件的处置 | 不推荐 | **新代码永远用这个** |

课件这一页底部的原话是：*`==` converts before it compares; `===` does not. In new code, always reach for `===`.*

> [!warning] `"5" == 5` 是 `true`，不是 `false`
> 这不是 bug，是 `==` 的设计：它会**把字符串转成数字**再比，所以两边"看起来相等"就判相等。危险之处在于**它悄悄替你做了决定**：
> ```js
> "5" == 5      // true   —— 松散相等转换了类型
> "5" === 5     // false  —— 严格相等看类型
> 0 == ""       // true   —— 同样的一类意外
> 0 == false    // true
> ```
> 这些 `true` 都不是 bug，但**都不是你读代码时预期的那件事**。想判断"从输入框来的 5 和我存的 5 是不是同一个数"，唯一可靠的办法是**两边都转成数字再比**：
> ```js
> Number(input) === 5
> ```
> 取值本身的规则见 [[类型系统]]。

同类还有一条：**`=` 写在条件里是 bug**。`=` 是赋值、`==` 是比较、`===` 是严格比较，三者不能混。

## 三、`typeof`：反过来问引擎

**`typeof` 返回类型名，而且是一个小写字符串。** 它可以作用于任何东西——字面量、变量、一整个表达式：

```js
typeof ""         // "string"
typeof "John"     // "string"
typeof 3.14       // "number"
typeof true       // "boolean"
typeof undefined  // "undefined"
typeof null       // "object"  (a quirk)
typeof [1, 2, 3]  // "object"
```

**只有一种数值类型**——整数和小数都回答 `"number"`。字符串可以用单引号或双引号，**两种都行**（细节见 [[字符串与数字]]）。

它返回的**八个字符串**是这门语言的类型问询答案：

| 返回值 | 什么时候出现 |
|---|---|
| `"undefined"` | 声明了但没赋值 |
| `"object"` | 普通对象、数组、**以及 `null`** |
| `"boolean"` | `true` / `false` |
| `"number"` | 整数和小数共用这一个 |
| `"string"` | 文本 |
| `"function"` | 函数 |
| `"symbol"` | 现代引擎的符号 |
| `"bigint"` | 现代引擎的大整数 |

> [!note] `typeof` 的**结果**是字符串，不是类型本身
> ```js
> typeof typeof 42     // "string"
> ```
> 内层返回的是字符串 `"number"`，外层再问一次，返回的就是 `"string"`。这是这门语言少见的"类型名也是一个值"的地方——`typeof` 是**唯一**一个把类型当字符串返回的运算符。

> [!warning] 两个著名的例外：数组和 `null` 都回答 `"object"`
> ```js
> typeof [1, 2, 3]   // "object"  —— 数组不是一种独立类型
> typeof null        // "object"  —— 这个是历史遗留
> ```
> 课件对数组的处置是：**要判断数组，用 `Array.isArray()`**，不要用 `typeof`。`Array.isArray()` 在 [[数组与空值]] 里展开。
>
> `typeof null === "object"` 是**语言第一版留下的遗留物，为了兼容被保留了下来**——最初版本的实现里 `null` 是一张"空对象"的表示，改不动了，于是就一直留着。**这一条值得单独记住**：它意味着 `typeof` **不能用来判断"这是不是一个对象"**。
>
> `undefined`、`""`、`null` 是三个不同的东西，区别见 [[数组与空值]] 与 [[类型系统]]。

## 四、这两个工具的分工

| 想知道 | 用什么 |
|---|---|
| 两个值是不是"同一个东西" | `===` / `!==` |
| 这个值是哪种类型 | `typeof`（但数组和 `null` 要另判） |
| 这是不是一个数组 | `Array.isArray()` |
| 这两个变量是不是指同一个对象 | 不是 `==`，见 [[原始值与引用值]] |

**先判断、再动作**——这个顺序和 DOM 里的"先查 `null` 再改属性"是同一种思路：先确认前提成立，再往下走。
