# 四种输出方式 · How JavaScript Shows Output

> **一句话**：四种写法里，**`console.log` 是专业的那一种**——它只有开发者看得见；`alert` 是上课演示用的，`document.write` 不该再用，**用户能看到的正式输出去改元素**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。§1 *Introduction* 的 "How JavaScript Shows Output" 一页。

## 一、四种方式对照

| 方式 | 写法 | 结果出现在哪 | 定位 |
|---|---|---|---|
| **写进元素** | `document.getElementById("demo").innerHTML = ...` | 页面上，用户看得见 | **通常做法** |
| **弹窗** | `window.alert(...)` | 一个对话框 | **只用于演示**——它会**阻塞页面**直到被关掉 |
| **控制台** | `console.log(任何东西)` | 开发者控制台 | **专业选择**——开发者看运行结果的窗口 |
| **写进文档流** | `document.write()` | 页面 | **加载后再用会清掉整个页面**，只用于测试 |

课件的定性原话是：**Choose deliberately**（有意识地选）——**前两种用户看得见，后两种你看得见**。以及一条硬规矩：**Never leave an alert in shipped code**（交付的代码里绝不要留 `alert`）。

## 二、`console.log`：专业的那一种

```js
console.log("debug");   // F12 · Cmd+Option+I 打开控制台
```

控制台是**开发者看运行结果的窗口**。它和 `alert` 的区别不是"哪个更方便"，而是**给谁看**：

| | `console.log` | `alert` |
|---|---|---|
| 谁能看见 | 只有打开开发者工具的开发者 | **每一个用户**，而且无法忽略 |
| 是否阻塞页面 | 否，代码继续往下跑 | **是**，必须点掉才继续 |
| 交付时能否保留 | **可以**，留着有价值 | **不行** |

课件的动手动作是：**打开 DevTools，看控制台**。控制台是这门课后面所有排错动作的现场，元素面板的用法见 [[DOM与开发者工具]]。

> [!warning] 交付代码里的 `alert` 是未完成标志
> 课件把"Never leave an alert in shipped code"单独立成一条规矩。`alert` 只在课堂上用来让人看见结果用；真要让人看见结果，改的是页面上的元素。另一个后果是它**阻塞页面**——用户不点掉，脚本后面所有代码都不执行。

## 三、改元素：正式输出走这条路

```js
document.getElementById("demo")
.innerHTML = "Hello JavaScript";
```

这是课件所有演示例子的落点，也是**面向用户的正式输出**。`demo` 这个元素在本库里的约定是："示例站"（一张假想的课程主页）`main` 区里的 `<div id="demo"></div>`，作为**课堂演示的结果输出框**；课件并没有给它正式设定，是本库为了让例子自洽而设的，正式功能页面上不会用这个 id 名。约定全文见 [[课程场景与阅读约定]]。

真实项目里写这一行，顺序是「**先 `querySelector` 拿到节点 → 检查它不是 `null` → 再改属性**」——因为 `null` 没有属性，赋值会抛错，而**这个错误在发作前一直是沉默的**。完整写法见 [[修改元素]]。

## 四、`document.write`：不要用

`document.write()` 的问题在**时机**：页面**加载完成之后**再调用它，会把已经建好的页面**整个抹掉**，换成你写进去的那段内容。课件因此把它限定为 *testing only*。

想追加内容、想插一段节点，都有更明确的做法（见 [[增删元素]]）；`document.write` 属于浏览器早期文档写入模型的遗留物，本课不采用。

## 五、怎么选

| 你要做的事 | 用哪个 |
|---|---|
| 让用户看到结果 | **改元素**（`innerHTML` / `textContent`） |
| 自己查代码跑到哪了、值是什么 | **`console.log`** |
| 课堂上让人看见一行结果 | `alert`（只在这个场合） |
| — | ~~`document.write`~~ |

`console.log` 和改元素不是二选一：**写正式功能时改元素，调试时加 `console.log`**，两者并存是常态。加按钮让结果随点击变化，属于 [[事件处理与常见事件]] 的范围。
