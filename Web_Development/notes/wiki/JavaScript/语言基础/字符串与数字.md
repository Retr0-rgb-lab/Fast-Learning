# 字符串与数字 · Strings & Numbers

> **一句话**：字符串是引号里的文本、引号两种随便挑但**要一直用同一种**；数字**只有一种**（`34` 和 `34.00` 是同一个数）；`length` 是个**属性**不是函数；而小数是近似值，所以**永远不要用相等去比较小数**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §3 Data Types 中 Strings and Numbers 一页：引号的选择、`length` 的写法、唯一的数字类型，以及浮点近似这条必须记住的规则。

## 一、字符串：两种引号，选一种然后别换

文本要放在引号里。单引号和双引号**效果完全一样**：

```js
var s1 = "John Doe";
var s2 = 'John Doe';   // 和 s1 一模一样
```

两者没有任何语义差别，都表示 8 个字符的文本 `John Doe`。课件的态度很明确：*either works, so pick one and stay consistent*——**随便挑一种，然后整个项目都用它**。

为什么要坚持？因为两种引号各自在一种情况下省事，混着写就会打架：

| 场景 | 写法 | 换一种引号会怎样 |
|---|---|---|
| 文本里要出现另一种引号 | `var s = "It's fine";` | 写成 `'It's fine'` 会提前结束字符串，语法报错 |
| 文本里要出现双引号 | `var s = 'He said "hi"';` | 写成 `"He said "hi""` 同样报错 |

所以规则不是"哪种更好"，而是"**一个项目一种**"。判断标准很简单：如果你经常要写 `it's`，就用双引号；经常要写带引号的英文，就用单引号。

## 二、数字：只有一种

JavaScript 里整数和小数**不是两个类型**，是同一个 `number`。写不写小数点都一样：

```js
var n1 = 34.00;
var n2 = 34;         // 和 n1 是同一个数
```

`n1 === n2` 的结果是 `true`。末尾的 `.00` 只是源码里的写法，不会在内存里留一份"带零的版本"。这也是为什么课件说 one number type。

真实世界里这个类型覆盖的东西比你想的宽：整数、小数、很大的数（超过约 1.8×10³⁰ 之后精度就没了）、`NaN`（不是一个数的结果）、`Infinity`。**没有整数类型、没有长整型、没有双精度/单精度之分**——就一个。

这个"一个数字类型"是**算术**视角。换成**二进制**视角，同一个 `number` 还有另一套算法——`&` `|` `^` `~` 和三个移位运算符，它们不按数值大小算，而是逐位处理二进制的每一位，见 [[位运算符]]。理解"数字就是二进制位"这一点，正是理解浮点数为什么近似的钥匙（下一节）。

## 三、`length` 是属性，不是调用

字符串知道自己有多长，答案在 `length` 上：

```js
var s1 = "John Doe";
s1.length        // 8
```

"John Doe" 8 个字符（空格也算一个），所以答案是 8。

关键在写法：**没有圆括号**。

| 写法 | 结果 | 说明 |
|---|---|---|
| `s1.length` | `8` | ✅ 读一个属性 |
| `s1.length()` | `TypeError` | ❌ 8 不是函数 |
| `s1.size` | `undefined` | 名字不叫 `size` |

`length` 是**存在值身上的数据**，不是"算长度"的动作。这和上一轮学的"调用"是两回事——要拿到一个值，**不写括号**。数组的 `length` 同理（见 [[数组与空值]]）。

## 四、浮点数是近似的

这是本节最需要记住的一条：**JavaScript 的数字是二进制浮点，精度有限，所以小数存的是"最接近的那个近似值"**，不是精确值。

课件点名的是这个例子：

```js
0.1 + 0.2        // 0.30000000000000004
```

它**不**等于 `0.3`。原因是 `0.1` 和 `0.2` 在二进制里都不能被精确表示：

```
十进制 0.1  →  二进制 0.0001100110011…0011   （无限循环，存不下，只能截断）
十进制 0.2  →  二进制 0.0011001100110…0110   （同样循环）
相加        →  0.0100110011001…0010 + 截断误差 = 0.30000000000000004
```

两个"近似值"相加，误差不会抵消——它被带进了结果里。

> [!warning] 永远不要用 `===` / `==` 比较小数
> ```js
> 0.1 + 0.2 === 0.3        // false —— 这是本课最常被坑的一行
> ```
> 比整数可以，比小数不行。哪怕只差 `0.00000000000004` 也不行——**完全相等就是完全相等，没有"差不多"这一档**。
>
> 从这条结论能直接推出的通行做法是**比差值而不是比值**（这是这条规则的常见应用，不是课件给的语法）：
> ```js
> Math.abs(0.1 + 0.2 - 0.3) < 1e-9    // true —— 差得足够小就算相等
> ```
> 凡是页面上会出现"用户输入的数字参与计算"的场合（价格、折扣、坐标、评分求平均），这条都要用上。

## 五、把本节写进示例站

```js
var s1 = "John Doe";
var s2 = 'John Doe';   // 与 s1 完全相同

var n1 = 34.00;
var n2 = 34;           // 同一个数

const demo = document.getElementById("demo");
if (demo) {
  demo.innerHTML =
    "same string: " + (s1 === s2) + "<br>" +   // same string: true
    "same number: " + (n1 === n2) + "<br>" +   // same number: true
    "length: " + s1.length + "<br>" +          // length: 8
    "0.1+0.2: " + (0.1 + 0.2);                 // 0.1+0.2: 0.30000000000000004
}
```
