# 原始值与引用值 · Primitives vs References

> **一句话**：原始值（primitive）是"一个东西"、**不可变**、赋值时**复制**；对象（数组、函数、普通对象）是引用值、**可变**、赋值时**共享同一个东西**——所以 `let b = a;` 之后两个名字指的是同一个数组。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §3 Data Types 中 Primitive Types 一页：什么是原始值、经典五种与现代新增两种、不可变性的后果，以及"原始值复制、对象共享"这条规则。

## 一、原始值 vs 引用值

JavaScript 的值分两大阵营。判断方法很简单：**这个值自己身上有没有属性和方法**。

| | 原始值（primitive） | 引用值（reference） |
|---|---|---|
| 是什么 | **一个单独的东西** | 装着东西的容器 |
| 自身有属性/方法吗 | **没有**——只有数据 | 有：数组有 `length`、`push`，函数有 `name`、`call` |
| 典型成员 | `string` `number` `boolean` `undefined` `null`（外加 `symbol` `bigint`） | 数组、函数、普通对象 |
| 能不能改内容 | **不能** | 能 |
| 赋值时发生什么 | **复制一份** | **再贴一个标签，指向同一个东西** |

课件的划分原话是：原始值是 *a single thing*，*no properties and no methods of its own*；其余的一切都是对象，是 *reference values*。

看起来有点怪：字符串明明有 `.length`、`.toUpperCase()` 这些方法，为什么算原始值？因为那些方法是**引擎为它准备的**，不是它自己带的数据——原始值身上确实**没有属于自己的属性**。

### 经典五种 + 现代两种

课件列的经典五种是：`string`、`number`、`boolean`、`undefined`、`null`。现代引擎又补上了两种：`symbol`（唯一标识）和 `bigint`（任意精度整数）。所以 `typeof` 总共给出八个回答，其中六个是原始值，剩下两个（`"object"` 和 `"function"`）归对象那一边（见 [[类型系统]]）。

## 二、不可变：只能换，不能改

> **Primitives are immutable** —— 你可以在变量里**替换**一个原始值，但**永远不能在原地编辑**它。

```js
var n = 34;
n = 40;          // ✅ 合法：换一个值进去

var s = "John";
s[0] = "J";     // ❌ 字符串没有可写的下标
```

"immutable"（不可变）指的是**值本身**一旦造出来就定死了。任何"改动"实际上是造一个新值、让变量指向它：

```js
let s = "John";
s = s.toUpperCase();    // "JOHN" —— 这不是改原来的字符串，是换了个新字符串
```

原来的 `"John"` 还在，它只是没人引用了。**这一点让原始值可以放心地到处传**——传给别人之后对方改不到你手上那份。引用值没有这个保证。

## 三、核心规则：原始值复制，对象共享

这一页的结论行是课件的原话：**Primitives are copied, objects are shared**。

### 原始值：复制

```js
let a = 1;
let b = a;      // 复制了一个 1 给 b
b = 2;          // 改的是 b
// a 仍然是 1 —— 两边彻底无关
```

### 对象：共享

课件给的例子只有两行，但它是全课最容易出错的地方：

```js
let a = [1, 2];
let b = a;      // one array, two names —— 一个数组，两个名字
```

`b = a` **没有复制数组**。它只是给那个数组贴了第二个标签。此刻 `a` 和 `b` 指向**同一个**数组。把它推到底：

```js
let a = [1, 2];
let b = a;

b.push(3);            // 通过 b 往数组里加一项
// a 现在也是 [1, 2, 3] —— 因为它们是同一个数组

a[0] = 99;            // 通过 a 改第一个元素
// b[0] 也是 99 —— 同一个数组

console.log(a === b); // true —— 同一个东西，两个名字
```

**变量名是贴在东西上的便利贴，不是盒子。** 原始值那张便利贴贴的是一份拷贝，对象那张便利贴贴的是原件。

### 什么时候会"分家"

只有**重新赋值**才会分家——重新赋值换的是标签，指向别处，两边就不再是同一个东西：

```js
let a = [1, 2];
let b = a;     // b 和 a 同一条
b = [9, 9];    // 重新赋值：b 拿到一个全新的数组
// a 仍然是 [1, 2] —— 从这里开始分家
```

> [!warning] 别把"共享"和"是同一个变量"搞混
> `a === b` 为 `true`，但 `a` 和 `b` 是**两个变量**。`a` 的类型也不因为 `b` 是数组而变成数组——**每个变量独立跟踪自己当前指向的值的种类**（这就是 [[类型系统]] 里说的"种类属于数据"）。真正共享的是**那个对象**，不是变量。

### 函数也在这边

函数是引用值，所以函数名也只是标签：

```js
function greet() { return "hi"; }
let f = greet;      // 把函数本身赋给 f（不是调用它）
f();                // "hi" —— f 也是一个能调用的名字
```

这个"函数可以当值传"的用法，正是 [[函数即值]] 那一组笔记的主题。

## 四、对比演示

```js
let p = 34;
let q = p;
q = 40;                 // 换 q，p 不动

let a = [1, 2];
let b = a;
b.push(3);              // 同一个数组

const demo = document.getElementById("demo");
if (demo) {
  demo.innerHTML =
    "p is " + p + "<br>" +            // p is 34
    "a is [" + a + "]<br>" +          // a is [1,2,3] —— 被 b 改了
    "b is [" + b + "]<br>" +          // b is [1,2,3]
    "a === b: " + (a === b);          // a === b: true
}
```
