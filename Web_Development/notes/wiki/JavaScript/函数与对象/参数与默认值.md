# 参数与默认值 · Parameters, Arguments and Defaults

> **一句话**：定义里写的是**参数名**、调用时传的是**实参值**，JavaScript 既不声明类型也不检查个数——多传的丢掉、少传的变 `undefined`，默认值是补缺口的工具，而**带默认值的参数只能排在最后**。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §5 Functions 的 Parameters, Arguments and Defaults 一页：参数与实参的分工、不声明类型、不检查个数、默认值的填空时机与摆放位置、以及 `arguments` 为什么被称为 legacy。

## 一、参数是名字，实参是值

课件的第一句就把两个词分开了：**parameters are the names in the definition; arguments are the values you actually pass**。

```js
function myFunction(p1, p2) {   // p1、p2 是参数：这里只有名字
  return p1 * p2;
}

myFunction(4, 3);               // 4、3 是实参：这里才是值
```

名字本身没有任何魔法，`p1` 换成 `firstname`、`secondname` 运行结果完全一样。名字的作用是让人读代码时知道函数体里的这个值将来是谁的。

## 二、不声明类型：调用方决定

**No types are declared** ——定义里永远不写"这是字符串"还是"这是数字"。这个决定权在调用方手里：同一个 `greet` 可以收名字也可以收数字，因为函数体里的 `+` 是拼接（见 [[运算符]] 里"数字相加、字符串相接"那条规则）：

```js
function greet(who = "guest") {
  return "Hello, " + who;
}

greet("Peleclic");   // "Hello, Peleclic"
greet(42);           // "Hello, 42"
```

课件没有在这一页展开不同类型各自的行为，只强调一件事：**定义不替你做类型决定，也不要把类型检查写进函数的职责里**。

> [!warning] 想要"必须传两个参数"的保障？JavaScript 不提供
> ```js
> function myFunction(p1, p2) { … }
> myFunction(4);          // 不报错，p2 是 undefined
> myFunction(4, 3, 99);   // 不报错，99 被丢掉
> ```
> 两种写法在语法上都是合法的。**如果某个参数确实不能少，要么给它默认值，要么在函数体里自己检查并给出提示**——语言层面不替你把关。

## 三、不检查个数：多传丢，少传变 `undefined`

课件用了 "No count check either" 这个说法，并把两种越界都点了出来：

| 情况 | 发生什么 | 例子 |
|---|---|---|
| **实参比参数多** | 多出来的**直接忽略** | `myFunction(4, 3, 99)` → 只用到 `4`、`3` |
| **实参比参数少** | 缺的**到达时是 `undefined`** | `myFunction(4)` → `p2` 是 `undefined` |

课件在这一页给了一个专门演示"少传"的例子：

```js
function f(x, y = 2) { … }

f(3);   //   x = 3, y = 2
```

`y` 写了默认值 `2`，所以少传的那一个不是 `undefined`，而是**被默认值顶上**。

> [!warning] "少传"和"故意传 undefined"在这里是两回事
> ```js
> f(3);        // y 用默认值 2
> f(3, undefined);   // y 也用默认值 2 —— 写了 undefined 等同于没传
> ```
> 这是默认值的判定方式：**没传值时默认值生效**；传进去一个具体的值就用那个值。课件把 undefined 和 null 分得很清楚：前者是引擎的"还没有东西"，后者是你自己设置的一个明确的空（见 [[数组与空值]]）。（`null` 是一个明确的"空"，不是"没给"）。所以想显式跳过中间某个参数又保留后面的默认值，只能靠写 `undefined` 占位。

## 四、默认值用来补缺口，而它必须排最后

默认值解决的是"这个参数不传时用什么"的问题。课件的写法是把缺的值直接写在参数名后面：

```js
function greet(who = "guest") {
  return "Hello, " + who;
}

greet();            // "Hello, guest"
greet("Peleclic");  // "Hello, Peleclic"
```

而 **defaults go last** 这一条是本篇最硬的规则：**A defaulted parameter must come after the plain ones** —— 带默认值的参数必须排在所有普通参数的后面。

| 写法 | 合法吗 | 原因 |
|---|---|---|
| `function f(x, y = 2)` | 合法 | 有默认值的 `y` 在后面 |
| `function f(x = 1, y)` | 不合法 | 后面又出现了普通参数 `y` |

这条规则背后的逻辑是：实参是**从左往右对位**传的（第几个值配第几个参数）。如果默认值夹在中间，调用方想跳过前面的参数去设置后面的，就必须写 `undefined` 占位，规则会变得难以使用——所以语言干脆禁止这种顺序。

> [!warning] 默认值不是"可选项"标记，位置是有约束的
> 看到 `function f(a, b = 2, c)` 这种"中间默认值 + 后面普通参数"的顺序，可以直接判定是写错了。正确的写法只有两种：把带默认值的全部挪到最后，或者给中间那些也补上默认值。

## 五、`arguments`：每个函数都有，但课件说它是 legacy

课件对 `arguments` 的评价只有一句：**arguments is legacy** —— 每个函数里都有这么一个对象（装着这次调用实际传进来的值），但课件紧接着给出了替代方案：**rest parameters `…args` are clearer**。

两种写法的对比：

```js
// legacy：从函数自带的 arguments 里取
function sumArgs() {
  return arguments[0] + arguments[1];
}

// 推荐：声明式地收下不定个数
function sumArgs(...args) {
  return args[0] + args[1];
}
```

区别在于**意图写在代码里还是藏在函数身上**：`...args` 是一个写在参数列表中的名字，读代码的人一眼就知道这个函数要收一串值；`arguments` 则是每个函数都背着的一个隐式对象，想收参数得知道去哪拿。

课件在这一页的态度是"知道它存在、但写新代码用 `...args`"，没有展开 `arguments` 的其他行为。
