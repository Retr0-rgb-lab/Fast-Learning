# 函数表达式与自执行 · Function Expressions and IIFE

> **一句话**：函数是**值**，所以能存进变量、传给别人、还能返回；代价是**函数表达式不会被提前登记**，用到它的那一行必须走在定义行之后 —— 而 `(function(){…})()` 用一对括号把这个函数当场变成表达式、立刻执行，用完就收，不留任何全局名字。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §5 Functions 的 Function Expressions 与 Self-Invoking Functions 两页：函数作为值、函数表达式与声明的差别、提升行为的差异，以及立即执行函数那对括号到底在做什么。

## 一、函数是一个可以拿在手里的东西

课件的标题句是 *A function is a thing you can hold* —— 函数是个**东西**，不只是"一段代码"。这意味着它可以：

- 存进一个变量
- 作为参数传给另一个函数
- 作为返回值被交出去

最直接的写法是**函数表达式**（function expression）：

```js
const multiply = function (a, b) {
  return a * b;
};

let z = multiply(4, 3);   // 12
```

和具名声明写起来几乎一样，区别在两处：

| | 函数声明 | 函数表达式 |
|---|---|---|
| 形状 | `function myFunction() {}` | `function (a, b) {}` |
| 名字 | **自带**一个名字 | 通常**匿名**，靠外面的变量当把手 |
| 怎么用 | 直接用 `myFunction(4, 3)` | 用变量名 `multiply(4, 3)` |

课件原话：*Anonymous is normal — the expression usually has no identifier of its own.* 函数表达式**通常没有自己的名字**。这不是缺陷 —— 它本来就是"造一个函数值，交给左边那个变量"。

## 二、提升行为不一样

这是这一页真正要记的东西。课件的措辞：*Hoisting differs — a declaration is hoisted; **a function expression is not ready before its line**.*

引擎在读到脚本时会先扫一遍，把**函数声明**提前登记好。所以这样能跑：

```js
sayHi();            // 先调用
function sayHi() {  // 后定义
  console.log("hi");
}
```

但换成函数表达式就会炸：

```js
sayHi();            // ✗ ReferenceError
const sayHi = function () {
  console.log("hi");
};
```

`const sayHi` 这一行还没执行到，`sayHi` 这个名字此刻根本不存在，引擎找不到它就报 `ReferenceError`。

> [!warning] 混用这两种写法最容易翻车
> 同一个文件里既有函数声明又有函数表达式时，只有声明享受"提前可用"。
> 看起来只是**写法不同**，实际可用范围差一整段。写的时候保持一致：要么全用声明，要么全用表达式。
>
> 这一页只讲**函数层面**的提升。`let` / `const` 声明的变量同样不会被提前赋值（它们有"暂时性死区"），那条在 [[变量与声明]] 里。

## 三、立即执行函数：`(function(){…})()`

**IIFE**（Immediately Invoked Function Expression）就是"定义完立刻执行一次"的函数：

```js
(function () {
  let x = "Hello!!";
  document.getElementById("demo").innerHTML = x;
})();
```

拆开看这三部分：

| 部分 | 作用 |
|---|---|
| `(function () { … })` | 一个**函数表达式**——注意它没有名字 |
| 紧跟的 `()` | 调用它 |
| 最外层的 `( )` | **关键**：把内部那个函数变成一个表达式 |

### 那对括号不是装饰

课件专门点了一句：***Wrap it in parentheses first — that is what turns a definition into an expression.***

在 JavaScript 里，语句位置读到 `function` 开头，**一律当成函数声明**。而函数声明必须有个名字，匿名函数在这里就是语法错误：

```js
function () { … }()      // ✗ SyntaxError：这是"匿名函数声明"
(function () { … })()    // ✓ 先用括号把它变成表达式，再调用
```

括号的作用就是"跳出语句位置"——让引擎知道接下来不是一条声明，而是一个可以求值、可以调用的表达式。

### 它解决什么问题

课件的落点是 *Everything inside stays inside — a tidy way to keep helper variables off the global scope.*

```js
(function () {
  let x = "Hello!!";        // 只活在这个函数里
  document.getElementById("demo").innerHTML = x;
})();
console.log(x);              // ✗ ReferenceError
```

`x` 不会跑到全局去。页面上有很多互不相干的脚本时，每个脚本都把临时变量塞进 IIFE，就**不会互相踩到对方的名字** —— 这就是所谓避免**全局命名空间污染**。

> [!tip] 现今还该不该用
> 课件是在讲 IIFE 的原理。现代代码里 `let` / `const` 本身就有块作用域，多数情况下用一个 `{ }` 包起来就够了，IIFE 不再是唯一手段。但课件这里讲的**括号如何把语句变成表达式**，以及**函数是值**这两点，是理解 [[函数即值]] 的前提。

## 四、三个写法放一起看

```js
// 声明：自带名字，被提前登记
function f() { return 1; }

// 表达式：匿名，交给变量当把手，不提前
const g = function () { return 2; };

// IIFE：匿名表达式 + 立刻调用，不留名字
(function () { console.log(3); })();
```

三者的**函数体完全一样** —— 里面能写什么、怎么用 `return`，都不变。
变的只是"这个函数值从哪来、叫什么、什么时候执行"。函数是值，所以它可以出现在任何需要值的位置上。
