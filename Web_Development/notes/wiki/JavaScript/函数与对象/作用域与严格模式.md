# 作用域与严格模式 · Scope and Strict Mode

> **一句话**：变量能被谁看到，由它写在哪决定 —— 全局 / 函数 / 块三层；`var` 会**逃出**花括号，`let` 和 `const` 不会；而 `"use strict"` 干的事就是把"我少写了一个 `let`"这种**静默的错误**变成当场报错。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §5 Functions 的 Variable Scope 与 Strict Mode 两页：三种作用域各自的范围、`var` 为什么能逃出块、漏写声明会造成什么，以及严格模式如何把它变成错误。

## 一、三种作用域

| 作用域 | 写在哪 | 活到什么时候 |
|---|---|---|
| **全局** global | 任何函数外面 | 整个页面 |
| **函数** function | 函数体里面（不在任何 `{}` 内）| 这个函数**返回时**就没了 |
| **块** block | 任何 `{ }` 里面（`if`、`for`、`{ }`）| 出这个 `{}` 就没了 |

课件的三句话：*Declared outside every function — visible to the whole page* /
*Declared inside a function — gone when that function returns* /
*`let` and `const` inside `{ }` stay inside; **`var` does not**.*

## 二、`var` 会逃出花括号

这是三种作用域里唯一需要特别记的一条。**块作用域只关得住 `let` 和 `const`，关不住 `var`。**

```js
if (true) {
  var leaked = "I'm out";     // var
  let kept   = "I'm in";      // let
}
console.log(leaked);   // ✅ 打印得出来 —— var 逃出去了
console.log(kept);     // ❌ ReferenceError
```

`{ }` 对 `var` 而言**根本不构成一道门**。课件把原因归给声明方式：见 [[变量与声明]] 里 `var` / `let` / `const` 的对照表。

> [!tip] 于是"什么时候用哪个"有了一条实用规则
> 知道个数就用 `for (let i = 0; …)`；计数器的 `let` 作用域正好是循环体那一对 `{ }`，
> 循环结束 `i` 就没了，不会污染外面。课件在 `for` 那一页也这么说
> （*declare the counter with `let` — it is scoped to the body, which is what you want*）。

## 三、漏写声明 = 悄悄造了个全局

课件点名的错误：*An undeclared assignment is a bug — writing `carName = "Volvo"` with no declaration creates a global by accident.*

```js
carName = "Volvo";    // 忘了写 let / var / const
```

**没有声明**的赋值**不会报错**，引擎就当你在创建一个全局变量。于是它：

- 悄悄跑起来了，**看不出任何问题**
- 污染了全局
- 下一个脚本里同名的东西会被无声地改掉 —— 这种 bug 极难查

课件给的对照例子：

```js
let carName = "Volvo";     // global

function myFunction() {
  let local = "Saab";       // local
  carName = "Fiat";         // 改的是全局那个
}

myFunction();
console.log(local);         // ReferenceError —— 它只活在 myFunction 里
```

> [!warning] 这一行是本篇的核心
> `carName = "Fiat";` 写在函数里、**没有 `let`**，它改的不是局部变量，而是**外面的全局**。
> 因为函数体内没有同名声明，引擎就往上找，找到全局那个并改掉它。
> 写代码时如果赋值左边没有 `let` / `var` / `const`，先停下来想一秒。

## 四、`"use strict"`：把静默错误变响亮

严格模式解决的就是上面那个问题。课件的定义很准确：*A **directive**, not a statement* —— 它是**一条指令**，不是一条语句。

```js
"use strict";

x = 3.14;        // 严格模式下：ReferenceError
```

它做的事只有一件，但正中要害：*It turns silent mistakes into errors — an undeclared assignment **throws** instead of creating a global.*

**同一个赋值，一个静默造全局，一个当场抛错。**

### 局部或全局

```js
function myFunction() {
  "use strict";
  y = 3.14;      // 抛错
}
```

把指令放在函数开头，**只对这个函数生效**；放在脚本开头，对整个脚本生效。

### 现代代码本来就是严格的

课件补了一条容易被忽略的事实：*Modern code is strict already — **modules and classes are strict by default**; the directive matters for plain scripts.*

| 代码类型 | 是否默认严格 |
|---|---|
| ES 模块（`import` / `export`）| ✅ 严格 |
| `class` 里的方法 | ✅ 严格 |
| 普通 `<script>` | ❌ 不严格，**要靠 `"use strict"` 这行** |

所以在当代，`"use strict"` 主要出现在**普通脚本**里（不是模块、没用 class 的那些），作用是把老习惯里的漏写声明变成立即可见的错误。

> [!note] 课件没讲的部分
> `"use strict"` 还会改变别的行为（`this` 在函数里不再指向全局、删除变量报错等），
> 但**本讲只讲了"未声明赋值抛错"这一条**，所以本篇也只写这一条。
> `this` 的完整规则课件留给了下一讲。
