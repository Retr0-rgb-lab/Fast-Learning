# 定义与调用 · Defining and Calling a Function

> **一句话**：写 `function` 只是把一段代码**登记**起来，它在被调用之前一行都不跑；真正决定行为的是调用——`return` 一到执行就停，不写 `return` 的调用照样发生，只是求值成 `undefined`。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §5 Functions 的 Defining a Function 与 Invocation and Return 两页：函数定义的形状、`return` 的语义、忘记写 `return` 会得到什么，以及 `toCelsius` 这个名字与 `toCelsius(77)` 这个调用到底差在哪。

## 一、定义：先把代码块登记成一个名字

课件给的形状是一个**具名的代码块**，括号里列参数名：

```js
function myFunction(p1, p2) {
  return p1 * p2;
}
```

这行代码被读到时，引擎只做一件事：**记住"存在一个叫 `myFunction` 的函数，它的参数叫 `p1` 和 `p2`"**。课件的措辞很直接——*it runs when something calls it, not when it is defined*，它是在**被调用**的时候运行，不是在被定义的时候运行。

这条区别决定了函数定义在代码里的位置是自由的：可以写在文件开头，也可以写在任何一行，只要在调用它的那一行之前登记好就行。页面上代码从上往下跑，某个函数完全可以先被调用、后被定义（前提是定义在它自己的文件里、且在调用行之前——这一点和"函数声明会被提前登记"那件事有关，见 [[函数表达式与自执行]]）。

```js
function myFunction(p1, p2) {
  return p1 * p2;
}

let result = myFunction(4, 3);   // 4 * 3 = 12
```

`myFunction(4, 3)` 执行时，`p1` 拿到 `4`、`p2` 拿到 `3`，函数体算出 `12` 并交回来。

## 二、括号里的是名字（parameters）

课件明确区分了两个词，这一篇先用住这个区分（另一半在 [[参数与默认值]] 展开）：

| 位置 | 叫什么 | 是什么 |
|---|---|---|
| 定义里 `function myFunction(p1, p2)` | **参数（parameter）** | 只是名字 / 占位符，这里还没有值 |
| 调用里 `myFunction(4, 3)` | **实参（argument）** | 真正传进去的值 |

定义里**不写任何类型**——课件的原话是定义从不声明是字符串还是数字，由调用方决定。所以 `p1` 名字起成 `p1` 还是 `firstname` 不影响运行，起名字是为了读代码的人不迷路。

## 三、`return`：交回结果，并且执行到此为止

课件对 `return` 给了两件事，一件是好的，一件是容易漏的：

1. **交回结果**——调用方收到这个值。
2. **执行停在那里**——`return` 后面的代码不再执行。

```js
function myFunction(p1, p2) {
  return p1 * p2;
  console.log("这一行不会跑");   // return 已经把执行截断了
}
```

## 四、不写 `return`：调用照样发生，只是求值为空

这是本篇最容易考的一格。课件的原话是 *no return means `undefined`*，并且补了半句解释：**the call still happens; it just evaluates to nothing** —— 调用确实执行了，函数体里的副作用（比如改页面）也真实发生了，只是这次调用整体没有值。

```js
function shout(text) {
  const demo = document.getElementById("demo");
  if (demo) {
    demo.innerHTML = text.toUpperCase();   // 页面确实被改了
  }
  // 没有 return

}

let nothing = shout("Hello!!");   // 页面显示 HELLO!!
console.log(nothing);              // undefined
```

`nothing` 是 `undefined`，但上面那行改页面的代码已经执行过了。**"没有结果"不等于"没有运行"**——想区分这两种情况，看函数体有没有副作用。

> [!warning] 以为"没 return 就是没执行"
> `console.log(f(1))` 打出 `undefined` 时，说明的是这次调用**没有产出值**。如果 `f` 的作用是改 DOM、发请求、记日志，那些事一件都不会少。想确认某个函数到底做了什么，要读它的函数体，不能读它的返回值。

## 五、名字 vs 调用：括号决定你拿到哪一个

课件用同一个例子把这件事讲透——`toCelsius` 这个**标识符**和 `toCelsius(77)` 这个**调用**，是两个不同的东西：

```js
function toCelsius(f) {
  return (f - 32) / 1.8;
}

toCelsius(77);      // 25 —— 跑一遍函数，拿回结果
toCelsius;          // 函数本身（一个函数的定义）
let t = "It is " + toCelsius(77) + " C";   // "It is 25 C"
```

| 写法 | 读到的是什么 |
|---|---|
| `toCelsius` | 函数本身。打印出来是一段函数定义 |
| `toCelsius(77)` | 调用。括号里给了实参 `77`，结果是 `25` |
| `(f - 32) / 1.8` | 调用里那句算式：`77 → 45 → 45 / 1.8 = 25` |

课件把这条规矩说成一句话：**`()` means call it now**——括号就是"现在就调用"的意思；没有括号时你手上的还是那个函数。

> [!warning] 忘了写括号：拿到函数而不是结果
> ```js
> let t = "It is " + toCelsius + " C";
> ```
> 这行**不会报错**，它只是把一段函数定义拼进了字符串，结果是一句莫名其妙的话。函数不会因为你没调用就自己跑，也不会提醒你少了括号——这种错误往往要到输出看起来完全不对时才被发现。写完调用，检查一下每个"该跑"的名字后面有没有 `()`。

## 六、调用是表达式，所以能出现在任何计算里

课件第三句是 *a call is an expression*：调用会**求值**，所以它不是一个只能在语句位置用的动作，而是一个值。值能去的地方，调用就能去：

```js
let t = "It is " + toCelsius(77) + " C";        // 拼进字符串
let hot = toCelsius(98) > 20;                    // 参与比较 → true
let readings = [toCelsius(77), toCelsius(98)];   // 放进数组
for (let i = 0; i < 2; i++) {
  console.log(readings[i]);
}
```

课件给的例子是第一种（字符串拼接），后两种是同一个道理：`myFunction(4, 3)` 求出 `12`，于是它可以和 `12` 去任何地方。

## 七、一共三种方式让函数跑起来

课件在 Invocation 一页列了全部可能性，本篇只列，第三种和细节留给专门讲"函数即值"的 [[函数即值]]：

| 方式 | 谁来跑 | 例子 |
|---|---|---|
| 事件（event） | 用户操作触发 | 点击后调用一个改页面的函数 |
| 自己的代码调用 | 你写的另一行 | `toCelsius(77)` |
| 自执行 | 定义的那一刻就是它自己 | 见 [[函数表达式与自执行]] |
