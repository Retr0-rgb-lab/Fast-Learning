# 属性增删与访问器 · Adding, Deleting, Getters and Setters

> **一句话**：对象的属性**不是固定的** —— 赋值就是新增、`delete` 就是删除（且**只**删属性，不删变量也不删函数）；`get` / `set` 则让你写出一个**读起来像字段、背后却在跑代码**的属性。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §6 Objects 的 Adding and Deleting Properties 与 Getters and Setters 两页：属性的新增与删除、`delete` 的作用范围，以及 getter / setter 各自在什么时候被调用。

## 一、赋值就是新增

课件：*Add by assigning — `person.nationality = "English"` **creates the property on the spot**.*

```js
const person = { firstname: "John", age: 50 };

person.nationality = "English";   // 出生了
person.nationality;               // "English"
```

对象字面量里没写过 `nationality`，**给它赋值一次，属性就出现了**。不需要先声明、不需要先建空壳。

而且 `const person` **不会因此报错** —— 这正好说明 [[对象与属性]] 里那条：`const` 保证的是"这个名字不能被重新指向别的东西"，**不是**"它里面的内容不能变"。要删属性得用 `delete`，不是重新赋值。

```js
const person = { firstname: "John" };
person = { firstname: "Jane" };   // ✗ TypeError —— const 的名字被重新指向了
person.firstname = "Jane";        // ✅ 改的是对象里的内容
```

读回来用哪种写法都行 —— 点号、方括号都可以，见 [[对象与属性]]。

## 二、`delete` 会把属性整个拿走

```js
const person = { firstname: "John", age: 50 };

delete person.age;    // 删掉了
person.age;            // undefined
```

课件的说法是 ***both the data and the property itself disappear*** —— 数据和**属性本身**一起消失。

**注意区分两件事**：

| | 发生了什么 | 再读它 |
|---|---|---|
| `delete person.age` | 属性**不存在**了 | `undefined` |
| 只是从没赋值过 | 属性同样**不存在** | `undefined` |

两者从"读"的角度看不出差别 —— 都是 `undefined`。想确认一个属性到底在不在，用 `in`：

```js
"age" in person;      // false
```

> [!warning] `delete` 只管属性，不管变量也不管函数
> 课件明确限定：***`delete` is for properties — it does nothing to variables or to functions.***
>
> ```js
> let x = 1;
> delete x;          // ✗ 在严格模式下是 SyntaxError
>
> function f() { }
> delete f;          // ✗ 删不掉
> ```
>
> 记法：**`delete` 后面跟的是"某个对象上的某个名字"**。如果那个名字不属于某个对象，
> 它就什么也删不了。

## 三、getter / setter：读起来像字段，背后在跑代码

课件叫它们**computed properties（计算属性）**：*a property that is worked out by a function **when you read it**.*

```js
const person = {
  firstName: "John",
  language: "en",

  get lang() {          // 读的时候跑
    return this.language;
  }
};

person.lang;             // "en" —— 跑了 getter，但没有括号
```

### 两条规则

| 关键字 | 什么时候跑 | 典型用途 |
|---|---|---|
| `get` | 属性被**读取**时 | 把一个值**算**出来（比如从别的字段推导） |
| `set` | 属性被**赋值**时 | 赋值时**顺手校验或改写** |

```js
const person = {
  firstName: "John",
  language: "en",

  get lang() {
    return this.language;
  },

  set lang(value) {            // 赋值时顺手做点事
    this.language = value;
    console.log("语言被改成：" + value);
  }
};

person.lang = "zh";     // 触发 setter
person.lang;            // 触发 getter → "zh"
```

课件特别点出 `set` 的用处：***`set` runs when the property is assigned — **the place to validate**.** 想在赋值那一刻拦住非法值，就写在 `set` 里。

### 为什么说它"看起来像字段"

课件的原话：*It looks like a field — **it reads with no parentheses**, yet code runs.*

```js
person.lang;          // 没有括号
```

别的语言里要调用方法得写 `getLang()`，这里**不用括号** —— 读起来和读一个普通字段一模一样，但背后是一个函数在跑。

这个设计叫**访问器（accessor）**。代价是要多两个关键字（`get` / `set`），好处是**调用方完全不用改** —— 原本读 `obj.lang` 的代码，改成 getter 之后一行都不用动。

## 四、什么时候值得用

课件给了一页例子就停在这一层，这里补一条判断标准（这是由上面两条规则推出来的，不是课件原文）：

| 场景 | 用什么 |
|---|---|
| 存一个用户真的填了的值 | 普通属性 |
| 值能从别的字段算出来，不该单独存 | `get` |
| 想在赋值那一刻校验/规整 | `set` |
| 只是个临时数据 | 别搞访问器，直接写普通属性 |

**`const` 配 getter/setter** 尤其常见：`const` 保证名字不变，而访问器控制**往里放什么、放出来什么** —— 名字和内容都被管住了。
