# 函数即值 · Functions as Values

> **一句话**：函数能当参数传给别人 —— 这种"交给对方、以后再由他调用"的函数叫**回调**；页面上几乎所有"页面会响应你"的机制都是回调，`addEventListener` 和 `setTimeout` 是同一个想法的两种写法。

课件原文见 [Lecture_06_JS.pptx](<../../../raw/Lecture_06_JS.pptx>)。本篇覆盖 §5 Functions 的 Functions as Parameters 一页：函数作为实参、回调的定义、`addEventListener` 与 `setTimeout` 的共通之处，以及箭头函数那种更短的写法。

## 一、函数是值，所以能传

课件的第一句是 *Functions are values — so a function can be an argument to another function.*

```js
function sayHi() {
  console.log("done");
}

setTimeout(sayHi, 1000);
```

`setTimeout` 收到的东西是**两样值**：一个函数、一段毫秒数。它不关心那个函数叫什么名字，只知道"一秒后，把这个叫来"。

这和传一个数字进去没有本质区别 —— 只是值的类型从"数字"换成了"函数"。

## 二、回调：交给别人，以后再调

这种"你传给我的函数，我**稍后**替你调用"的参数，课件给了名字：**callback（回调）**。

> *That argument is a callback — the function you hand over, to be called later by the receiver.*

关键词是 **later（以后）**。调用者和被调用者不是同一段代码，调用发生在你写这段代码的时候之外 —— 这正是"函数是值"这个前提的实用价值：

**你写一个函数，把它的名字交出去，就等于把"将来某刻要执行什么"这件事，交给了一个你现在还不知道是谁的角色。**

## 三、页面上两处最重要的用法

课件点出两处，并且强调它们是**同一个想法**：

### 事件监听

```js
btn.addEventListener("click", handler);
```

你把 `handler` 交给按钮。**按钮不知道 `handler` 内部写了什么**，它只负责"被点到的时候，把这个函数叫来"。这正是 [[事件监听器]] 那一页讲的机制。

### 定时器

```js
setTimeout(() => sayHi(), 1000);
```

定时器也不知道你要跑什么，它只是"一秒后把这个叫来"。详见 [[定时器与Cookie]]。

> [!important] 为什么课件把这两处并列
> 因为初学者常以为"事件"和"定时器"是两种魔法。其实它们是同一件事：
> **有一段代码，我不管它叫什么、里面写了什么，我只在你告诉我的时候执行它。**
> 搞清楚这一点，后面学 Promise、`async/await`、回调地狱时都会省很多力气 —— 那几个也全是"以后再调"的机制。

## 四、箭头函数：更短的一种写法

课件给的简写形式：

```js
setTimeout(() => console.log("done"), 1000);
```

箭头函数把 `function` 关键字和一对花括号省掉了。三种常见形态：

| 形态 | 长相 |
|---|---|
| 无参 | `() => { … }` |
| 单个参数 | `x => x * 2` |
| 表达式体（不写 `{}` 和 `return`）| `x => x * 2` |

```js
const double   = x => x * 2;          // 最简
const add      = (a, b) => a + b;     // 多参数要加括号
const doThing  = () => {               // 多行语句还是要花括号
  console.log("a");
  return 1;
};
```

### 一个必须记住的差别

课件在这条上加了一句限定：*and **it does not create its own `this`**.*

箭头函数**不创建自己的 `this`** —— 里面的 `this` 来自它被写下的那个位置的外层代码。

这条在本讲只在**一个地方**用得上：写**对象方法**时不能用箭头函数代替普通 `function`，否则 `this` 不会指向那个对象。细节在 [[方法与this]]。

> [!warning] 这是箭头函数最常踩的坑
> "箭头函数更短"是真的，"箭头函数到处都能用"是假的。
> 需要 `this` 指对象的场合（对象方法、事件处理函数里要读触发元素），一律用 `function` 写法。
>
> 本讲只教到这一句为止 —— 箭头函数的 `this`、以及 `this` 的完整规则，课件留给了下一讲
> （Week 7 JavaScript II: `this`、prototypes、classes & closures），那份课件还不在 `notes/raw/` 里，所以本库不展开。
