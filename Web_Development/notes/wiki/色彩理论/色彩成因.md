# 色彩成因 · Why We See Colour

> **一句话**：颜色是一种**波长**；**颜料把光减掉（subtractive），光自己相加（additive）** —— 所以屏幕和打印机**永远印不出同一批颜色**，而 CSS 从头到尾用的是**加色的 RGB**。

课件原文见 [Tutorial_01_ColorTheory.pptx](<../../raw/Tutorial_01_ColorTheory.pptx>)。本篇覆盖其中「Why We See Colour」一节：从「What Is Colour?」到「Pigment and Light — Two Sets of Primaries」，另引「Three Wheels, Three Primaries」一页收尾。

## 一、颜色是一种波长

可见光是一种**电磁波**。**改变波长，你就改变了颜色。**

| 波长 | 看到的颜色 |
|---|---|
| 约 **380 nm** | 紫（violet） |
| 约 **750 nm** | 红（red） |

波长和频率是同一件事的两种说法：**波长越短，频率越高**。而眼睛**按频率给光排序** —— 课件的结论很干脆：*「that sorting is the whole of colour.」*（这个排序就是颜色的全部。）

## 二、眼睛只会做加法

这一条是理解后面一切的钥匙。课件说得很直接：**The eye adds, it cannot separate.**

两个波长同时到达时，眼睛**不会**把它们看成两种颜色，而是**把它们加起来，报出一个结果**。所以：

> [!important] 眼睛只有加法，没有减法
> 两种光一起进来 → 你看到的是**一个**颜色，不是两个。这正是「加色」（additive）的物理根据，也是 CSS 走 RGB 的根本原因。
>
> 顺带解释了另一个常见误会：RGB 三个通道相加得到白色，而不是**去掉**了某些东西。屏幕点亮像素就是加法，绝不会「吸收」光。

## 三、白色不是一种波长

把所有可见波长一起送进来，和就是**白光** —— 这正是阳光。

> [!important] 所以白色**不在光谱上**
> 没有哪个波长产生白色。白色是**眼睛在「什么都不缺」时报告的结果**。
>
> 课件的表述：*「White is what the eye reports when nothing is missing.」* 这一点在调色时非常有用 —— 见 [[色轮与三大参数]] 里「value 升高永远不会带来白色」那条。

## 四、两套理论

### 减色：颜料（Subtractive — pigment）

**白光照到一个表面上，表面吸收掉一部分波长，把剩下的反射回来。你看到的，是剩下的那些。**

| 要点 | 说明 |
|---|---|
| 过程 | 白光照射 → 表面吸收一部分 → 反射其余 |
| 你看到的 | **被剩下来的**那部分光 |
| 混合的效果 | **移除光** —— 混得越多，**越暗** |
| 三原色 | **cyan（青）、magenta（品红）、yellow（黄）** |

青 + 品红 + 黄把**所有**波长都吸收掉了，结果趋近于**黑**。

> [!warning] 所以打印机用 CMY 之外还要一个 K
> 课件解释了那个多出来的字母：**混出来的 CMY 油墨给的是一种浑浊的深棕色（a muddy dark brown），不是真正的黑**。所以额外加一道 **K（黑墨）** 才能印出真黑 —— 这就是 **CMYK** 的 K。

### 加色：光（Additive — light）

**光是被发射出来的，不是被反射的。把波长加起来，结果更亮。**

| 要点 | 说明 |
|---|---|
| 过程 | 光被**发射** |
| 混合的效果 | **相加** —— 越多越**亮** |
| 三原色 | **red（红）、green（绿）、blue（蓝）** |
| 红绿蓝全满 | **白光** |

> [!important] 一个像素就是三盏小灯
> 课件的原话：*「A pixel is three tiny lights; the colour is the sum.」* 你手上每一块屏幕都在混这三个。RGB 里某个通道调到最大，就是把那盏灯开到最亮。

## 五、同一张表，两边对照

| | 减色（颜料） | 加色（光） |
|---|---|---|
| 光是 | 被**反射**的 | 被**发射**的 |
| 混合 | 移除波长 | 相加波长 |
| 越混越 | **暗** | **亮** |
| 三原色 | **CMY**（青 品红 黄） | **RGB**（红 绿 蓝） |
| 极端结果 | 全吸收 → **黑** | 全通过 → **白** |
| 谁在用 | 印刷、油墨、颜料 | 屏幕、显示器、**CSS** |
| 极端表现 | 「一塌糊涂的深棕」→ 补一个 K | 直接得到纯白，不需要补 |

课件在两张幻灯片的底部各留了一句，本篇的两条核心就来自它们：

- *「**Pigment takes light away. Light adds up.**」*（颜料把光**拿走**，光**加起来**。）
- *「Every colour question in CSS starts here.」*（CSS 里的每一个颜色问题都从这里开始。）

## 六、由此得到的两条实用结论

> [!important] 一、屏幕和打印机**做不出同一批颜色**
> 课件说得不留情面：*「A screen and a printer cannot reproduce the same colours — they build them the opposite way round.」* 一个把光加起来，一个把光拿走，**过程正好相反**。屏幕上看着好看的饱和蓝，打印出来可能发闷 —— 这不是打印机坏了，是两台设备在做相反的运算。

> [!important] 二、**CSS 用的是 RGB**
> 课件 Three Wheels, Three Primaries 一页点明：屏幕用 RGB，印刷用 CMY，手工调颜料用 RBY（红黄蓝）。而*「**Your CSS works in RGB.**」*
>
> 所以你在样式表里写的每一个颜色，最终都被浏览器存成**一个 RGB 三元组**，哪怕你写的是 `hsl()`。四种写法怎么写、为什么 `hsl()` 是设计时更好用的那个记法，见 [[颜色表示法]]；三个参数各是什么，见 [[色轮与三大参数]]。
