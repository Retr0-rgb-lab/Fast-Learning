# 背景与混合模式 · Background & Blend Modes

> **一句话**：背景负责画 content 和 padding（**从不画 margin**），`background` 简写里**没提到的属性一律重置为默认值**，而 `mix-blend-mode` 是**算出来的**结果而不是手挑的颜色。

课件原文见 [Lecture_04_CSS.pptx](<../../raw/Lecture_04_CSS.pptx>)。本篇覆盖其中「Background — the Properties」到「Blend Modes」各页。

## 一、背景属性总表

| 属性 | 干什么 |
|---|---|
| `background` | 一条声明里设置**所有**背景属性（简写） |
| `background-attachment` | 背景图是**跟着页面滚**还是**钉在视口上** |
| `background-color` | 元素的背景颜色 |
| `background-image` | 元素的背景图 |
| `background-position` | 背景图的起始位置 |
| `background-repeat` | 背景图如何重复 |

## 二、逐条拆开

### `background-color`：纯颜色

颜色画在**匹配到的那个元素的 content 和 padding 底下**。HTML 里**一个属性都不用改** —— 颜色全由样式表送过来。

```css
h1  { background-color: green; }
div { background-color: lightblue; }
p   { background-color: yellow; }
```

三个元素三种颜色，一条属性搞定，颜色按盒子被遇到的**先后顺序**铺开。

### `background-image`：一张文件，而不是一种颜色

`url(...)` 加载一张图，盒子用它来画，而不是用平涂的颜色。

```css
body { background-image: url("paper.gif"); }
```

> [!warning] 默认是**双向平铺**
> 不做任何声明，图会在**横向和纵向都重复**，所以一个小文件就铺满整页。这既是背景图最大的优点（一张小图撑一面墙），也是最常被误判为 bug 的现象。

### `background-repeat`：把平铺收窄

| 需求 | 写法 | 效果 |
|---|---|---|
| 上下也铺（默认） | `background-repeat: repeat;` | 一行小图拼成一条长带 |
| **只要一行**（页头色带） | `background-repeat: repeat-x;` | 同一个文件变成一条**横向页头条** |
| **只要一份** | `background-repeat: no-repeat;` | 盒子里的唯一一张图 |

```css
body {
  background-image: url("gradient_bg.png");
  background-repeat: repeat-x;
}
```

### `background-position`：那唯一一份放哪

`no-repeat` 之后只剩一张图，这个属性决定它**锚在盒子的哪个角**。

```css
body {
  background-image: url("img_tree.png");
  background-repeat: no-repeat;
  background-position: right top;
  margin-right: 200px;      /* ← 关键：右外边距 */
}
```

> [!important] `margin-right: 200px` 是防撞的关键
> 光把图放右上角，它会**压在正文上**。那 200px 的右外边距把正文的可用宽度收窄，**给图片让出位置**，它才落不到文字上。课件的原话是：*The right margin is what stops the picture landing on the words.* 背景图与文字的重叠，对比度的账要另外算，见 [[对比度与可读性]]。

### `background-attachment`：`scroll` 还是 `fixed`

| 值 | 行为 |
|---|---|
| `scroll` | 图**跟着页面一起滚**（默认） |
| `fixed` | 图**钉在视口上**，文档在它下面动 |

```css
body {
  background-image: url("img_tree.png");
  background-repeat: no-repeat;
  background-position: right top;
  margin-right: 200px;
  background-attachment: fixed;
}
```

> [!warning] 一屏高的页面上看不出 `fixed`
> 课件专门提醒：**页面得够长才看得出区别**。一屏就装下的页面，滚不动，两种值一模一样。改完记得把页面拉长再看。

## 三、`background` 简写

```css
body {
  background: #ffffff url("img_tree.png") no-repeat right top;
  margin-right: 200px;
}
```

一条声明同时设好**颜色、图、重复、位置** —— 顺序就是简写读取的顺序。

> [!important] 简写最大的坑：**没提到的属性会重置**
> 课件标题就是这句：**"What you leave out is reset"**（你略去的部分会被重置）。你**没有**在简写里写的每一个背景属性，都会**回到它的默认值**，不是「保持原样」。
>
> 也就是说：先写 `background-repeat: no-repeat;`，再写 `background: #fff url(...)` —— 那个 `no-repeat` 会被第二条的默认值吃掉。**要么全部写进简写，要么把它放在简写之后。**

课件的补充结论是：*It does not matter if one of the property values is missing, as long as the other ones are in this order* —— 少写一两个值没关系，**只要留下的按顺序排**。

## 四、`mix-blend-mode`：算出来的混合

`mix-blend-mode` 决定元素的**内容**如何与**它背后已经画好的东西**混合。它**需要背后真有东西**才能混合。

| 值 | 做什么 | 公式（a = 底层，b = 上层，逐通道，0–255） |
|---|---|---|
| `normal` | 默认。上层**直接盖住**下面 | — |
| `multiply` | **变暗**，两种颜色都保留 | `a * b / 255` |
| `screen` | **变亮**，与 multiply 正好相反 | `255 - (255-a)*(255-b)/255` |
| `darken` | 逐通道**取较暗的那个** | `min(a, b)` |
| `lighten` | 逐通道**取较亮的那个** | `max(a, b)` |

课件的演示是 `#ffc107` 压在 `#185fa5` 上面走一遍这五种。课件的总结句值得抄下来：

> **Two colours, five results — computed, not picked by hand.**（两种颜色，五种结果 —— 是算出来的，不是手挑的。）

### `isolation: isolate`

混合会**沿着页面向外传播**，一路往祖先那边混下去 —— 除非你叫停：

```css
.wrap { isolation: isolate; }   /* 把混合关在这个容器里 */
```

放在一个包裹元素上，就阻止混合继续影响页面上更上层的东西。

> [!important] 为什么这件事在实践中要紧
> 混合模式会牵连**整条渲染链**，效果可能来自你以为无关的祖先。这是 `mix-blend-mode` 调试时最费时间的地方 —— 有了 `isolation: isolate` 就能把变量限定在局部。另一个「同属渲染、但不会引起重排」的工具是 [[变换transform]]：位移、旋转、缩放都靠合成层完成，混合与变换共享这个「便宜」的家族特征。
>
> 主题色的写法见 [[颜色表示法]]，若要把一套色值做成可切换的主题，见 [[CSS变量]]。
