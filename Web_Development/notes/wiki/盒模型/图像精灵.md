# 图像精灵 · Image Sprites

> **一句话**：精灵图就是把一堆小图排成规则网格塞进**一个文件**，然后把每个盒子缩到**一格大小**当窗口 —— `background-position` 用**负数**把想看的那一格移进窗口，**盒子本身一动不动**。

课件原文见 [Lecture_04_CSS.pptx](<../../raw/Lecture_04_CSS.pptx>)。本篇覆盖其中「Image Sprites — One File, Many Pictures」与「Sprites in Practice — Icons and Animation」两页。

## 一、一张图装下很多画面

**精灵表（sheet）** 是一个文件，里面按**规则网格**排着一格格画面 —— 一段动画的十二帧，或者九十个图标。好处立刻兑现：

- **一次请求**（one request）
- **一条缓存记录**（one cache entry）
- **没有闪烁**（no flicker）

课件给出的第一组具体数字：

| 项 | 值 |
|---|---|
| 文件 | `character.png` |
| 尺寸 | **512 × 384** |
| 内容 | **十二帧**，每帧 **128 × 128** |
| 体积 | **23 KB** |
| 请求数 | **一次** |

（512 = 128 × 4，384 = 128 × 3 —— 4 × 3 的网格，正好十二格。）

第二组是真实场景里的图标表：

| 项 | 值 |
|---|---|
| 文件 | `icons.png` |
| 尺寸 | **960 × 864** |
| 内容 | **九十格**，每格 **96 × 96** |
| 体积 | **44 KB** |
| 请求数 | **一次**（九十次绘制都从浏览器自己的缓存里出） |

## 二、盒子就是那个窗口

这是整篇的核心机制，只有一句话：

> **把盒子做成一格那么大，整张文件就从它的左上角被画进这个盒子里 —— 你看到的，就是这个盒子恰好盖住的那个矩形。**

格子本身就是那个窗口。你能看见的不是「一张图」，而是**「盒子覆盖到的那一块区域」**。

## 三、`background-position` 负责取格

要把画面从第一格挪到第二格，做法是**把图往左、往上移动整格**：

```css
background-position: -128px 0;   /* 取第二格 */
```

| 位置 | 取到第几格 |
|---|---|
| `0 0` | 第 1 格 |
| `-128px 0` | 第 2 格 |
| `-256px 0` | 第 3 格 |
| `-384px 0` | 第 4 格 |

**数字取负，盒子不动。** 没有任何东西被裁切，也没有任何东西被复制 —— 变的只有一条声明。

课件那句总结是：**"Same file, four boxes — the only thing that changes is one declaration."**（同一个文件、四个盒子，唯一变的是一条声明。）

## 四、`steps()` 把它变成动画

如果只用 `steps()` 之外的普通缓动，背景会**平滑地滑**，于是你同时看到**两帧各一半**。要避免这个，得让位移**按帧跳**：

```css
animation: face 1.2s steps(4) infinite;
```

`steps(4)` = **四帧，不混合，没有中间状态**。每个阶段干脆地跳到下一格。完整的 `steps()` 动画写法见 [[关键帧动画]]。

## 五、hover 状态也在表里

精灵图当初被发明出来，正是为了这个：**一个 hover 状态是多一条 `background-position`，而不是多一次请求。**

```css
.icon { background-image: url("icons.png"); background-position: 0 0; }
.icon:hover { background-position: -96px 0; }   /* 同一张表的相邻格 */
```

课件的措辞：**"A hover state is one more background-position, not another request."**

### 一个变量统管所有尺寸

用 CSS 自定义属性（见 [[CSS变量]]）里的一个数同时乘过**格子、整张表、以及位移距离**，几何和动画就不会各说各话：

```css
:root { --s: 1; }        /* 24px */
.icon {
  width:  calc(96px * var(--s));
  height: calc(96px * var(--s));
  background-size: calc(960px * var(--s)) calc(864px * var(--s));
  background-position: 0 0;
}
:root { --s: 3; }        /* 改成 72px，三样一起放大 */
```

课件的演示给的就是 **24px / 48px / 72px 三个尺寸出自同一个文件**。

## 六、这笔账的代价

精灵图不是白拿的，课件专门用一节列了三笔账：

| 代价 | 说明 |
|---|---|
| **每格必须同形** | 网格是规则的。图标可以不一样，但**每格画布的形状得一样**，否则取格会切到邻居 |
| **页面会下载它从不显示的图标** | 整个文件一次性进来，你只用其中两格也一样全下 |
| **背景图自己带不了 alt 文本** | `background-image` 没有任何 `alt` 属性可写 |

> [!important] 第三条最要命：可访问性
> `<img src="icons.png" alt="搜索">` 有 `alt`，`background-image: url(...)` **一个字的替代文本都放不下**。屏幕阅读器读到这段背景图时，得不到任何说明。
>
> 这就是精灵图在现代实践中让位给**内联 SVG** 的主要原因 —— SVG 可以带 `<title>`、可以带 `role` 与 `aria-label`。权衡的完整对比见 [[图标]]；若要让颜色/状态本身也能传达信息而不只靠图形，见 [[对比度与可读性]]。
