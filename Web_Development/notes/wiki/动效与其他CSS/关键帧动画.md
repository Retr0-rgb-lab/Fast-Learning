# 关键帧动画 · Keyframe Animation

> **一句话**：`@keyframes` 是**配方**（时间线上任意多个停靠点），`animation` 是**让它跑起来的指令**（多快、跑几遍、来回还是单向）—— 一个定义过程，一个发动过程。

课件原文见 [Lecture_05_CSS.pptx](<../../raw/Lecture_05_CSS.pptx>)。本篇覆盖其中「Animation」一节的后半：从「@keyframes」到「transition vs animation」。

## 一、配方与指令的分工

```css
/* 配方：定义过程 */
@keyframes bounce {
  from { transform: translateY(0); }
  to   { transform: translateY(120px); }
}
/* 指令：发动它 */
.ball {
  animation: bounce 1s ease infinite alternate;
}
```

课件那句最好记的话：*「Keyframes are the recipe — animation is the instruction to run it.」*

| 概念 | 角色 | 决定什么 |
|---|---|---|
| `@keyframes` | 配方 | 每一刻的样式：位置、颜色、大小…… |
| `animation` | 指令 | 跑哪份配方、多快、几遍、来回还是单向 |

`@keyframes` 里可以写**任何可动的属性**，不止 `transform`。

### 起止停靠点

| 写法 | 含义 |
|---|---|
| `from` / `to` | 就是 `0%` 和 `100%` 的简写 |
| `0%` / `100%` | 时间线的两端 |
| 任意百分比 | 想加几个停靠点就加几个 —— `0%, 25%, 50%, 100%` |

课件的比喻：*「Each percentage is one moment of the animation.」* 每一个百分比就是动画里的**一个瞬间**。

## 二、多停靠点：三个不显然的规则

```css
@keyframes traffic {
  0%        { background: #d9534f; }
  40%       { background: #ffc107; }
  70%, 100% { background: #3d9970; }
}
```

| 规则 | 说明 |
|---|---|
| 停靠点可以**多于两个** | `0%` 和 `100%` 只是时间线的两端，不是限制 |
| **共享停靠点** | `70%, 100% { … }` 一块规则同时应用到两个时点 |
| **没有停靠点的区间会冻结** | 70% 到 100% 之间没有新停靠点，值就保持不动 |

> [!warning] 区间冻结是最容易看错的一处
> 70% 之后没有写新的停靠点，所以那 30% 的时间里颜色**一直是** `#3d9970` —— 它不是慢慢变过去，是停住。想知道一段动画什么时候「不再动」，就去数那两个百分比之间有没有停靠点。

（上面这组三色里，`#d9534f` 与 `#ffc107` 正好是课程调色板的 Alert 与 Gold；`#3d9970` 不属于调色板，只是这页示例用的第三色。）

### 相等的停靠点 = 硬切，不是渐变

```css
/* 相等的停靠点 = 一次硬切，而不是渐变 */
@keyframes blink {
  0%,  49% { opacity: 1; }
  50%, 100% { opacity: 0; }
}
```

- `0%` 到 `49%` 全都是 `opacity: 1` —— 这段是**冻住**的。
- `50%` 一到，值直接变成 `0` —— 中间没有过渡，因为 49% 和 50% 之间**没有任何停靠点**可以插值。

这正是**闪烁光标（typing caret）**的原理：光标本来就不是淡入淡出的，它就是一顿一顿地亮灭。课件把它列进了六个循环配方里。

## 三、`animation` 简写与八个长写属性

简写的**顺序固定**：`name · duration · curve · delay · count · direction · fill`。

```css
/* 长写 */
.ball {
  animation-name: bounce;
  animation-duration: 1.2s;
  animation-delay: 0.2s;
  animation-timing-function: ease-out;
  animation-iteration-count: 3;
  animation-direction: alternate;
  animation-fill-mode: forwards;
}
/* 常用组合写成一行 */
.ball { animation: bounce 1s ease infinite; }
```

八个长写属性：

| 属性 | 取值 / 作用 |
|---|---|
| `animation-name` | 跑哪一份 `@keyframes` |
| `animation-duration` | 一个循环要多久 |
| `animation-timing-function` | 曲线 —— 和 `transition` 一样，**包括 `steps()`** |
| `animation-delay` | 第一个循环开工前先等多久 |
| `animation-iteration-count` | `infinite`，或一个具体遍数 |
| `animation-direction` | `normal` / `reverse` / `alternate` / `alternate-reverse` —— 每个循环往哪边跑 |
| `animation-fill-mode` | `none` / `forwards` / `backwards` / `both` —— **开始前**和**结束后**保持什么样子 |
| `animation-play-state` | `running` / `paused` —— 通常从 JavaScript 控制暂停 |

> [!tip] `alternate` 是什么感觉
> `alternate` 让动画**正着放一遍，再倒着放回来**，第二遍不用重写一份反向的关键帧。往返的循环（呼吸感、心跳感）几乎都用它。

> [!important] `fill-mode` 决定动画结束后停在哪
> `forwards` 让元素**停在最后一帧**的样子，而不是弹回原始值。动画要「动完就留在那儿」时就得加它，否则元素会突然跳回去。

## 四、六个循环配方

课件 Looping Motion Recipes 一页给的六个，每个都是「几行 CSS + 一份关键帧」：

| 配方 | 怎么做的 |
|---|---|
| 转圈 Spinner | 一圈边框，其中一侧上色，按 `linear` 时钟转 |
| 骨架屏微光 Skeleton shimmer | 一道高光扫过形状像内容的色块 |
| 弹跳圆点 Bouncing dots | **一份关键帧 + 三个不同延迟** —— 波浪感全在延迟里 |
| 在线圆点 Live dot | 一个点加一个正在淡出的自己，表示「还连着」 |
| 同步图标 Sync icon | 先转再歇；没有那个「歇」它就像电风扇 |
| 打字光标 Typing caret | 相等停靠点硬切 —— 正是光标的行为 |

转圈那个最短，`linear` 是关键（匀速才像转，不像抽搐）：

```css
.spinner {
  width: 24px; height: 24px;
  border: 3px solid #9DC0EE;      /* 浅色一圈 */
  border-top-color: #1E4FA8;      /* 一侧上色 */
  border-radius: 50%;
  animation: spin 0.8s linear infinite;
}
@keyframes spin {
  to { transform: rotate(360deg); }
}
```

弹跳圆点示范「一份配方 + 三个延迟」这个技巧：

```css
.dot { animation: bounce 1s ease-in-out infinite alternate; }
/* 波纹来自延迟，不是来自第四份关键帧 */
.dot:nth-child(1) { animation-delay: 0s; }
.dot:nth-child(2) { animation-delay: 0.15s; }
.dot:nth-child(3) { animation-delay: 0.3s; }
```

`nth-child()` 的写法见 [[组合选择器]]；`alternate` 带来的往返感见上一节。

## 五、`steps()` 与帧动画

`animation-timing-function` 除了那五条缓动曲线，还能接受 `steps()` —— 它不做插值，而是**一格一格地跳**。这正是逐帧动画的做法。

课件的例子：**一张精灵图（sprite sheet）八个帧，每帧间隔 96px**。

```css
/* 一个盒子，一个文件，八帧 */
.walk {
  width: 96px;
  height: 96px;
  background: url(walk.png) 0 0 no-repeat;
  animation: walk 0.8s steps(8) infinite;
}
@keyframes walk {
  to { background-position: -768px 0; }
}
```

逐个值拆开看：

| 值 | 作用 |
|---|---|
| `steps(8)` | 八次等距跳跃 —— 一帧一跳，**不产生模糊** |
| `to { background-position: -768px 0; }` | **唯一在变的东西**：背景位置从 `0 0` 走到 `-768px 0` |
| `-768px` | 8 帧 × 每帧 96px |
| 整个循环 0.8s | 每帧约 0.1 秒 |

> [!important] 为什么它很便宜
> 课件原话：*「One image, already cached, moved by the compositor.」* 只有一张图、已经被缓存，动的只是它的位置。精灵图怎么切格、`background-position` 怎么取格，见 [[图像精灵]]。

## 六、`transition` 还是 `animation`

| | `transition` | `animation` |
|---|---|---|
| **需要触发** | ✅ 跑在属性变化时 —— `:hover`、`:focus`、class | ❌ **自己就跑**，页面加载即开始 |
| **状态数** | 只有 **A → B** 两个状态 | 关键帧可以定义**任意多个**中间状态 |
| 复杂度 | 更简单 | 功能更强 |
| 重复 | 不循环（跑一次就结束） | `infinite` 循环，或 `alternate` 往返 |
| 典型用途 | 悬停效果、开关切换 | 加载动画、循环动效 |

课件给的**经验法则**：

> **hover effect → transition；looping motion → animation.**

换句话说：*「一个要触发、一个自己跑」*。判断某个动效该用哪个，只需要问一句「**它什么时候开始？**」—— 答得出「鼠标移上去」，用 `transition`；答不出（页面一打开就该动），用 `animation`。

> [!warning] 循环动效一定要配 `prefers-reduced-motion`
> 无限循环的运动是对某些读者最刺眼的一种动效。系统里声明了「减少动态效果」时应该关掉它 —— 但保留原本传达的意思。写法见 [[动效与可访问性]]。
