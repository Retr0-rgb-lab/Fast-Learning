# 动效与可访问性 · Motion & Accessibility

> **一句话**：`prefers-reduced-motion` 是一个**报告用户系统设置**的媒体查询，在它里面把动画和过渡关掉 —— 但要把「滑入」换成「淡入」，**别换成什么都不给**。

课件原文见 [Lecture_05_CSS.pptx](<../../raw/Lecture_05_CSS.pptx>)。本篇覆盖其中「Motion & Accessibility」一页，以及「Media Query Recipes」里 "Less motion" 那一行与 Best Practices 中 `prefers-reduced-motion` 那一条。

## 一、它是什么

`prefers-reduced-motion` 是 `@media` 里的一个**媒体特性（media feature）**。它和其他媒体查询的区别在于：它问的不是「屏幕多宽」，而是**「读者在系统里设了什么」**。

```css
@media (prefers-reduced-motion: reduce) { … }
```

| 值 | 含义 |
|---|---|
| `reduce` | 系统里声明了「减少动态效果」，需要安静 |
| （不写 / `no-preference`） | 系统没有这个偏好，放心动 |

> [!important] 它问的是设备，不是页面
> 读者在操作系统或浏览器里设一次「减少动态效果」，你**每一个**站点的动效都会自动降级。这就是为什么它属于 `prefers-*` 这一族媒体查询 —— 和 `prefers-color-scheme: dark`（系统深色模式）、`prefers-contrast: more`（系统要更高对比度）是同一个机制：问设备要答案，见 [[响应式与媒体查询]]。

## 二、为什么要做

课件给了理由，一句就够：*「Motion can trigger nausea and migraine for some people.」* 运动可能引起**恶心和偏头痛**。

这不是「有些人觉得晃得难受」这种程度的问题 —— 大量前庭功能敏感（vestibular sensitivity）的人面对大幅位移、视差、自动播放的循环动画会真的生病。所以这不只是礼貌，是一种**健康与可访问性**的要求。

> [!warning] 无限循环是最糟的一种
> 一次性的入场动画用户看几秒就过去了；一个 `infinite` 的循环会一直刺眼下去。所以**循环动效必须配降级**，一次性动效也别掉以轻心 —— 快速的大幅位移最容易触发放射反应。

## 三、怎么做（两种写法）

课件在两处给了写法，作用范围不同。

**写法一：关掉所有动画**（Media Query Recipes 里的 "Less motion"）——

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; }
}
```

**写法二：课件 Motion & Accessibility 一页的「三行」版本** ——

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none; }
}
```

课件那句总结是 *「Three lines that make a page safe for everyone.」*

> [!tip] `!important` 什么时候需要
> 写法一用了 `!important`，是因为 `*` 的优先级很低，站内别处的规则可能盖过它。写法二没写 —— 那就要求你自己的动画规则别写得比这里更靠后。两种都是课件原文，实际项目里取哪种取决于你能不能保证「这一段一定生效」。

不过这两条只关了 `animation`。课件那句话其实要求**两个都关** —— *「Inside it, set animation and transition to none.」* 完整一点的写法：

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation: none !important;
    transition: none !important;
    scroll-behavior: auto !important;
  }
}
```

## 四、最关键的一条：别把意思一起关掉

课件这一页真正的重点不是那句媒体查询，是紧接着的半句：

> **Keep the meaning — replace a slide-in with a plain fade, not with nothing.**

「替换成一次朴素的淡入，而不是替换成什么都没有。」

| 原来的动效 | 降级后应该 | 不能是 |
|---|---|---|
| 面板从下方滑入 | **淡入** | 完全不出现 |
| 加载转圈 | 留一个静止的「正在加载」文字 | 转圈照转 |
| 提交成功后卡片滑走 | 原地淡出 | 用户不知道发生了什么 |
| 循环的在线圆点 | 保留那个静态的实心点 | 圆点消失，「是否在线」无从判断 |

> [!important] 动效常常在传递信息，删掉它等于删掉信息
> 一个滑入的侧边栏，滑入这个动作本身就在说「这个东西从页面外进来了，是临时的」；一份加载转圈，转圈在说「系统还在工作，请稍候」。用 `animation: none` 一刀切，等于把这些含义全部删掉 —— 对不需要动效的读者来说，页面反而变得**更难懂**了。
>
> 正确做法：只把**幅度**去掉，保留**出现 / 消失**这件事本身。淡入没有位移，同样传达了「它来了」。

```css
/* 原本：从下方滑入 */
.panel { animation: slide-in 0.3s ease; }
@keyframes slide-in {
  from { opacity: 0; transform: translateY(24px); }
  to   { opacity: 1; transform: none; }
}

/* 降级：保留「它出现了」，去掉位移 */
@media (prefers-reduced-motion: reduce) {
  .panel { animation: fade-in 0.3s ease; }
  @keyframes fade-in {
    from { opacity: 0; }
    to   { opacity: 1; }
  }
}
```

> [!tip] 这个思维习惯比这条 CSS 更值钱
> 去掉的是**运动**，不是**反馈**。同样的道理适用于其他动效属性：过长的过渡可以缩短到几乎为零，但**反馈必须留着** —— 按钮按下去要有反应，菜单打开要看得见。

## 五、检查清单

写完动效，顺手过一遍：

- [ ] 页面上有无限循环动画吗？有的话，`prefers-reduced-motion` 里关了吗？
- [ ] 动效本身在传达信息吗？如果是，降级时有没有用别的方式表达？
- [ ] 位移幅度大不大？大位移是发射反应的主要来源。
- [ ] 只在 `transition` 那一半关够了吗？`animation` 和 `transition` 要**一起**关。

课件 Best Practices 把 `prefers-reduced-motion` 列成六条习惯之一：*「Respect users who want less movement.」* 动效做得再好，读者说不想要的时候就得没有。
