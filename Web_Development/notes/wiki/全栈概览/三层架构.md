# 三层架构 · The Stack, Layer by Layer

> **一句话**：每个 Web 应用都是**浏览器 / 服务器 / 数据库**三层在对话，其中只有前两层之间走 HTTP、后两层之间走 SQL——**两跳、两种语言、三层职责**，这就把整门课该建的东西一次说完了。

课件原文见 [Lecture_01_Overview.pptx](<../../raw/Lecture_01_Overview.pptx>)。本篇覆盖其中 "The Big Picture" 一节的 The Stack, Layer by Layer 一页，即三层结构与两层协议跳转。

## 一、三层各是什么、各做什么

课件的原话是 "Every web application is three layers talking to each other"，并且给每层都留了"技术选型 / 具体职责 / 一句话总结"三栏：

| 层 | 课件给的技术 | 课件给的职责 | 一句话 |
|---|---|---|---|
| **CLIENT** 客户端 | 浏览器（Browser）· HTML · CSS · JavaScript | renders pages · captures input（渲染页面、采集输入） | 用户看得见、点得动的那一层 |
| **SERVER** 服务器 | Node.js / Express | logic · routes · APIs（逻辑、路由、接口） | answers requests · runs code（应答请求、执行代码） |
| **DATABASE** 数据库 | SQL / NoSQL | stores, queries, returns rows（存、查、返回行） | 应用的数据最终落在这里 |

> [!important] 三层你都要建
> 课件的收尾句很重：**"You build all three layers this semester — that is the whole course in one picture."**
> 意思是这门课不只教前端，也不只教某个后端框架，而是**从浏览器一路建到数据库**。任何一个 Web 应用题，三层缺一层都答不完整。

## 二、两跳，两种语言

这三层不是"排成一行"的，而是**只相邻两层之间有连线**——一共两跳，且两跳说的话不一样：

```
   ┌──────────────┐        ①  → HTTP request      ┌──────────────┐
   │   CLIENT     │            ← HTTP response    │   SERVER     │
   │   浏览器      │                              │ Node/Express │
   └──────────────┘                              └──────────────┘
                                                       │
                                              ②      → SQL query
                                                       ← data rows
                                                  ┌──────────────┐
                                                  │   DATABASE   │
                                                  │  SQL / NoSQL │
                                                  └──────────────┘
```

| 跳 | 方向 | 说的是什么 | 课件原文 |
|---|---|---|---|
| **① 客户端 ↔ 服务器** | 请求 / 应答 | **HTTP** | `→ HTTP request` / `← HTTP response` |
| **② 服务器 ↔ 数据库** | 查询 / 结果 | **SQL**（结果是一行行数据） | `→ SQL query` / `← data rows` |

三处值得单独记住的细节：

1. **箭头是不对称的。** 请求永远是客户端发出去、服务器不主动开口；数据永远是服务器**去问**数据库、数据库不主动推。这直接解释了 [[后端技术栈]] 里的 WebSocket 为什么要**先以 HTTP 起步再升级**：让服务器能主动推，等于要给这套"你问我答"的模型开一个后门。
2. **`data rows`（数据行）这个词说明数据库这一层是行/记录形态的。** HTTP 那一跳传的是 HTML、JSON、图片或文件（[[HTTP与URL]]），SQL 那一跳传的是**行**。
3. **课件把第二跳标成 "SQL query"，但第三层的技术栏写的是 "SQL / NoSQL"。** 两者并不矛盾——**跳线是示意，层是可选**：换成 MongoDB 那一跳就不再是 SQL，而是 NoSQL 的查询语法。这是原文自身的措辞，本篇照实记录。

## 三、这套结构是分布式的

课件对此有一句专门的补充：

> The web is distributed: client and server may be continents apart — they only need a network.

这句话是 Week 1 最重要的**世界观**交代，可以拆成三个推论：

| 推论 | 含义 |
|---|---|
| **不需要共享内存** | 客户端和服务器不在一台机器上，因此不能靠读对方的内存，只能靠网络传消息（HTTP / SQL）。 |
| **不需要共享时钟** | 两端谁也不知道对方现在在做什么，所以协议必须自带完整的请求—应答配对，HTTP 才有 request/response 这种结构。 |
| **不需要物理邻近** | 跨洲也能通信，代价只是**延迟（latency）**——而延迟正是 [[性能与可扩展性]] 里"用户离得远"那一类问题的来源。 |

> [!tip] 一句话记住两跳
> **客户端只会说 HTTP，数据库只会说 SQL，夹在中间的服务器两种都得会。**
> 所以课程把服务器端的语言定成 JavaScript——它让"前端和后端用同一种语言"成为可能（[[后端技术栈]] 的 Part I）。

## 四、三层里最常被写的一处

按 [[课程场景与阅读约定]] 里约定的「示例站」（全库共用的那张假想课程主页：`header` + `nav` + `main` + `footer`），三层落下来是这样：

| 层 | 在示例站上做的事 |
|---|---|
| CLIENT | 渲染出课程表格、渲染报名表单；采集用户填的邮箱 |
| SERVER | 收到 `POST`，校验字段，写进数据库，再回一个成功页 |
| DATABASE | 存下一行 `name` / `email` / 时间戳，管理员之后能查出来 |

**注意这件事的两跳都要走**：浏览器 → 服务器是 HTTP，服务器 → 数据库是 SQL。用户在表单里点提交的那一刻，这两层是**串行**发生的，中间任何一跳失败，页面就不会变。这正是 Week 9（HTTP）、Week 10–11（Node.js、Express、数据库）三周要连起来教的原因。
