## Part I — Node.js 运行时

| 课件的四个词 | 原文要点 |
|---|---|
| **Runtime** | Node.js 就是**浏览器之外的 JavaScript**——**V8 引擎 + libuv**，一个**事件驱动、非阻塞（non-blocking）I/O** 模型。**一个线程，同时处理很多连接。** |
| **npm** | 包管理器：`npm init` 建项目，`npm install <pkg>` 加库，`package.json` 记录**每一个依赖**。 |
| **Modules** | 把代码拆成可复用文件——**CommonJS 的 `require` / `module.exports`**，或现代的 **ES 模块 `import` / `export`**。 |
| **HTTP server** | **内置的 `http` 模块**能把任何一台机器变成 web 服务器——**基础功能不需要框架**。 |

课件给的第一段代码，就是 Part I 全部要点的最小可运行形态：

```js
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello from Node.js!');
});

server.listen(3000, () => {
  console.log('Server running on :3000');
});
```

对照着看，这十行分别踩到了上面四个词：`require('http')` 是**模块**，`createServer` 是**HTTP server**，`res.writeHead(200, {...})` 是[[HTTP与URL]] 里的**状态行与响应头**，`listen(3000)` 是[[HTTP与URL]] 里 URL 六段中那个**端口**。

> [!important] 为什么必须是非阻塞
> [[Web应用与客户端-服务器模型]] 说客户端是**一对多**——成千上万个请求会同时到达。如果一个连接占住一个线程等 IO，线程很快就用光。课件的措辞是 **"One thread, many concurrent connections"**：靠事件驱动，**等待 IO 时线程去干别的活**。这正是本课程要"全栈"的底气——**前端和后端是同一种语言**（[[后端技术栈]] 的 Part I 与 [[三层架构]] 的两跳）。

## Part II — Express · REST · CRUD 与数据

| 课件的四个词 | 原文要点 |
|---|---|
| **Express** | Node 的**事实标准（de-facto）** web 框架。`app.get('/path', handler)` 把**一个 URL 映射到一个函数**；**中间件（middleware）**把日志、鉴权、JSON 解析这些可复用的步骤串成链。 |
| **REST API** | 把**资源**摊在 HTTP 上：`GET /notes` 列出、`POST` 创建、`PUT /notes/1` 更新、`DELETE /notes/1` 删除。课件的总结句：**"the URL names the thing, the verb names the action"**——URL 命名**东西**，动词命名**动作**。 |
| **CRUD** | **Create、Read、Update、Delete**，每个应用都在做的四种操作，**与数据库动作一一对应**。 |
| **Database** | 路由去连 **SQL（SQLite、Postgres）或 MongoDB**。**驱动（driver）负责查询，模型（model）负责成形，schema 负责校验**——数据至此才真正持久。 |

```js
const express = require('express');
const app = express();

app.use(express.json());

app.get('/api/notes', (req, res) => {
  res.json([{ id: 1, text: 'Hello' }]);
});

app.post('/api/notes', (req, res) => {
  // create a note in the database…
});
```

三行值得停下来：`app.use(express.json())` 是**中间件**（在这里做"解析 JSON 请求体"这一件可复用的事），`res.json([...])` 对应响应头里的 `Content-Type: application/json`，而 `POST` 那条路由的注释里那句 "create a note in the database" 就是**第二跳**（[[三层架构]] 里的 SQL query）。

按 [[课程场景与阅读约定]] 约定的「示例站」（那张假想的课程主页：顶部 `header` + 导航 `nav` + `main`（课程表格 + 报名表单 + 配图）+ `footer`），这个 REST 层会长成这样：

| 方法 | 路径 | 对应示例站上的什么 | 对应 CRUD |
|---|---|---|---|
| `GET` | `/api/courses` | 课程表格的数据来源 | Read |
| `GET` | `/api/courses/comp3421` | 单门课的详情 | Read |
| `POST` | `/api/signups` | 报名表单提交后写库 | Create |
| `PUT` | `/api/signups/1` | 改一条报名记录 | Update |
| `DELETE` | `/api/signups/1` | 撤回报名 | Delete |

这张表就是 [[HTTP与URL]] 里那张 HTTP 动词表，在真实资源上的落法。

## Part III — 高级集成

| 课件的四个词 | 原文要点 |
|---|---|
| **WebSocket** | 一条**持久的、全双工（full-duplex）**连接——**服务器任何时候都能推更新，不只是被问到时**。它**以 HTTP 起步，然后升级（upgrades）**。 |
| **Real-time** | 聊天、实时比分、协同编辑。**Socket.IO** 在 WebSocket 外面包了房间（rooms）、重连与回退。 |
| **SPA** | **单页应用**——只有一个 HTML 页面，**JavaScript 换视图**：取数据、重新渲染，**不再整页刷新**。 |
| **Deployment** | 同一个 Node 应用**发到云上**——静态站放 Netlify/Vercel，服务器放 Render/Fly，外加一个**真实域名与 HTTPS**。 |

课件给的三行，分别是这四件事的最小形态：

```js
// server pushes a message — client just listens
const ws = new WebSocket('wss://chat.example.com');
ws.onmessage = (ev) => renderMessage(ev.data);

// SPA — swap the view without reloading the page
history.pushState({}, '', '/notes');  renderView();

// deploy — push to git, the cloud builds and serves
git push origin main   →   auto-deploy
```

> [!note] 为什么 WebSocket 值得单独一个 Part
> [[三层架构]] 那个"请求进、应答出"的循环里，**服务器永远是应答方**。WebSocket 是课件里**唯一**打破这一点的技术：它**始于 HTTP**（所以不必新发明握手），然后升级成一条服务器能主动开口的通道。理解这一句，"实时"就不是玄学。

## Part IV — 性能与优化

| 课件的四个词 | 原文要点 |
|---|---|
| **Caching** | **把答案留在近处**：`Cache-Control` 头、ETag、服务端缓存（Redis）——**回访时跳过重复计算**。 |
| **CDN** | **内容分发网络**——把静态文件的副本放在**全世界的边缘服务器**上，从**离每个用户最近的那一个**发出。 |
| **HTTP/2 与 HTTP/3** | **多路复用（multiplexing）**——一条连接上跑很多请求；**头部压缩**；HTTP/3 进一步走 **QUIC/UDP**。 |
| **Measure first** | **Lighthouse 和 Network 面板给你数字**——**按数据优化，不按猜测优化**。 |

```http
Cache-Control: max-age=86400
```

```html
<!-- CDN — serve static files from the nearest edge -->
<script src="https://cdn.example.com/app.js"></script>
```

```http
GET /style.css   GET /app.js   GET /logo.png  (in parallel)
```
