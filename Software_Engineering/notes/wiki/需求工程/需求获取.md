# 需求获取 · Requirements Elicitation

> **一句话**：需求获取是**技术人员与利益相关者协作**，以理解应用领域、工作活动、服务、期望的系统功能及相关方面的过程。它采用**螺旋式**的四阶段，并有一套核心技术与一批"难缠"的挑战。

课件原文见 [04. Requirements Engineering](<../../raw/04. Requirements Engineering.pdf>)。上位见 [[需求工程-定义与过程]]。

## 什么是利益相关者 · Stakeholder

**利益相关者 = 可能影响、被影响，或自认为会被某个项目的决策、活动或结果影响的个人、群体或组织。**

| 类型 | 说明 |
|---|---|
| **主要用户** Primary users | **每天实际使用**这个软件的人 |
| **次要用户** Secondary users | 不直接使用，但**为其供数据或依赖它**（如供应商、管理者） |
| **领域专家** Domain experts | 懂得业务规则（定价、法律、工作流、例外情况） |
| **监管机构** Regulatory bodies | 政府与法律约束。**不可协商**，且**常被遗忘** |
| **项目的反对者** Opponents to the project | 存在但常未被纳入分析 |

## 螺旋式的四个阶段

需求获取是**迭代过程**，可用**活动的螺旋**表示：

| # | 阶段 | 英文 |
|---|---|---|
| 1 | **需求发现与理解** | Requirements discovery and understanding |
| 2 | **需求分类与组织** | Requirements classification and organization |
| 3 | **需求优先级排序与协商** | Requirements prioritization and negotiation |
| 4 | **需求文档化** | Requirements documentation |

> **螺旋的含义**：走完一圈不是结束，而是带着**更精确的理解**进入下一圈。每一圈都会发现新的利益相关者和新的需求。

## 核心技术

| 技术 | 英文 | 一句话 |
|---|---|---|
| **访谈** | Interviews | 与人一对一深入交谈 |
| **观察** | Observation | 在自然环境中**观看真实的工作** |
| **问卷** | Surveys | 问**很多人同样的问题** |
| **原型化** | Prototyping | 展示一个**模型**，让人对具体的东西作出反应 |
| **头脑风暴** | Brainstorming | 群体**快速**产生想法 |
| **文档分析** | Document analysis | 阅读**已在使用的手册与表单** |

## 两种主要技术的细部

### 访谈 · Interviews

与 People **一对一、深入地交谈**。

- **开放式访谈 Open interview**：**无固定脚本或议程**，用**开放式问题**
- **封闭式访谈 Closed interview**：**预定义的封闭式问题**集合
- 多数需求访谈**混合**使用：开放问题用于**探索**，封闭式问题用于**确认**

**强项**：深入理解上下文与理由 · 答案出人意料时可**追问** · 为**整个项目**建立融洽关系与信任

**弱项**：**耗时**（进行、记录、分析都耗时） · 答案会被**访谈者与受访者的偏见**塑造

### 观察 · Observation

**民族志（Ethnography）**：在用户的**自然环境中观看他们做真实工作** —— **不打断他们**。

**强项**：

- 人们**不必解释或表述**自己的工作
- **相对便宜**
- 观察者能获得对工作的**实践性洞察**，可观察到重要的**社会与组织因素**

**弱项**：

- 参与者**可能被打扰**
- 参与者**可能改变工作方式**，导致观察者**看不清全貌**
- **基于知识的活动难以观察**
- 对**发现更广泛的组织或领域需求**、以及**提出创新**而言**并不有效**

> [!tip] 观察的定位
> 观察擅长回答"**他们实际怎么做**"，不擅长回答"**整个领域需要什么**"。后者要用访谈与文档分析补足。

## 更根本的挑战

> [!warning] "更快的马"问题
> **利益相关者常常描述的是表层解决方案，而不是根本问题。**
>
> 需求获取因此像一艘**潜到水平线以下**的潜艇 —— 冰山模型中**陈述出来的需求只占约 10%**，**实际需要占约 90%**。后者包括**业务逻辑、变通做法（workarounds）、政治因素、未言明的期望**，即**没有人说出口的那一部分**。

除此之外：

- **利益相关者不知道他们真正想要什么。**
- 利益相关者**用自己的术语表达需求**，并带有**其工作的隐含知识**。
- **不同利益相关者**带着**多样的需求**，且**表达方式各不相同**。
- **组织与政治因素**可能影响系统需求。
- 需求在**分析过程中持续变化**：**新的利益相关者会出现**，业务环境也会变化。
