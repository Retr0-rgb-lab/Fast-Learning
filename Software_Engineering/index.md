# 系统工程知识库 · System Engineering MOC

> COMP3211 Software Engineering 课程知识库。按 **主题**组织（不按讲次），所有笔记通过 Obsidian **双链（wikilink）** 互联。
> **每篇笔记都是自足的** —— 单独打开任何一篇都能读懂，不需要回忆课件里的例子。

## 使用方式

- **按主题浏览** → 看下面的 [[#四大模块]]
- **零散复习** → 直接打开 `notes/wiki/<主题>/` 下任意一篇，每篇末尾的「关联」列出它的邻居
- **查原始出处** → `notes/raw/` 下四份课件 PDF 的纯文本转写
- **做练习** → 另见 `E:\College_Projects\SE\review\test1.ipynb`

## 四大模块

### 软件过程 · Software Processes

回答"开发软件这件事本身该怎么组织"。

- [[软件过程-定义]] — 过程是什么、描述三要素、plan-driven vs. agile
- [[软件过程-四活动]] — 规格 / 开发 / **V&V** / 演化
- [[瀑布模型]] — 五阶段、为何难以应对变更、三类适用系统
- [[增量开发]] — 增量 ≠ 交付、冻结规则、架构退化风险
- [[复用式软件工程]] — 三类可复用件、失去演化控制这个代价
- [[应对变更]] — **moving target**、anticipation vs. tolerance、原型化两种策略
- [[过程成熟度模型]] — **Performance / Capability / Maturity**、**CMMI 五个等级**、QA

### 敏捷开发 · Agile

回答"计划驱动太重时，用什么替代"。

- [[敏捷宣言与原则]] — 来由、**Manifesto 四条**、**五原则**、适用性与局限
- [[用户故事]] — 格式、**Three C's**、"不是系统需求"这个后果
- [[重构]] — **design for change** 的对立面
- [[测试驱动开发]] — 先写测试、自动化、客户参与、三个困难
- [[结对编程与集体所有]] — 收益、**XP 十项实践全表**
- [[Scrum]] — 三阶段、sprint 循环、**八个术语**、收益

### 需求工程 · Requirements Engineering

回答"要建的东西是什么、怎么记下来、怎么确认没记错"。

- [[需求工程-定义与过程]] — 三个通用活动、**迭代交错**
- [[用户需求与系统需求]] — 两层需求的**七维对照**
- [[功能需求与非功能需求]] — **可验证 NFR**、十二类度量
- [[需求获取]] — **四阶段螺旋**、利益相关者、核心技术、**"更快的马"**问题
- [[需求规约]] — 四种记法、自然语言的五类问题、**shall/should**、rationale
- [[软件需求规格说明书]] — **SRS 十章结构**、WHAT not HOW
- [[需求验证]] — **五种检查**、三种技术、验证的局限
- [[需求跟踪矩阵]] — **向前/向后追踪**、影响分析

### 系统建模 · System Modelling

回答"怎么把系统画清楚"。

- [[系统建模-定义与视角]] — **四个视角**、模型的三种变化维度
- [[UML概览]] — **14 种图**、用途决定完整度
- [[类与对象]] — Class ≈ Type、类的记号
- [[类之间的关系]] — **依赖 / 关联 / 泛化 / 实现**、多重性读法
- [[聚合与组合]] — **实心 vs. 空心**、**判据是生命周期不是多重性**
- [[用例建模]] — actor、五种关系、**`<<include>>` vs. `<<extend>>`**
- [[顺序图]] — 生命线/激活/帧、loop / opt / alt
- [[行为模型]] — **data-driven vs. event-driven**、状态图、超状态
