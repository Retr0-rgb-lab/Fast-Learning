# 进程映像与线程

> **一句话**：**进程映像（process image）** 是一个进程在内存里占的那一整套东西 —— 代码、堆、栈、寄存器。**线程就是把这套东西切开：多个线程共享"代码和数据"，但各有各的"寄存器和栈"。** 共享的那部分让它们通信便宜，独占的那部分让它们能同时跑。

课件对应 L02 p7–p16。课件原文见 [02-Unix-Processes](<../../raw/02-Unix-Processes.pdf>)。

## 完整场景：为什么要在进程里面再切一刀

[[进程是什么]] 讲到，进程是"用到的资源 + 这些资源的状态"。**问题是：一个进程往往用不完整个机器。**

假设你写了个图形界面程序，同时要：刷新界面、下载文件、播放音频。**三个活可以同时进行**。

如果做成三个**进程**：它们要各自申请一份完整的内存（代码、库、堆），内存浪费，而且互相传数据麻烦。

**线程就是答案** —— 把一个进程拆成几个执行流，让它们**共用**那份内存。

## 一、线程的定义（p7）

课件 p7 把状态拆成"共享什么"和"独占什么"两份：

> *"A process is the time sequence of $\{s(e,i)\}$"*（见 [[进程是什么]]）

而在 p7–p13 里，课件反复用同一个句式画出线程的画面：**两个线程共享 computer resources，各自有自己的东西。**

### 课件给的资源清单（p11–p13）

课件 p11 把资源分成两组，这是**本篇的核心表格**：

| | 资源 | 说明（课件原文） |
|---|---|---|
| **共享** | 内存存**公共代码** | *"Memory to store common code（e.g. **common library code, such as printf**）"* |
| **共享** | 内存存**公共数据** | *"Memory to store common data（e.g. **global/static variables, heap, command line arguments, environment variables**）"* |
| **共享** | 内存存**共享的外设资源** | *"Memory to store shared peripheral resources（e.g. **file meta info and content**）"* |
| **独占** | **寄存器** | *"Registers"* |
| **独占** | **栈** | *"Stack（memory to store each function call's **local variables**）"* |
| **独占** | 内存存**线程专属代码** | *"Memory to store **thread specific code**"* |

**共享的三样**：公共代码、公共数据（含**堆**）、外设资源（**文件**）。
**独占的三样**：寄存器、栈、线程专属代码。

> [!warning] 「堆」在共享那一栏，这是最容易记错的地方
> 直觉上"每个线程有自己的数据"→ 堆应该是独占的。
> 但课件明确把 **heap（堆）** 和 **global/static variables（全局/静态变量）** 归在 **common data（公共数据）** 里。
>
> **含义**：同一进程的多个线程**共享同一个堆**。所以两个线程往 `malloc` 出来的对象里写东西会互相干扰 —— **共享内存的线程必须自己做同步**（互斥锁等）。

## 二、一张图看懂共享与独占（p8–p16）

课件用同一个版式画了六页（p8–p16），每页只是挪动几个元素。对应现实就是：

```
        ┌─────────── 进程 ───────────┐
        │                            │
        │  ┌──────────────────────┐  │
        │  │  共享：公共代码       │  │  ← printf 之类的库代码
        │  │         （全部线程一份）│  │
        │  ├──────────────────────┤  │
        │  │  共享：公共数据       │  │  ← 全局变量、静态变量、堆、命令行参数、环境变量
        │  │         （全部线程一份）│  │
        │  ├───────────┬──────────┤  │
        │  │ 共享：文件 │ 共享：文件│  │  ← 文件元信息与内容
        │  ├───────────┼──────────┤  │
        │  │ 独占：栈   │ 独占：栈  │  │
        │  │  线程 1    │  线程 2   │  │  ← 各自函数调用的局部变量
        │  ├───────────┼──────────┤  │
        │  │ 独占：寄存器 │ 独占：寄存器│  │  ← 程序计数器、栈指针…
        │  └───────────┴──────────┘  │
        └────────────────────────────┘
```

**记忆锚点**：

| | 谁用 |
|---|---|
| 代码、数据、文件、**堆** | **共用一份** —— 便宜，但要自己同步 |
| **栈**、**寄存器** | **各有一份** —— 天然隔离，所以能并行 |

> [!tip] 为什么这个划分能同时给出"通信便宜"和"能并行"
> - **能并行**：寄存器是 CPU 的执行现场，两个线程各有自己的现场 ⇒ 可以各自停在不同地方 ⇒ 真正并发
> - **通信便宜**：代码和数据在同一片内存里，一个线程写的数据另一个线程直接就能读到 ⇒ **不需要任何 IPC 机制**
>
> 对比 [[../重定向与管道/管道与进程间通信|管道]] 那种跨进程通信：要开管道、要写代码同步、要在内核态和用户态之间来回搬数据。**线程内通信只是"读另一个地址"。**

## 三、进程映像 Process Image（p15、p16）

"进程映像"这个术语在 p15/p16 被正式给出，**它就是上面那张图在单个线程视角下的完整样子**。

### 映像包含什么

课件 p15/p16 的图里列出的部分（合并 p11–p13 的清单）：

| 组成部分 | 多个线程时 |
|---|---|
| **公共代码** memory to store common code | 共享 |
| **公共数据**（全局/静态变量、堆、命令行参数、环境变量） | 共享 |
| **共享外设资源**（文件元信息与内容） | 共享 |
| **栈**（函数调用的局部变量） | **独占** |
| **寄存器** | **独占** |
| **线程专属代码** memory to store thread specific code | **独占** |

> [!note] 为什么这个清单里没有"程序计数器"单独一项
> 程序计数器（PC，program counter）**就是寄存器之一** —— 它是 CPU 用来记住"下一条该执行哪条指令"的那个寄存器。
> 线程切换时保存/恢复 PC，是"线程各有各的寄存器"最直接的体现。

### 映像是"内存视图"，不是"一个地址"

> [!warning] 一个常见误解：进程映像 = 一个连续的内存块？
> **不是。** 上面这些部分**散布在不同的位置**：代码段和数据段由**操作系统在加载时装配**，栈在**进程自己生长**，寄存器根本**不在内存里**（在 CPU 上）。
>
> 所以"进程映像"是**逻辑概念**，指"这个进程占用的全部资源"，**不是一个地址范围**。

## 四、线程只是概念，实际实现各有各的（p14）

课件 p14 是本讲**最重要的一段提醒**，原话：

> *"All the previous slides on thread are just **conceptual guidelines**."*
> （前面所有关于线程的幻灯片都只是**概念性指引**。）

> *"But different OSs（**even OSs belonging to the Unix family**）have **different ways to realize the concepts** and the **PThread programming interface**."*
> （但不同的操作系统（**即使是 Unix 家族内部的操作系统**）**实现这些概念的方式不同**，**PThread 编程接口**也不同。）

**这句话的意思**：前面那张"共享/独占"的图，是**所有 Unix 都应该表现成的样子**，**不是任何一个 Unix 的实际内存布局**。

### 编程接口：PThread

**PThread（POSIX Threads）** 是 Unix 上多线程的标准编程接口。名字里的 **P** 就是 **POSIX** —— 和 [[../Unix 总览/Unix 是什么与由来|Unix 是什么与由来]] 里的 POSIX 标准是同一套体系。

> [!note] 本课程的覆盖范围
> 课件 p14 **点名了 PThread 但没有展开** —— 没有讲 API、没有代码。本目录没有 PThread 的专题笔记，属于已知缺口。

### Linux：已经不区分线程和进程了（p14）

课件 p14 的最后一句非常值得记：

> *"For example, **modern Linux no longer differentiates threads and processes**, all are realized as **copy-on-write**..."*
> （例如，**现代 Linux 不再区分线程和进程**，**全部都实现为写时复制（copy-on-write）**……）

> [!warning] 这句话的份量：它推翻了前面那张图的一部分
> 前面说"线程共享一份堆和代码" —— **在现代 Linux 上，实际情况不是"共享"，而是"各自有一份、但在你去写之前两边都指向同一份物理内存"**。
>
> 这就是 **copy-on-write（COW，写时复制）**：
> ```
> fork() 之后：
>   子进程的虚拟地址空间和父进程**长得一模一样**
>        ↓ 但没有任何一份数据被真的复制 —— 两边共用同一批物理页
>        ↓ 谁先写，谁触发真正的复制；没写的那边继续共用
> ```
>
> **结果是"看起来共享、实际隔离"** —— 既拿到了线程的通信便宜，又拿到了进程的隔离安全。
>
> 这个机制正是 [[../进程管理/fork 创建进程|fork]] 的实现基础，见该篇。

## 五、共享与独占的对照速查

| 资源 | 多线程之间 | 会不会打架 |
|---|---|---|
| 公共代码（库代码） | **共享** | ❌ 只读，不打架 |
| 全局变量 / 静态变量 | **共享** | ⚠️ **会** —— 需同步 |
| **堆** `malloc` 的内存 | **共享** | ⚠️ **会** —— 需同步 |
| 命令行参数、环境变量 | **共享** | ⚠️ **会** |
| 文件元信息与内容 | **共享** | ⚠️ **会** —— 需同步 |
| **栈**（局部变量） | **独占** | ✅ 不打架 |
| **寄存器**（含 PC） | **独占** | ✅ 不打架 |

> [!tip] "会打架"那几行就是需要互斥锁的地方
> 判断标准很简单：**这块内存是不是同一个进程的多个执行流都在用？**
> - 是 → **共享** → 要同步
> - 否 → **独占** → 天然安全
>
> 函数里的局部变量在栈上、独占 ⇒ **不需要加锁**，这就是为什么"把变量放局部"比"放全局"在多线程下更安全。

## 一句话

> 进程映像 = 代码 + 数据 + 堆 + 文件（**共享**）+ 栈 + 寄存器（**独占**）。**线程就是把这份映像切成共享部分和独占部分**：共享部分让通信变便宜，独占部分让执行真正并行。
