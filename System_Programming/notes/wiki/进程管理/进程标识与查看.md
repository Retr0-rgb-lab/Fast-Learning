# 进程标识与查看

> **一句话**：内核给每个进程记一份**元数据**，最重要的是三个整数 —— **PID**（自己是几号）、**PPID**（我爹是谁）、**UID**（我是谁的用户）。进程之间组成**父子树**。用 `ps -l` 能把它们全列出来。

课件对应 L02 p17–p20。课件原文见 [02-Unix-Processes](<../../raw/02-Unix-Processes.pdf>)。

## 完整场景：为什么需要这些号码

[[进程是什么]] 讲到，内核会为每个进程创建一个"进程结构实例"来**记录该进程的信息**。**这一篇就是那份记录里最核心的几个字段。**

先说清楚它们各自解决什么问题：

| 问题 | 用哪个字段回答 |
|---|---|
| 这个进程**自己**是第几个？ | **PID** |
| 这个进程**是谁创建的**？它出错了该找谁？ | **PPID** |
| 这个进程**属于哪个用户**？它能碰哪些文件？ | **UID** |

## 一、进程的层级：父子关系（p17）

课件 p17 的原话：

> *"Besides its image, a process has its corresponding **meta data（in kernel）** for the OS to manage it, e.g. **process ID**."*

**"Besides its image"** 是个关键区分 —— 进程有**两样东西**：

| | 在哪 | 是什么 | 笔记 |
|---|---|---|---|
| **映像 image** | **用户态内存**（进程自己能用） | 代码、数据、堆、栈 | [[进程映像与线程]] |
| **元数据 meta data** | **内核里**（进程**碰不到**） | PID、PPID、UID 等 | **本篇** |

> [!warning] 元数据在"进程碰不到的地方"，这一点很重要
> 进程**无法修改自己的 PID 或 UID** —— 这些字段在内核空间。
>
> 这带来一个实际后果：**代码不能假设"我知道我的 UID"**。想知道自己是谁，只能**问内核**（调 `getuid()`），而不是读一个全局变量。
>
> 这也呼应了 [[../Unix 总览/Unix 的特性]] 里"内核在特权模式"的架构。

### 父子关系

> *"A Unix OS typically maintains a **hierarchy of processes** related by **parent-child links**: the process that **requests to create** another process is called the **parent process**, the created process is called the **child process**."*
> （Unix 系统通常维护一个通过**父子链接**关联的**进程层级**：**请求创建**另一个进程的那个进程叫**父进程**，被创建出来的那个叫**子进程**。）

**关系的建立方式**：**由提出创建请求的一方**当爹。所以"父子关系"= **创建关系**，不是"谁启动谁"。

```
init (PID 1)
 ├── bash (你的登录 shell)
 │    ├── vim
 │    └── ls
 └── sshd
      └── bash (另一个会话)
```

> [!note] 顶层那个 `init` 是谁
> 课件 p17 只说"maintains a hierarchy"，**没有展开 `init`**。上面这张树是按 Unix 惯例补的示意，课件里没有对应文字。
> 可以确定的是：**树根的 PPID 不指向任何还活着的进程**（否则它就不是根），这条性质会在 [[../进程管理/wait 等待子进程|wait 等待子进程]] 的孤儿进程一节起作用。

## 二、三个关键字段（p18）

课件 p18 逐个给出：

### PID — Process ID

> *"Process ID – integer **PID**"*

**进程自己的编号，整数。**

> [!tip] PID 是唯一的，但不是永久的
> [[进程是什么]] 第 2 步说创建进程时会"分配一个**唯一的**进程 ID"。**唯一是指"当前活着的进程之间不重复"**，不是"永久占用"。
>
> 进程死了之后，**它的 PID 会被回收、可以分给新进程**。所以：
> - 你在日志里看到一个 PID，**过一段时间可能已经是另一个进程了**
> - 看到"找不到该 PID"可能是**进程已退出**，也可能**PID 被复用了**
>
> 排查线上问题时这一点很要紧。

### PPID — Parent Process ID

> *"Parent process ID – an integer **PPID**"*

**父进程的 PID。** 由上面的父子层级决定。

**最典型的一个 PPID**：你在终端敲命令时，**创建命令进程的那个进程就是你的 shell**。所以一条命令的 PPID 通常是那个 bash 的 PID。见 [[../进程管理/fork 创建进程|fork]]。

### UID — User process ID

课件 p18 的解释分两层：

> *"In Unix, **each user has a unique user ID**. Each process is associated with a particular user called the **owner of the process**, which executes the program. The **owner has certain privileges with respect to the process**."*
> （在 Unix 里，**每个用户有一个唯一的用户 ID**。每个进程都关联到某个特定的用户，称为这个进程的**所有者**。**所有者对这个进程拥有某些权限**。）

**这个字段和文件权限是同一套体系** —— 进程的 UID 决定它能打开哪些文件，见 [[../文件系统结构/权限位与 ls -l|权限位与 ls -l]]。

> [!warning] "owner has certain privileges" 的实际含义
> 进程能做什么，**不是由"这个程序是谁写的"决定，而是由"谁启动它"决定**。
>
> 一个 setuid 程序可以让**任何用户**都以**文件所有者的权限**运行它 —— 这是 Unix 的经典提权机制，也是历史上大量安全漏洞的来源。
> **课件 L01–L03 没有讲 setuid，属于已知缺口**，但它是理解"进程的 UID 从哪来"的关键补充。

## 三、用 ps 查看（p19）

课件 p19 给了三条命令，逐条拆解。

| 命令 | 课件原文 | 拆解 |
|---|---|---|
| `ps` | *"lists your **current processes**"* | 列出**你自己**的进程 |
| `ps -a` | *"lists **more processes**, including ones being run by **other users** and at **other terminals**（but **not include the shells**）"* | 列出**更多**：包括**别的用户**的、**别的终端**上的（但**不包括 shell**） |
| `ps -l` | *"prints **longer, more information lines**, including **UID, PID, PPID, process status**, etc."* | **长格式**，多打印 UID、PID、PPID、进程状态等信息 |

> [!note] `ps` 是 "process status" 的缩写
> 课件 p19 明确写了 *"ps is the short for '**process status**'"*。

### `ps -l` 输出各列的含义

课件 p19 只列了 UID / PID / PPID / process status 四项。**完整的 `ps -l` 输出通常还有更多列**（如 `S` 状态码、`NI` 优先级、`TTY`、`TIME`、`CMD`）—— **课件未展开，属于已知缺口**。

本目录只按课件给的这四列来解释，不补充未讲的内容。

## 四、用 API 查询（p20）

课件 p20 给了完整代码：

```c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

void main(void){
    printf("Process ID: %ld\n",      (long)getpid());
    printf("Parent proces ID: %ld\n",(long)getppid());
    printf("Owner user ID: %ld\n",   (long)getuid());
}
```

### 三个函数对应三个字段

| 函数 | 返回 |
|---|---|
| `getpid()` | **PID** — 本进程 |
| `getppid()` | **PPID** — 父进程 |
| `getuid()` | **UID** — 本进程所有者 |

### 课件那条必须注意的注解（p20）

> *"Note: under POSIX, the returned type **`pid_t` may be either an `int` or a `long`**"*
> （注意：在 POSIX 下，返回类型 **`pid_t` 可能是 `int` 也可能是 `long`**）

**这就是上面代码里那些 `(long)` 强转的由来。**

> [!warning] 这个坑非常常见
> 课件代码写的是：
> ```c
> printf("Process ID: %ld\n", (long)getpid());
> ```
> `getpid()` 真正的返回类型是 **`pid_t`**，而 `pid_t` 是 **实现定义的**：在你的系统上可能是 `int`，也可能是 `long`。
>
> **如果你直接写 `printf("%d", getpid())`**：
> - 系统上 `pid_t` 是 `int` → 恰好正确
> - 系统上 `pid_t` 是 `long` → **`%d` 按 4 字节读，参数却是 8 字节传的 → 打印出垃圾值或崩溃**
>
> **这就是"同源代码、跨平台"为什么需要这种看起来多余的强转。** 也是 [[../Unix 总览/Unix 是什么与由来|可移植性]]在代码层面的一个具体体现。

## 五、三个字段的关系小结

| 字段 | 读法 | 谁填的 | 变化时机 |
|---|---|---|---|
| **PID** | 我是几号 | 创建时由内核分配 | **永不改变** |
| **PPID** | 我爹是几号 | 创建时由内核填（= 父进程的 PID） | **永不改变** |
| **UID** | 我属于谁 | 创建时继承 + 可能被 `setuid` 改 | 可被特权程序改变 |

**共同点**：三者都**在创建时确定、存在内核、进程自己改不了**。

> [!note] PPID 也有"变化"的情形
> 严格说 PPID 本身不变，但**父进程一旦退出，进程的"父亲"就没了** —— 这时它成了孤儿进程，随后通常被**过继**（re-parent）给别的进程（通常是 PID 1）。
>
> 细节见 [[../进程管理/wait 等待子进程|wait 等待子进程]] 的孤儿进程一节。

## 一句话

> 内核给每个进程记三个关键整数：**PID**（自己）、**PPID**（创建者）、**UID**（所有者）；父子关系是**创建关系**，用 `ps -l` 查看、用 `getpid`/`getppid`/`getuid` 查询，**注意 `pid_t` 可能是 `int` 也可能是 `long`**。
