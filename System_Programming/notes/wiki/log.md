## 三层抽象这条主线

三讲被串成一条线，写进 `index.md` 的 mermaid 图：

- **L01 · 谁在管** —— Shell 指挥 Kernel 指挥硬件；凡是需要知道硬件细节的地方都被关在设备驱动里
- **L02 · 动的东西怎么生灭** —— 进程 = 程序的一次执行；`fork` → `exec` → `wait` → 终止
- **L03 · 不动的东西怎么寻址和读写** —— 名字 → inode → 数据块；fd → SFT → inode

**三讲共享同一个内核概念体系**（系统调用、特权态、设备驱动），所以 L01 讲的机制会在 L02/L03 被具体用到，反之亦然。跨讲引用因此非常多。

## 整理原则

沿用 `AGENTS.md` 的全库约定：

- **场景不预设**：所有例子从零完整解释。例如
  - `fork` 之后两个进程**各自看到什么**、为什么输出顺序不可预测（课件 p22–p25 用 `sleep(1)` 稳定顺序）
  - `cp /etc/passwd /dev/tty` 为什么会打印到屏幕而不是生成文件（课件 p10 的 demo）
  - `mv ../file1 .` 里那个 `.` 到底指什么（课件 p13 的原文例子）
  - name resolution 逐级查表的**完整 5 步**（课件 p33 只给了定义）
- **每篇自足**：课件页码只作溯源标注
- **术语中英对照**：inode/i-number/i-node、fd/SFT、fork/exec/wait、pipe/dup
- 每篇都有 `domain` / `course` / `lecture` / `source`，指回 `notes/raw/` 的具体 PDF
