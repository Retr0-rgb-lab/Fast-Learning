# 当前工作目录

> **一句话**：**每个进程都挂着一个"当前工作目录"（cwd）**，记作 `.`。**相对路径就是从这里开始数的**。Shell 的 cwd 通常是**家目录（home directory）**，`pwd` 打印它，C 函数 `getcwd()` 查它。

课件对应 L03 p13–p14。课件原文见 [03-Unix-File-System](<../../raw/03-Unix-File-System.pdf>)。

## 完整场景：为什么每个进程都要有 cwd

**先把问题摆出来。** 考虑这段操作：

```bash
$ ls notes.txt      # 报了 "No such file or directory"
```

**这个报错的意思不是"这个文件不存在"，而是"在这个目录下没找到"。** Unix 的 `open("notes.txt")` 之类的调用默认**从当前目录开始找**。

所以"当前在哪个目录"是**每个进程都要记的状态** —— 见 [[进程是什么]] 第 4 步"分配运行所需的资源"。

## 一、cwd 的定义（p13）

课件 p13 的三条表述：

> *"At anytime, **every process has an associated directory** called the **current working directory**（**cwd**）."*
> （在任意时刻，**每个进程都关联一个目录**，称为**当前工作目录**（**cwd**）。）

> *"Denoted by a dot `'.'`*, e.g., `"mv ../file1 ."`."*
> （**用一个小点 `'.'` 表示**，例如 `"mv ../file1 ."`。）

> *"The cwd associated with **a user's login shell** is called the user's **home directory**. `pwd` prints the name of the cwd."*
> （与**用户登录 shell** 关联的 cwd 称为用户的**家目录**。**`pwd`** 打印 cwd 的名字。）

### 四个要点

| 要点 | 内容 |
|---|---|
| **每个进程都有** | 不是每个用户、不是每个终端，是**每个进程** |
| **记作 `.`** | 单个小点 |
| **登录 shell 的 cwd = 家目录** | 这是你登录后所在的位置 |
| **`pwd` 打印它** | *print working directory* |

> [!tip] "每个进程都有 cwd" 和 "家目录" 的关系
> 这两条不矛盾：
> - **每个进程**都有自己的 cwd（通常**继承自父进程**）
> - **只有登录 shell 那个** cwd 初始是**家目录**
>
> 你在 shell 里跑一个程序，那个程序的 cwd **就是 shell 的 cwd**（除非程序自己 `chdir` 了）。
> 这就是为什么 [[../进程管理/fork 创建进程|fork]] 出来的子进程**自动就在对的目录里** —— 它继承了父进程的 cwd。

### `mv ../file1 .` 这个例子（p13 原文）

课件用这个命令说明 `.`：

```bash
mv ../file1 .
```

拆开看三部分：

| 部分 | 含义 |
|---|---|
| `../file1` | **源**：到**父目录**找 `file1` |
| `.` | **目标**：**当前目录** |
| 作用 | 把父目录的 `file1` **移进当前目录** |

**这条命令恰好体现了"`.` 就是 cwd"**：目标写 `.` 就等于"移到我所在的地方"。

> [!warning] `.` 和 `..` 在目录里是真实存在的条目
> 它们不只是"符号写法" —— **每个目录里都有两个真实的文件条目**，名字分别叫 `.` 和 `..`。
> `..` 的实现方式是**它的 i-number 指向父目录的 inode**，见 [[../inode 与链接/inode 与目录文件|inode 与目录文件]]。
>
> **后果**：即使当前目录被别人删掉了，`pwd` 仍可能返回一个**已经不存在**的路径 —— 因为 cwd 指向的是 inode，目录被删了 inode 还在（直到没有进程引用它）。**Unix 允许你"待在"一个已被删除的目录里。**

## 二、getcwd：程序里怎么查 cwd（p14）

### 课件给的原型

```c
char *getcwd(char *buf, size_t size)
```

**两个参数各管什么**（课件 p14 的说明）：

| 参数 | 含义 |
|---|---|
| `buf` | **你自己提供的缓冲区**，函数把 cwd 的路径名写进去 |
| `size` | **路径名的最大长度** |

> [!warning] 这个 API 的形状值得留意：它要你自己备缓冲区
> 和 `getpid()` 那种"直接返回一个数"不同，`getcwd` **不分配内存**，它写进你给的 `buf`。
>
> 好处是**不涉及内存分配**，坏处是**你得自己保证 `size` 够大** —— 这就是下一个知识点。

### 失败情形：ERANGE（p14 明确给出）

> *"If longer than the maximum, **returns NULL** and sets **errno to ERANGE**."*
> （如果路径名**比最大值更长**，**返回 NULL** 并把 **errno 设为 ERANGE**。）

**这个失败的现实场景**：cwd 可以**很深**。

```
/home/alice/work/project/build/artifact/v123/final/output
```

**路径名可以是任意长的**（受文件系统限制，但比 `PATH_MAX` 常见值更容易超）。

> [!tip] 这是"健壮"特性的又一次现身
> 见 [[../Unix 总览/Unix 的特性]] 第六条：**失败不 abort，返回错误码让调用方处理。**
> `getcwd` 失败时返回 **`NULL`**（指针类型的失败约定）并设 `errno = ERANGE` —— 和 `open` 返回 `-1` 是同一个模式。
>
> **所以正确写法必须判 NULL：**
> ```c
> char buf[4096];
> if (getcwd(buf, sizeof buf) == NULL) {
>         perror("getcwd");
>         /* 这里 errno == ERANGE，说明 4096 不够 */
> }
> ```

### 课件 p14 的完整例子

课件给了：

```c
#include <unistd.h>
#include <stdio.h>
#include <errno.h>

int main(){
        /* … */
}
```

> [!note] 课件这段代码在 PDF 里不完整
> p14 提取出的代码只到 `int main(){` 之后就没了 —— 剩下的部分（大概是 `getcwd` 调用和输出）**没有出现在课件文本层**。
>
> 本篇只使用课件明确写出的**原型说明**（`buf`/`size`/`NULL`/`ERANGE`），**不补写课件没有的代码**。

## 三、三个概念的关系

把 p13/p14 的内容和别处串起来：

```
        用户的家目录 home directory
                  │  ← 登录 shell 的 cwd 初始位置
                  ▼
        当前工作目录 cwd（记作 "."）
                  │
        ┌─────────┴──────────┐
        ▼                    ▼
   相对路径的起点        程序里 getcwd() 的返回值
   "notes.txt"          "/home/alice/xxx"
   从这里开始找          这是它的绝对路径
```

**三者的关系一句话**：

> **cwd 是一个位置**；**`.` 是它的名字**；**家目录是登录 shell 的 cwd 初始值**；**`getcwd()` 返回它的绝对路径**；**相对路径从它开始算**。

> [!tip] 一个常见困惑：cwd 和 `PWD` 环境变量的区别
> Shell 里敲 `echo $PWD` 也能拿到路径，而且**不用系统调用**。
>
> 区别：
> - **`PWD` 是环境变量**，属于进程的"公共数据"（见 [[../进程与线程/进程映像与线程|进程映像与线程]]）。它是**一份字符串副本**，可能和你**真正所在的目录不一致** —— 比如你手动 `cd` 出去、或者 `PWD` 被程序改坏了。
> - **`getcwd()` 是系统调用**，**直接问内核**"我现在在哪"，**一定准**。
>
> **结论：脚本里判断位置，用 `pwd` / `getcwd`，不要信任 `$PWD` 环境变量。**
>
> ⚠️ **这个区别课件 L03 没有讲**（p13 只提了 `pwd` 命令、p14 只提了 `getcwd`）。上面这段是根据 Unix 通行实践补的，**背景补充**。

## 四、实践要点

| 场景 | 怎么做 |
|---|---|
| 交互式查位置 | `pwd` |
| 程序里查位置 | `getcwd(buf, size)` + 判 `NULL` |
| 引用当前位置 | `.` |
| 上退一级 | `..` |
| 定位脚本自身目录 | `cd "$(dirname "$0")"`（因为 cwd 可能是任意位置） |
| 让脚本行为可预测 | **用绝对路径**，别依赖 cwd |

## 一句话

> **每个进程都挂着一个 cwd**（记作 `.`），**相对路径从这里开始数**；登录 shell 的 cwd 就是**家目录**；`pwd` 打印它，`getcwd(buf, size)` 在 C 里查它，**路径太长则返回 `NULL` 并设 `errno = ERANGE`**。
