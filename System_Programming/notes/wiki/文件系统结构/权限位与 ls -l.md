# 权限位与 ls -l

> **一句话**：`ls -l` 输出的开头有 **10 个字符** —— **第 1 个是文件类型，后 9 个是权限**，按 **user / group / others** 三组、每组 `rwx` 三位排列。9 个字符就是 `$3\times3$。

课件对应 L03 p8–p10。课件原文见 [03-Unix-File-System](<../../raw/03-Unix-File-System.pdf>)。

## 完整场景：先看 `ls -l` 的输出

**不预设你见过 `ls -l`。** 先看它打印什么。

```
$ ls -l
total 12
drwxr-xr-x  2 peleclic  peleclic  4096 Oct  3 12:24  .
drwxr-xr-x  5 peleclic  peleclic  4096 Oct  7 09:37  ..
-rw-r--r--  1 peleclic  peleclic  1234 Oct  6 11:26  notes.txt
-rwxr-xr-x  1 peleclic  peleclic  5678 Oct  6 11:26  run.sh
lrwxrwxrwx  1 peleclic  peleclic    9 Oct  6 11:26  link.txt -> notes.txt
```

**每一行的格式是固定的：**

```
[类型+权限9位]  [硬链接数]  [所有者]  [所属组]  [大小]  [时间]  [名字]
    10          1          1        1       6      12     n
   字符
```

**本篇只讲最前面那 10 个字符**（课件 p8、p9 讲的也正是这两个部分），后面几列课件未逐项展开。

## 一、第 1 个字符：文件类型（p8）

课件 p8 的原话：

> *"For each file you can see **ten characters before the user and group owner**. The **first character** tells us the **type of the file**."*
> （每个文件在用户和组所有者之前有 **10 个字符**。**第一个字符**告诉我们**文件的类型**。）

**常见类型字符**（对照 [[文件类型]] 的三类）：

| 字符 | 类型 | 含义 |
|---|---|---|
| **`-`** | **普通文件 regular file** | 装数据/程序 |
| **`d`** | **目录 directory** | 装文件清单 |
| **`l`** | **符号链接 symbolic link** | 指向别的路径，见 [[../inode 与链接/硬链接与符号链接\|硬链接与符号链接]] |
| **`b`** | **块设备 block special** | 磁盘、CD-ROM |
| **`c`** | **字符设备 character special** | 终端、键盘 |

**对照上面的输出**：`notes.txt` 是 `-`（普通）、目录是 `d`、`run.sh` 是 `-`、`link.txt` 是 `l`。

> [!warning] 判断能不能 `cd` 进去，看的是第 1 位还是第 4 位
> - **`d`** = 这是个目录
> - **`x`**（第 4 位）= **你能不能进入它**
>
> 一个 `d` 开头但你没有 `x` 权限的目录：**你能 `ls` 它（因为有 `r`），但不能 `cd` 进去**。这就是"能列目录、但进不去"的成因。
>
> ⚠️ **这个组合的完整含义，课件 L03 没有讲**（p9 只讲怎么读 9 个字符）。上面这段是根据 Unix 通行语义补的，**背景补充**。

## 二、后 9 个字符：权限（p9）

课件 p9 的原话：

> *"Next **9 characters** represent **access right assignment for user, group, and all**."*
> （接下来 **9 个字符**表示**对 user、group 和 all（所有人）的访问权限分配**。）

**三个字母 `r`、`w`、`x`：**

| 字母 | 全称 | 中文 | 含义 |
|---|---|---|---|
| **`r`** | **r**ead | 读 | 能**读取**内容 / 能**列出**目录里的名字 |
| **`w`** | **w**rite | 写 | 能**修改**内容 / 能**增删**目录里的条目 |
| **`x`** | **eXecute | 执行 | 能**执行**这个程序 / 能**进入**这个目录 / 能取到里面文件的元信息 |

**按三组排列，每组 3 位：**

```
 9 位 = 3 组 × 3 位

      user          group          all（others）
   owner 组       所属组组        其他所有人组
  ┌──────────┐  ┌──────────┐  ┌──────────┐
  │  rwx     │  │  rwx     │  │  rwx     │
  └──────────┘  └──────────┘  └──────────┘
   ↑第2-4字符    ↑第5-7字符     ↑第8-10字符
```

### 完整拆解一个真实例子

取上面输出的 `notes.txt`：

```
-rw-r--r--
 └┬┘└┬┘└┬┘└┬┘
  │  │  │  └── others  = r--  →  其他所有人：可读，不可写、不可执行
  │  │  └───── group   = r--  →  所属组：可读，不可写、不可执行
  │  └──────── user    = rw-  →  所有者：可读、可写、不可执行
  └─────────── type     = -    →  普通文件
```

**读出来是**：**所有者可读写；同组和其他人只可读。**

再看 `run.sh`：

```
-rwxr-xr-x
 └┬┘└┬┘└┬┘└┬┘
  │  │  │  └── others = r-x  →  可读、不可写、**可执行**
  │  │  └───── group  = r-x  →  可读、不可写、**可执行**
  │  └──────── user   = rwx  →  可读、可写、**可执行**
  └─────────── type    = -
```

**读出来是**：**所有者可读写执行；同组和其他人可读、可执行、不可写。**

> [!tip] 权限位最常见的用途：判断脚本为什么跑不起来
> 你写了个 `run.sh`，执行时报 `Permission denied` —— 去 `ls -l` 看**所有者那一组**（前 3 个字符）有没有 `x`。
>
> `x` 位**只对"普通文件 + 可执行内容"才有意义**。给目录加 `x` 是"能否进入"，给数据文件加 `x` 是"能否当程序跑"，**语义完全不同但字母相同**。

## 三、三个"谁"的分组，为什么要有

9 位分成三组，是因为要回答**三个不同的问题**：

| 组 | 问的是 | 为什么单列 |
|---|---|---|
| **user（owner）** | "**文件的拥有者**能干什么？" | 拥有者通常是自己，可以完全控制 |
| **group** | "**和拥有者同组的其他人**能干什么？" | 团队协作：同组人可以互相访问，但不该能改 |
| **all（others）** | "**剩下的所有人**能干什么？" | 陌生人，通常只读 |

**这个分组直接来自"多用户"这个特性**（见 [[../Unix 总览/Unix 的特性]] 第二节）：

```
多用户（每人一个 UID）
      ↓ 需要回答"谁能碰这个文件"
权限位分 user / group / others 三组
      ↓ 每组再细分 rwx
9 个字符
```

**进程能对文件做什么，由进程的 UID 决定落在哪一组** —— 进程的 UID 见 [[../进程管理/进程标识与查看|进程标识与查看]]。

> [!note] 课件 p9 提到"user, group and all"三个词
> 但**没有讲 `chmod` 怎么改**、**没有讲 umask（默认权限）**、**没有讲 setuid/setgid**，也**没有给出实际各组 UID 的数字形式**（`ls -l` 有时显示数字而非名字，那涉及 **NSS / 用户数据库**，见 [[../Unix 总览/Unix 家族与变体|Unix 家族与变体]] 的 POSIX 部分）。
> 这些都属于本目录的已知缺口。

## 四、课件 p10 的 demo：往设备文件"复制"

课件 p10 给了一个演示任务：

```
> cp /etc/passwd /tmp/garbage      ← 复制到一个普通文件
> cp /etc/passwd /dev/tty          ← 复制到终端设备
Demo  Task1
```

**两条命令的区别，正是本篇全部内容的落地：**

| | `/tmp/garbage` | `/dev/tty` |
|---|---|---|
| 第 1 字符 | **`-`** 普通文件 | **`c`** 字符设备 |
| 内容真的存磁盘吗 | ✅ 是 | ❌ **不是** —— 它指向终端驱动 |
| 结果 | 生成一个新文件，内容是 `passwd` 的内容 | **内容被打印到终端上**，不产生文件 |
| 需要什么权限 | 目标目录的 `w` | **设备文件的写权限** |

**这就是"一切皆文件"最直观的一次体现**：`cp` 这个程序**完全不知道**自己往终端写还是往磁盘写，它只是 `open` + `read` + `write`。差别全在内核看到 `/dev/tty` 后走了设备驱动那条路。

> [!warning] 这个 demo 顺带说明了权限的重要性
> 对 `/dev/tty` 的写权限，**不是每个用户都有**。这正是 [[文件类型]] 里说的"device drivers … **protect the devices from unauthorized use**"在用户侧的体现。
>
> 如果人人都能写 `/dev/sda`（整块磁盘），那安全就不存在了。

## 速查表

```
完整格式：  [类型1位] [user3位] [group3位] [others3位]   共 10 字符

类型位：  -  普通文件      d  目录        l  符号链接
         b  块设备        c  字符设备

权限位：  r  读（普通=读内容 / 目录=列名字）
         w  写（普通=改内容 / 目录=增删条目）
         x  执行（普通=可运行 / 目录=可进入）

读法示例：
   -rw-r--r--   普通文件，owner 读写，group 只读，others 只读
   drwxr-xr-x   目录，owner 全权，group 读+进入，others 读+进入
   lrwxrwxrwx   符号链接，权限位多为固定值 rwxrwxrwx（实际权限在目标文件上）
```

## 一句话

> `ls -l` 每行开头 **10 个字符 = 1 个类型位 + 9 个权限位**；9 个权限位按 **user / group / others** 三组、每组 `rwx` 排列，其中 **`x` 对普通文件是"可执行"、对目录是"可进入"**。
