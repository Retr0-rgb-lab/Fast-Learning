# 层次结构与路径名

> **一句话**：Unix 的文件系统是一棵**树** —— **内部节点全是目录、叶节点全是文件**，只有一个根目录 `/`。**路径名**有两种写法：**绝对路径**从 `/` 出发（唯一确定），**相对路径**从当前目录出发（依赖你在哪）。

课件对应 L03 p11–p12。课件原文见 [03-Unix-File-System](<../../raw/03-Unix-File-System.pdf>)。

## 完整场景：树长什么样

**不预设你见过 Unix 的目录结构。** 课件 p11/p12 用的就是这棵树，把它画全：

```
                        /                     ← 根目录（root）
                        │
        ┌───────────────┼───────────────┐
        │               │               │
      dirA            dirB            dirC
        │               │
   ┌────┴────┐     ┌────┴────┐
   │         │     │         │
My1.dat  My2.dat  My1.dat  My3.dat
```

**两个结构事实：**

| 事实 | 含义 |
|---|---|
| **内部节点是目录，叶节点是文件** | 目录里装目录和文件；**文件不能再装东西** |
| **只有一个根** | 所有路径最终都能追到 `/` |

**注意树里有**两个**叫 `My1.dat` 的文件** —— 它们在**不同目录**下，是**完全不同的两个文件**。这一点在下一节会成为关键。

## 一、路径名（p11）

课件 p11 的原话：

> *"A Unix file system has a **hierarchical tree structure** where **internal nodes are directories and leaf nodes are files**."*
> （Unix 文件系统有**层次树结构**，其中**内部节点是目录、叶节点是文件**。）

> *"The **absolute or fully-qualified pathname** **uniquely specifies a file**, e.g. `/dirA/My1.dat` differs from `/dirA/dirB/My1.dat`."*
> （**绝对路径或全限定路径名**能**唯一确定一个文件**，例如 `/dirA/My1.dat` 不同于 `/dirA/dirB/My1.dat`。）

### 两种路径

| | **绝对路径 absolute** | **相对路径 relative** |
|---|---|---|
| 从哪开始 | **从根 `/`** | **从当前工作目录 cwd** |
| 例子 | `/dirA/My1.dat` | `My1.dat` |
| 换个地方还指同一个文件吗 | ✅ **是**（它是"从根数起的完整地址"） | ❌ **不是**（它依赖你在哪） |
| 写法 | **第一个字符是 `/`** | **第一个字符不是 `/`** |

**绝对路径的关键性质就是课件说的 "uniquely specifies"（唯一确定）**：不管你在哪敲 `/dirA/My1.dat`，指的都是同一个文件。

**相对路径的关键性质是它依赖 cwd** —— cwd 见 [[当前工作目录]]。

> [!tip] 相对路径里的两个特殊写法
> | 写法 | 是什么 |
> |---|---|
> | **`/`** | **根目录自己** |
> | **`.`** | **当前目录**（一个点） |
> | **`..`** | **父目录**（两个点） |
>
> `..` 的作用是往上退一级，比如 `../file1` 就是"到父目录去找 `file1`"。

## 二、路径名怎么变成文件（预告）

> [!warning] 这里有个关键问题，课件花了 8 页才回答
> 路径名 `/dirA/My1.dat` 是**一串字符**，文件内容在**磁盘的数据块**里。**中间要经过一条链路：**
> ```
> "/dirA/My1.dat"
>       │  逐级在目录里查名字 → 找到 i-number
>       ▼
> i-number = 230
>       │  拿 i-number 去 inode 表里查
>       ▼
> inode 230
>       │  inode 里记着"数据块在哪"
>       ▼
> 数据块 A, B, C  ← 文件内容
> ```
>
> **三步，各自有独立的一篇笔记：**
> - **目录里存的是"名字 → i-number"** → [[../inode 与链接/inode 与目录文件|inode 与目录文件]]
> - **逐级查名字这个动作** → [[../inode 与链接/名称解析与文件大小上限|名称解析与文件大小上限]]
> - **inode 怎么指出数据块** → 同上

> [!warning] 同名文件是常态，不是异常
> 上面那棵树里有两个 `My1.dat`。它们**是两个不同的文件**，各有各的内容和 inode。
>
> 它们的**名字相同、内容可能完全不同**。所以任何时候都必须说清"**哪个** `My1.dat`" —— 靠的是**完整路径名**。
>
> 这也是为什么 Unix 里 `rm My1.dat` 会让你确认："**你在哪个目录里？**"

## 三、目录自己也是文件（回到 p18 那个特性）

课件 L01 p18 把"层次化文件系统"列为 Unix 的八大特性之一：

> *"Directories are themselves organized into a **tree-like structure**. There is **one master directory**, the so-called **root directory**, from which various sub-directories branch off. The hierarchical structure offers **maximum flexibility for grouping information in a way that reflects its natural structure**."*
> （目录自身组织成**树状结构**。存在**一个主目录**，即所谓的**根目录**，各种子目录从它分叉出去。这种层次结构提供了**最大的灵活性，用来按反映信息自然结构的方式组织信息**。）

### "目录本身也是文件"带来的能力

这句话在 [[文件类型]] 里是"目录文件 vs 普通文件"的区别，在这里的意义是：

```
目录能装目录  →  可以任意深嵌套
目录能装文件  →  叶子
目录有权限    →  见 [[权限位与 ls -l|权限位]]
目录有元信息  →  自己也有 inode
```

> [!note] 目录的 inode 是什么
> 课件 p25–p26 的目录文件示例里，目录自己的条目是：
> ```
> i-number   File name
> 123        .          ← 指向自己
> 247        ..         ← 指向父目录
> 220        dirB
> 230        My1.dat
> ```
> **`.` 和 `..` 是每个目录都有的两个特殊条目**，它们的 i-number 就是实现"当前目录"和"父目录"这两个概念的方式。
> 完整展开见 [[../inode 与链接/inode 与目录文件|inode 与目录文件]]。

### "反映自然结构"的含义

课件用的词是 *"reflects its natural structure"*。举例说明这句话的意思：

| 自然结构 | 对应的目录组织 |
|---|---|
| 一门课有多个讲次，每讲有课件和笔记 | `课程名/讲次N/{课件.pdf, 笔记.md}` |
| 一个项目分前端、后端、文档 | `项目名/{frontend/, backend/, docs/}` |
| 用户的图片按年份分 | `图片/2026/{一月/, 二月/}` |

**目录树是使用者自己设计的语义结构** —— 内核只管"树 + 按名字查找"，**不管你怎么归类**。这正好呼应了本仓库自身的结构（`notes/raw` + `notes/wiki`）。

## 四、相对路径依赖 cwd

**这一节的实践含义**：你在哪个目录，决定了相对路径指哪。

```bash
$ cd /dirA
$ ls My1.dat        # → /dirA/My1.dat
$ cd /dirA/dirB
$ ls My1.dat        # → /dirA/dirB/My1.dat   ★ 同一个命令，不同的文件 ★
```

**所以**：

> [!warning] 相对路径什么时候会咬人
> | 场景 | 后果 |
> |---|---|
> | 脚本里写相对路径，但**脚本的工作目录不确定** | 找错文件或报"No such file" |
> | 别人在你的机器上复现命令 | **同样的命令在他那儿指不同的文件** |
> | 排查问题时看到一条报错路径 | 忘了自己当时 `cd` 到哪了 → 对不上 |
>
> **对策**：脚本里尽量用**绝对路径**，或者先 `cd` 到脚本所在目录再操作。

## 一句话

> 文件系统是一棵**只有一个根 `/` 的树**，内部节点全是目录、叶节点全是文件；**绝对路径**从 `/` 出发因此唯一确定文件，**相对路径**从 **cwd** 出发因此依赖位置；树上**可以出现同名文件**，任何时候都要靠完整路径指明"哪一个"。
