# 文件类型

> **一句话**：Unix 里**磁盘、键盘、屏幕、打印机全都是文件**。文件分两大类 —— **普通文件**装数据/程序，**特殊文件**代表设备；特殊文件再分**块设备**（按块传输，像磁盘）和**字符设备**（按字节流传输，像键盘）。目录本身也是文件。

课件对应 L03 p4–p7。课件原文见 [03-Unix-File-System](<../../raw/03-Unix-File-System.pdf>)。

## 完整场景：三个设备的差别

**先把"设备"这件事讲清楚。** 计算机上有三种本质不同的硬件：

| 硬件 | 数据怎么进出 | 例子 |
|---|---|---|
| **磁盘** | 一次读写一整块（比如 4 KB），你自己指定位置 | 硬盘、SSD、CD-ROM |
| **键盘** | 你按一个键，它来一个字节；**顺序的、没有"位置"概念** | 键盘 |
| **显卡** | 数据往屏幕刷 | 显示器、打印机 |

**如果每种硬件都要一套专门的编程接口**，程序就没法通用了。

## 一、Unix 的方案：设备也是文件（p4）

课件 p4 的表述：

> *"A file is a **container of some information**: data, program."*
> （文件是**某些信息的容器**：数据、程序。）

> *"In Unix, **devices**（disks, tapes, CD ROMs, screens, keyboards, printers, mice, etc.）are **also treated as files**, so as to provide a **unified and device independent interface** to applications."*
> （在 Unix 里，**设备**（磁盘、磁带、CD-ROM、屏幕、键盘、打印机、鼠标等）**也被当作文件**，从而为应用程序提供一个**统一的、与设备无关的接口**。）

> [!tip] 这句话是本讲的核心思想，后面每一节都是它的展开
> **"设备也是文件"** 带来一个巨大的简化：
> ```
> 不用设备也用文件
>        ↓
> 对磁盘和对屏幕，用的是同一套 open / read / write
>        ↓
> 应用程序不需要知道对面是硬盘还是显卡
> ```
>
> 机制上：你在 `/dev` 目录下看到"文件"，内核一看就知道**这不是真的存储着数据，而是指向一个设备驱动**。

## 二、内核怎么屏蔽设备细节（p5）

课件 p5 从程序员和内核两侧讲：

> *"OS provides **system calls** to the programmer for performing **control and I/O to devices**. These system calls are handled by **device drivers**, which **hide the details of device operation** and **protect the devices from unauthorized use**."*
> （操作系统为程序员提供**系统调用**来对设备进行控制和 I/O。这些系统调用由**设备驱动**处理，设备驱动**隐藏了设备操作的细节**，并**保护设备不被未授权地使用**。）

> *"Some OS provides **specific system calls for each type** of supported devices. In contrast, Unix has a **unified set of file-related system calls** that work on **all types of devices**."*
> （有些操作系统为**每种**设备提供**专门的系统调用**。相比之下，Unix 有一套**统一的、与文件相关的系统调用**，可以工作在**所有类型的设备**上。）

**两句话的对照就是本节全部内容：**

| | 其他一些 OS | **Unix** |
|---|---|---|
| 设备访问 | 每种设备一套**专用**调用 | **统一**的文件调用 |
| 程序要写几套代码 | 每种设备一套 | **一套** |
| 差异藏在哪 | 露在调用接口里 | **藏在设备驱动里** |

> [!warning] "protect the devices from unauthorized use" 是权限问题
> 设备驱动不只隐藏细节，还要**防止未授权访问**。
>
> 这条在用户侧对应**权限位**：你能不能打开 `/dev/sda`（整块硬盘）、能不能打开 `/dev/mem`，是由 [[权限位与 ls -l|权限位]] 决定的。
>
> **一个真实的风险**：如果一个文件可写且属于 root，普通用户写了进去，就可能通过设备文件间接操作硬件。**设备文件是提权攻击的经典目标。**
>
> 课件 L03 没有展开设备权限的具体配置，属于背景补充。

## 三、三种文件类型（p6）

课件 p6 的完整清单：

| 类型 | 英文 | 课件原文含义 |
|---|---|---|
| **普通文件** | **Regular file** | *"an ordinary **data/program** file on disk – contains bytes of data/program organized into a **linear array**"* 磁盘上存放数据/程序的普通文件，内容是**线性排列**的字节 |
| **特殊文件** | **Special file** | *"a file **representing a device** – located in the **`/dev`** directory"* 代表设备的文件，**放在 `/dev` 目录下** |
| └ **块特殊文件** | **Block special file** | *"devices transferring info **in blocks or chunks**, just like **disks, CD ROM**"* 按**块**传输的设备，像磁盘、CD-ROM |
| └ **字符特殊文件** | **Character special file** | 课件 p6 的这半句在提取文本里被截断，按上下文指**按字符流**传输的设备 |

**类型之间是什么关系**（这是最容易误解的地方）：

```
文件
├── 普通文件        ← 内容真的存在磁盘上
└── 特殊文件        ← 内容其实在设备里，文件只是个"入口"
    ├── 块设备      ← 磁盘、CD-ROM：按块传，可以随机跳着读写
    └── 字符设备    ← 键盘、终端、打印机：一个字节一个字节地流
```

> [!warning] 字符设备的关键特征是"流"
> **字符设备不能"跳着读"。** 你没法对键盘说"把第 100 个字符给我" —— 字符是一个个**按时间顺序到来**的。
>
> 这解释了 Unix 里读键盘和读文件的代码形式很像、但行为根本不同：代码都调 `read(fd, buf, n)`，但对键盘 `read` 会**等你按键**、按几个给几个（不超过 `n`），**而对文件一定返回你要的 `n` 字节**（除非到文件尾）。
>
> 这也解释了为什么**管道**（[[../重定向与管道/管道与进程间通信|管道]]）两端都是字符设备的形式：**它就是个字节流**。

## 四、普通文件 vs 目录文件（p7）

课件 p7 给了两条对照，这是本节最该记住的：

> *"**Contents**: data/program vs **file info***
> **Operations**: **what can be done** and **who can do them**"*

### 对照表

| | **普通文件** | **目录文件** |
|---|---|---|
| **内容是什么** | **数据 / 程序** | **文件信息** —— 名字到 inode 号的映射表 |
| **能做什么操作** | 读、写 | **查找、增、删"名字→编号"的对应项** |
| **谁能做** | 所有者与权限 | 同上（见 [[权限位与 ls -l]]） |

**两条对照读出来的关键结论**：

1. **目录里装的不是"文件内容"，而是"文件清单"** —— 精确说是"文件名 → i-number"的表。详见 [[../inode 与链接/inode 与目录文件|inode 与目录文件]]。
2. **目录的操作和普通文件完全不一样** —— 普通文件是"读写字节"，目录是"增删改条目"。

> [!tip] 这解释了 Unix 里目录权限的一个常见困惑
> 对一个**目录**：
> - **`读`（`r`）** = 能列出里面有哪些文件名
> - **`写`（`w`）** = 能在里面**新建 / 删除 / 重命名**条目
> - **`执行`（`x`）** = 能**进入**它、能取到里面文件的元信息
>
> **"在目录里创建文件"需要的不是写文件的权限，而是那个目录的 `w` 权限。** 常见后果：用户对目录有 `w` 但对目录本身进不去时，仍能创建文件，但**列不出**目录内容。
>
> ⚠️ **课件 L03 只讲了 9 位权限位怎么读（见 [[权限位与 ls -l|权限位与 ls -l]]），没有讲目录权限的特殊含义。** 上面这段是根据 Unix 通行语义补的，**标记为背景补充**。

## 五、为什么这个设计重要

把上面四节合起来，得到 Unix 文件系统最反直觉但最有价值的一点：

> [!tip] "一切皆文件"不只是个口号，它有实际后果
> | 后果 | 说明 |
> |---|---|
> | **一套 I/O 代码通吃** | `cp` 一个文件和 `cp` 到终端，代码几乎一样 |
> | **可以用管道串设备** | `cat /dev/input` \| `wc -l` —— 键盘也能被当文件处理 |
> | **权限统一管理** | 设备文件和数据文件用同一套 9 位权限管，见 [[权限位与 ls -l]] |
> | **设备可以被重定向** | `ls > /dev/null` 丢弃输出、`command < /dev/tty` 强制交互 |
>
> 第四条的机制在 [[../重定向与管道/I O 重定向与 dup|I/O 重定向与 dup]]。

> [!note] 本课程尚未覆盖设备驱动开发
> 课件 L01 p2 把 **Device Driver Development** 列为 Part I 的后半部分（含字符设备、块设备驱动开发）。**本目录目前只有 `/dev` 里的文件在用户侧的样子**（本篇），**驱动本身的开发没有笔记**。
> 这也意味着：`/dev/tty`、`/dev/sda` 这些设备文件**在 C 程序里怎么用**（`ioctl` 等）没有覆盖 —— 课件 p35 提到 `ioctl` 是文件描述符相关系统调用之一，但未展开。

## 一句话

> Unix 把**设备也做成文件**（放在 `/dev` 下），于是**一套 `open`/`read`/`write` 通吃所有硬件**；文件分**普通文件**（真的存数据）和**特殊文件**（指向设备），后者再分**块设备**（按块、可跳读）和**字符设备**（按字节流、不可跳读）。
