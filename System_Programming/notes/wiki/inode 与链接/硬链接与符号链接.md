# 硬链接与符号链接

> **一句话**：两种让"**一个文件有多个名字**"的办法。**硬链接**是在目录里**多加一条指向同一个 inode 的记录**（真正共享数据）；**符号链接**是**新建一个只存路径字符串的文件**，读它时再去解析那个路径。前者共享数据、后者只是一个指针。

课件对应 L03 p27–p32。课件原文见 [03-Unix-File-System](<../../raw/03-Unix-File-System.pdf>)。

## 完整场景：需求从哪来

[[inode 与目录文件]] 建立了这个模型：**目录文件是一张"名字 → i-number"的表，inode 里没有文件名。**

现在考虑这个需求：

```bash
$ cp /etc/passwd /tmp/backup_passwd      # 备份一份
```

**问题**：Unix 里"复制"和"多一个名字"是两件不同的事。

| 我想要的 | 该用的命令 | 后果 |
|---|---|---|
| **一份独立副本**（改一个不影响另一个） | `cp` | 占双倍磁盘空间 |
| **同一个文件，多个名字**（改任何一个都反映到所有名字） | **`ln`** ← 本篇 | 只占一份空间 |

**本篇讲 `ln` 的两种形式。**

## 一、硬链接（p27、p28）

### 课件的创建命令（p28）

> *"Hard link creation command: `ln My1.dat My2.dat`"*

### 课件给的示例（p27）

在 [[inode 与目录文件|上一节]] 那张目录表基础上，加一条记录：

| **i-number** | **File name** |
|---|---|
| 123 | `.` |
| 247 | `..` |
| 220 | `dirB` |
| 230 | `My1.dat` |
| **230** | **My2.dat** ← 新增 |

**注意最后两行的 i-number 都是 230。**

**这就是硬链接的全部含义**：

```
目录表：
  My1.dat  → 230
  My2.dat  → 230     ← 两个名字，同一个 inode

inode 230：类型、权限、大小、数据块位置…   ← 只有一份

数据块 A、B、C                              ← 只有一份
```

**所以 `My1.dat` 和 `My2.dat` 是同一个文件**，只是两个名字。它们：

- 共享 inode（**一份元信息**）
- 共享数据块（**一份内容**）
- **改任何一个，另一个立刻反映出来**
- `ls -l` 的**硬链接计数**会是 **2**

> [!tip] 名字变了，inode 不变
> 从 inode 的角度看：**它根本不知道自己有名字**，更不知道有**两个**。
> 名字只是"目录表里的一条记录"。删掉一条记录，inode 一点感觉都没有。
>
> **这正是"名字不在 inode 里"的直接后果。**

## 二、符号链接（p29、p30）

### 课件给的示例（p29、p30）

同样在目录表里新增一条：

| **i-number** | **File name** |
|---|---|
| 123 | `.` |
| 247 | `..` |
| 220 | `dirB` |
| 230 | `My1.dat` |
| 230 | `My2.dat` |
| **250** | **My1SymLink.dat** ← 新增，**i-number 是 250，不同** |

**关键的第二处变化：磁盘上的 Data Block 里多了一块：**

课件 p29/p30 的图在数据块区标出了：

> `Data Block 1923` … `→ ./My1.dat`

**这个 `1923` 正是新分配的 inode 250 所指向的数据块。** 它的内容就是**一串路径**：

```
./My1.dat
```

### 所以符号链接的本质

```
My1SymLink.dat
   │
   ├─ 它自己是一个普通文件（有独立的 inode 250）
   │     类型：普通文件（ls -l 第 1 个字符是 -）
   │     内容："./My1.dat"  ← 一串路径字符串
   │
   └─ 你读它的时候：
          先读出内容 "./My1.dat"
                    ↓
              再去解析这个路径
                    ↓
              找到真正的 My1.dat（inode 230）
```

**它是一个"写着地址的小纸条"。**

> [!warning] 这是符号链接最本质的区别，也是最容易误解的地方
> **符号链接有自己的 inode、自己的数据块。**
>
> 所以：
> - `ls -l My1SymLink.dat` 显示的**类型是 `-`（普通文件）**，**不是** `l`
> - 它**占磁盘空间**（哪怕只有几个字节）
> - 它有自己的权限位（虽然几乎无用）
>
> **"符号链接"这个名字容易误导** —— 它在**目录表里**是个普通文件条目；**只有当它是"指向路径"时才表现出链接的行为**。

## 三、两者对比（p32）

课件 p32 给了三条对照，全部照录：

| | **硬链接 Hard link** | **符号链接 Symbolic link** |
|---|---|---|
| **文件系统限制** | *"Hard links **must be on the same file system**"* | *"symbolic links **can cross file systems**"* |
| **原文件被移动后** | *"Hard linked files **stay linked** even if either one is **moved**"* —— **仍然连着** | *"Symbolic linked files **break if the original is moved**"* —— **断掉** |
| **本质** | *"Hard linked files are **co-…**"*（课件此处被截断，按上下文是"同一个文件的共同名字"） | 一个**存着路径的文件** |

### 三条对比的机制解释

**① 为什么硬链接不能跨文件系统？**

因为跨文件系统意味着**两块磁盘上有两个不同的 inode 表**（见 [[inode 与目录文件]] 第二节：inode 表在每个文件系统的前部）。**i-number 只是本文件系统内的下标**，在另一个文件系统里毫无意义。

```
文件系统 A 的 inode 表      文件系统 B 的 inode 表
  下标 230 → inode           下标 230 → 另一个完全不同的 inode
       ↑ 同一个数字，不同的东西
```

**`ln` 要让两个名字指向同一个 inode，就必须能跨表引用同一个下标 —— 做不到。**

**② 为什么硬链接移动后还连着，符号链接会断？**

| | 移动的是哪个 | 发生了什么 |
|---|---|---|
| **硬链接**：把 `My1.dat` 改名成 `A.dat` | 目录表里那条记录 | 表里仍有"某条记录 → 230"。**只要还有一条记录指向 230，inode 和数据块就都在** |
| **符号链接**：`My1.dat` 改名成 `A.dat` | 目录表里那条记录 | 符号链接**文件内容里存的那串路径 `./My1.dat` 没变**，但**那个路径现在找不到了** |

**关键差别**：硬链接靠的是 **inode 还被引用着**；符号链接靠的是 **那串路径还能被解析**。**移动会破坏路径，不会破坏 inode 引用。**

> [!warning] 但硬链接也不是"移动后永远安全"
> 课件 p32 的原文有一个限定：
> *"Hard linked files stay linked even if either one is moved (**unless the move crosses file system boundaries, triggering copy-and-delete**)"*
>
> **注意括号里那句** —— 跨文件系统移动时，很多工具会做 **copy-and-delete**（复制一份再删原件），这时候**就真的断了**（因为成了两个独立 inode）。
>
> **"移动"在不同工具、不同文件系统间行为不同。** 所以严格说，硬链接"移动后仍相连"这个承诺**只在同一文件系统内、且工具用 `rename` 而不是 copy-and-delete 时成立**。

## 四、`ls -l` 里的一个观察

[[../文件系统结构/权限位与 ls -l|权限位与 ls -l]] 那一篇的示例输出里有这一行：

```
lrwxrwxrwx  1 peleclic  peleclic    9 Oct  6 11:26  link.txt -> notes.txt
```

**逐列读这一个符号链接：**

| 位置 | 内容 | 含义 |
|---|---|---|
| 第 1 字符 | **`l`** | **类型 = 符号链接**（见 [[../文件系统结构/文件类型\|文件类型]]） |
| 后 9 位 | `rwxrwxrwx` | **几乎固定是 `rwxrwxrwx`** —— 符号链接自己的权限没意义 |
| 硬链接数 | **`1`** | 它只有一条目录记录 |
| 大小 | **`9`** | **`notes.txt` 有 10 个字符，`-> ` 占 3 个，剩 7…** 课件未解释这个数字的算法 —— 实际各系统实现不同（Linux 上是**目标路径的字节长度**，`notes.txt` = 9 字节） |
| **结尾** | **`-> notes.txt`** | **符号链接特有的这一段：它指向谁** |

**`->` 后面那段是 `ls -l` 对符号链接的专门处理** —— 你一眼就能看出这是链接以及目标是谁。

> [!tip] 硬链接没有这个标记
> 硬链接在 `ls -l` 里的输出**和普通文件一模一样**，**没有 `->`**，因为**从内核视角它就是个普通文件**，只是有两条目录记录指向它。
>
> **识别硬链接的办法**：看**硬链接计数**那一列。
> ```
> -rw-r--r--  2 alice  staff  1234 ... report.txt
>                            ↑ 硬链接数 = 2
> ```
> **计数大于 1，就说明有硬链接存在。**

## 五、选择哪一种

| 需求 | 用哪个 | 为什么 |
|---|---|---|
| **同一份数据的多个名字，必须是同一份数据** | **硬链接** | 只有它真共享数据 |
| **指向的可能是一个还不存在的文件** | **符号链接** | 硬链接**目标必须已存在**才能建 |
| **跨文件系统** | **符号链接** | 硬链接做不到，见 ① |
| **目标可能被移动/删除** | **硬链接**（同文件系统内） | 符号链接会断，见 ② |
| **不想让删除影响别人** | ⚠️ **两个都有风险** | 见下 |

> [!warning] 删除时的反直觉行为
> | 操作 | 硬链接 | 符号链接 |
> |---|---|---|
> | `rm` **目标** | 只减计数，**数据还在**（另一个名字还在） | 链接变成**断链**，读它报错 |
> | `rm` **链接本身** | 减计数，数据还在 | 只删掉那个小纸条 |
>
> **"删除一个硬链接不会丢数据"** 是很多运维事故的反面：以为删掉了，实际数据还在另一个名字下；等那个名字也被删，磁盘空间才真正释放。
>
> ⚠️ **课件 L03 没有讲删除行为**，上表是根据 inode 引用计数模型补的，**背景补充**。

## 一句话

> **硬链接**是在目录表里**多加一条指向同一个 i-number 的记录**（真共享 inode 和数据块，**同文件系统内**、移动后仍相连）；**符号链接**是**新建一个存着目标路径字符串的普通文件**（有自己的 inode，可跨文件系统，**原文件移动即断**）。
