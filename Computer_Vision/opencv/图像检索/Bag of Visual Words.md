# Bag of Visual Words

全局特征的做法是"一张图 = 一个向量"。但用**局部特征**（关键点上的 descriptor，如 SIFT 那种）时，一张图会产出几十到几百个 descriptor，而且**每张图数量还不一样**，没法一个对一个算距离。BoVW 解决这个。

> **任务：把数量可变的局部描述子集合，转成一个固定长度的图像向量。**

## 三步

### 1. 建视觉词典（codebook）

收集数据库**所有图像**的所有局部 descriptor，对它们跑 K-Means。

- 每个**簇的中心（代表向量）**才是一个 **visual word（视觉单词）**；
- 所有中心合起来是固定的 **codebook / visual dictionary**；
- 簇内的 descriptor 不是"一个词"，而是被量化到同一个词的**实例**。

### 2. 量化：每个局部特征映射到一个词

新图像的每个 descriptor 与词典中**所有簇中心**比较，分配给最近的 visual word，计数 +1。

> [!warning] 这时**不重新跑 K-Means**
> 一旦重跑，词典变了，数据库图的表示和 query 的表示就落在**不同的坐标系**里，直方图之间不可比。

### 3. 统计成词频直方图

长度为 $K$ 的直方图，$K$ 就是建词典时 K-Means 用的簇数。第 $i$ 位记录该图中有多少 descriptor 被分到第 $i$ 个词。

```text
某图 10 个 descriptor 的分配结果：
  word 1：2 个
  word 2：5 个
  word 3：0 个
  word 4：3 个
        ↓
BoVW 特征 = [2, 5, 0, 3]
```

不论原来有多少局部特征，**每张图都变成同样维度的 $K$ 维向量**，于是 [[CBIR 基于内容的图像检索]] 又可以用欧氏距离或余弦相似度排序了。

## 全流程

```text
局部特征集合
→ 用 K-Means 建词典
→ 每个局部特征映射到一个视觉词
→ 统计视觉词频率
→ 固定长度 BoVW 向量
→ CBIR 比较
```

## 优点与缺点

**优点**：突出局部、有区分性的视觉细节。适合"要认的是某个具体图案"的任务——比如 IMHere 那种玩法：要判断上传的 token 照片和库里哪张拍的是同一个地方/同一个物体，靠的是地标性的局部纹理，而整体颜色和光照几乎每张都不同。全局颜色直方图在这种任务上基本失效。

**缺点：丢掉空间布局。**

两张图含相同的圆和三角，一张"圆左三角右"，另一张"圆右三角左"——词频直方图完全一样，但内容不同。

```text
图 A:  ○ —— △        BoVW = [2,5,0,3]
图 B:  △ —— ○        BoVW = [2,5,0,3]   ← 直方图无法区分
```

直方图只保留"每种词出现几次"，等于一个**无序的词袋**，根本没记录 descriptor 的坐标。

| 对比项 | 全局颜色直方图 | BoVW |
| --- | --- | --- |
| 统计什么 | 整图各种颜色的像素数 | 局部关键区域上的视觉词频 |
| 局部区分性 | 弱（整体颜色像，局部可能差很远） | 强 |
| 空间布局 | 无 | **也无**（同一个坑） |
| 两张图如何才能"看起来一样" | 颜色分布几乎相同 | 视觉词频几乎相同 |

## 改进方向（课件未展开）

BoVW 的原始版本丢掉了布局，后续工作有几条补法：

- **几何验证**：先用 BoVW 粗排，再用 descriptor 的实际坐标检查候选图里局部图案的位置是否也对得上，重排结果；
- **空间金字塔（spatial pyramid）**：把图切成网格，逐格算 BoVW，再把各格直方图拼接——相当于给直方图加上粗粒度位置；
- **词对（pairwise words）**：统计"词 A 和词 B 同时出现"的次数，把相对位置关系编码进词表。

## 一句话

> BoVW = 局部特征做 K-Means 变成"词"，再数词频。代价和文本 BoW（Bag of Words，词袋模型）一样：只知有什么，不知在哪。
