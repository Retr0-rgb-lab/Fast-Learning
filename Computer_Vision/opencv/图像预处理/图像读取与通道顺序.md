# 图像读取与通道顺序

OpenCV 读图像的两个核心约定，最容易踩坑。

## 两个根本不同

| 维度 | OpenCV 默认 | PyTorch 默认 |
| ---- | ---- | ---- |
| 数组形状 | `(H, W, C)` = HWC | `(C, H, W)` = CHW |
| 通道顺序 | **BGR** | RGB |

PIL、OpenCV 读图一般是 `(H, W, C)` 的 HWC；`transforms.ToTensor()`（或 `v2.ToImage()`）会改成 `(C, H, W)` 的 CHW。

## `cv2.imread`

```python
img = cv2.imread("cat.jpg")    # shape=(H, W, 3), dtype=uint8, BGR 顺序
```

- 默认 BGR
- 读不出来返回 `None`（不报错），务必检查返回值

## `cv2.cvtColor` —— 颜色空间转换

```python
rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)        # BGR → RGB
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)    # BGR → 灰度
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)      # BGR → HSV
```

## 为什么 OpenCV 默认 BGR

历史原因——早期摄像头/视频流常用 BGR 排布，OpenCV 直接沿用。实际计算（颜色转换、阈值、滤波）顺序无所谓；**唯一要小心的是和别的库/模型对接时别搞反**——RGB 通道搞反，颜色会偏（红变蓝、蓝变红）。

## 通道主导色

- R 通道偏亮 → 暖色（红/橙/黄）
- B 通道偏亮 → 冷色（蓝/青）
- G 通道偏亮 → 偏黄/绿

把一个通道置零会强烈改变色调，是最简单的"滤镜"之一：`img[:, :, 0] = 0` 让蓝色消失。

## 转 PyTorch 张量（手动）

```python
x = img.astype("float32") / 255.0       # 归一化到 [0,1]
x = x.transpose(2, 0, 1)                # HWC → CHW
# 形状 (3, H, W), float32, RGB
```

## 一次性合成：`cv2.dnn.blobFromImage`

如果走 OpenCV DNN 模块，几次转换可以一步到位：

```python
blob = cv2.dnn.blobFromImage(
    img, scalefactor=1/255.0, size=(224, 224),
    swapRB=True, crop=False
)  # 形状 (1, 3, H, W)
```

内部会 resize、可选减均值、BGR↔RGB、再排成 NCHW。

## 一句话

> **OpenCV 出来的数组：(H, W, 3) + BGR；进 PyTorch 要变 (C, H, W) + RGB。**
