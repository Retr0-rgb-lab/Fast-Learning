# 旋转

把图像绕一个中心转过角度 $\theta$。**颜色本身不变，只是每个像素的位置重新计算**。

## 数学本质：极坐标

把图像中心当作极点，一个点写成 $(r,\varphi)$（半径 + 角度）。旋转只有一句规则：

$$
(r,\varphi)\ \longrightarrow\ (r,\ \varphi+\theta)
$$

**半径 $r$ 不变，只改角度**。

例：中心正右方 $(3, 0^\circ)$ 逆时针转 $90^\circ$ 后到正上方 $(3, 90^\circ)$。**整张图的旋转，就是对每个像素做同一件事**。

## 展开成直角坐标

用和角公式 $\cos(\varphi+\theta)=\cos\varphi\cos\theta-\sin\varphi\sin\theta$、$\sin(\varphi+\theta)=\sin\varphi\cos\theta+\cos\varphi\sin\theta$，代回 $x=r\cos\varphi$、$y=r\sin\varphi$：

$$
x' = x\cos\theta - y\sin\theta
$$

$$
y' = x\sin\theta + y\cos\theta
$$

写成矩阵：

$$
\begin{bmatrix}x'\\y'\end{bmatrix}=
\begin{bmatrix}
\cos\theta & -\sin\theta \\
\sin\theta & \cos\theta
\end{bmatrix}
\begin{bmatrix}x\\y\end{bmatrix}
$$

旋转矩阵是**正交矩阵**，保持向量长度（$\sqrt{x^2+y^2}=\sqrt{x'^2+y'^2}$）——这就是"距离中心不变"的数学原因。

## 绕图像中心

上面默认绕原点 $(0,0)$。图像通常绕中心 $(c_x,c_y)$：

$$
\begin{bmatrix}x'\\y'\\1\end{bmatrix}=
T(c)\,R(\theta)\,T(-c)\,
\begin{bmatrix}x\\y\\1\end{bmatrix}
$$

齐次坐标写成 $3\times3$ 矩阵相乘：先 $T(-c)$ 把中心移到原点，再 $R(\theta)$ 旋转，最后 $T(c)$ 移回去。**为什么是"减中心、旋转、加回去"**：旋转矩阵只在原点才成立，绕别的点要先平移到原点附近。

## OpenCV 捷径

```python
# 只能 90° / 180° / 270°（不损失像素）
img_90_cw  = cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)
img_90_ccw = cv2.rotate(img, cv2.ROTATE_90_COUNTERCLOCKWISE)
img_180    = cv2.rotate(img, cv2.ROTATE_180)

# 任意角度
M = cv2.getRotationMatrix2D(center=(w/2, h/2), angle=45, scale=1.0)
rotated = cv2.warpAffine(img, M, (w, h))
```

## $90^\circ$ 旋转的离散索引规则

设原图大小为 $H\times W$，原图像素 `source[y, x]`，顺时针转 $90^\circ$ 后：

```python
target[x, H - 1 - y] = source[y, x]
```

含义拆开：

- 原来的**行** $y$，旋转后变为新的**列相关位置**
- 原来离顶部距离 $y$，旋转后变成离右侧距离，所以是 `H - 1 - y`
- 原来的列 $x$，旋转后变成新图的行

例：原图左上角 `source[0, 0]` 顺时针转 $90^\circ$ 后到目标图右上角 `target[0, H-1]`。

> [!warning] 数组索引是 `[行, 列] = [y, x]`
> 不是数学里常写的 $(x,y)$——旋转代码看起来容易混乱的主因。

## 为什么是 `H - 1 - y` 而不是 `H - y`

因为数组索引从 **0** 开始。高度为 $H$ 的图像，合法行索引是 $0,1,\ldots,H-1$（不是 $1\sim H$）。最底部那一行的索引必须是 $H-1$，`H` 已经越界，会报错。

| 原行 $y$ | 新位置 $H-1-y$ |
| --: | --: |
| 0 | $H-1$ |
| 1 | $H-2$ |
| $\vdots$ | $\vdots$ |
| $H-1$ | 0 |

**翻转一个长度为 $H$ 的索引轴，公式永远是"最大合法索引减当前索引"。**

## 手写任意角度旋转（理解底层）

```python
import numpy as np

src = img
h, w = src.shape[:2]
x0, y0 = w / 2, h / 2
theta = np.deg2rad(90)
c, s = np.cos(theta), np.sin(theta)

dst = np.zeros_like(src)
for y2 in range(h):           # 遍历目标图
    for x2 in range(w):
        # 反向映射：目标 → 原图
        x1 =  c * (x2 - x0) + s * (y2 - y0) + x0
        y1 = -s * (x2 - x0) + c * (y2 - y0) + y0
        x1, y1 = int(round(x1)), int(round(y1))   # 最近邻插值
        if 0 <= x1 < w and 0 <= y1 < h:
            dst[y2, x2] = src[y1, x1]
```

两层循环在干什么：

- **外层/内层**：枚举目标图每个像素 $(x_2, y_2)$
- **反向映射**：用 $R(-\theta)$（即 $R(\theta)^T$）倒推来源坐标
- `int(round(...))` = **最近邻插值**（旋转后坐标常非整数）
- **不反向会怎样**：正向遍历原图 → 转到目标图时坐标常不是整数，可能**出现空洞**（某些目标格子没人写入）

## 为什么反向映射更稳

| 方式 | 过程 | 问题 |
| ---- | ---- | ---- |
| 正向 | 每个原图点 → 目标位置 | 旋转后坐标非整数；某些目标格子没人写 → 空洞 |
| 反向 | 每个目标格子 ← 来源位置 | 必须决定"去原图哪里采样"；来源非整数就用插值估计 |

## 颜色 vs 坐标

> **旋转 = 围绕中心，把每个像素的**位置**重新计算；颜色值本身不变。**
