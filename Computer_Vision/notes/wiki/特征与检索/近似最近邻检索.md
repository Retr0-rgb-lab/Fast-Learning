# 近似最近邻检索

课件里"用 K-Means 做粗到细"这个思想（见 [[粗到细检索]]），被现代向量检索库工程化了。

**向量检索库**：先建立 index，把大量高维向量组织成可快速搜索的结构，查询时快速返回距离最近的 Top-$K$ 个结果。代表工具是 **Faiss**（Facebook 的密集向量相似度搜索库，支持按欧氏距离或内积检索），教程 <https://faiss.ai/>。

## 核心取舍

| | 精确最近邻（暴力检索 / brute force） | 近似最近邻（ANN, Approximate Nearest Neighbor） |
| --- | --- | --- |
| 保证 | 一定找到真正最近的 | **可能漏掉**真正的最近邻 |
| 速度 | 大规模时很慢 | 快很多，内存也更省 |
| 做法 | 全部扫一遍 | 只搜最有希望的少数区域，或用压缩后的表示 |

> **少搜一些地方来换速度，代价是少量召回率风险。**

这和 [[粗到细检索]] 里 top-$k$ 候选簇**完全是同一个取舍**——ANN 只是把它做成了工业级实现。

## 常见技术（课件未展开，作索引用）

| 家族 | 核心思想 | 对应本讲哪个概念 |
| --- | --- | --- |
| **IVF**（倒排文件） | K-Means 分桶，query 只扫最近的几个桶 | [[粗到细检索]] 的一字不差 |
| **PQ**（乘积量化） | 把向量切段、各段用小码本压缩，用查表算距离 | 压缩换内存 |
| **HNSW** | 多层图索引，逐层贪心下降 | 索引组织成树/图，多轮逐层筛选 |
| **PQ + rerank** | 粗排压缩表示 → 精排原向量补召回 | 就是 coarse-to-fine |

评估指标 **recall@k**：真正的 Top-$k$ 里找回了多少（100% = 精确检索，80% 表示漏了两成）。它和延迟、内存占用构成三角权衡。

## 一句话

> ANN = 工业版的 coarse-to-fine。少搜换速度，漏检索是明码标价的代价。
