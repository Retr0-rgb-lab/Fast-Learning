## 为什么按概念轴分，而不是按讲次

**课件的组织方式**（raw 里的文件名）是 `01` / `02` / `03`，对应三次课。但三次课的实际内容不是三块，而是一条链：

```
为什么要做 HCI ──▶ 界面为什么长这样 ──▶ 人这一侧的实际约束
   学科定位              交互的历史           人类信息加工 / 知觉与视觉 / 运动与绩效
   情境与文化
```

而且**重叠区正好落在讲次边界上**：

- Fitts 定律在 L02-b，但它的 $W$ 来自 L03 的视角度量
- "胖手指"灾难在 L01，但它的原理在 L02-b
- 药提醒 App 案例在 L02-b，但它同时是文化问题（L01-b 的人类学）

按讲次切，这些会变成文件夹边界上的断链；按概念轴切，它们降级成普通双链，于是可以被逐条显式连上。这套方法与 Computer_Vision 库 2026-10-03 的重组同源（见那本库的 log）。

## 六个域的划法

| 域 | 回答什么 | 归入标准 |
|---|---|---|
| **学科定位** | 为什么做 HCI？管到哪儿为止？ | 论据性内容，不依赖任何具体机制 |
| **情境与文化** | 同一个"效率"在不同组织/文化里意味着什么？ | 案例落点在**组织、工作方式、文化**，不在机制 |
| **交互的历史** | 今天这套界面从哪一步长出来？ | 按时间与人物组织 |
| **人类信息加工** | 认知加工怎么工作？ | [[人类信息处理器模型]]的**中间段**：记忆、认知、情感 |
| **知觉与视觉** | 眼睛和大脑把数据变成什么？ | 处理器模型的**输入段** |
| **运动与绩效** | 手移到目标上要多快、多准？ | 处理器模型的**输出段** |

> [!note] 一处刻意的取舍
> 「视觉」归入 `知觉与视觉` 而不是单开一个 `计算机图形` 域。L03 的课件标题是 *Visual perception and computer graphics*，但 91 页里**计算机图形只有零星几页**（立方体、Overwatch、Next Car Game 三个"这是三维吗"的游戏截图），主体是知觉。图形那点内容作为"设计师根本没画立方体"这个例子，放在 [[格式塔原则]] 里更合适。

## 用户四条要求 → 落实方式

| # | 要求 | 落实 | 怎么验 |
|---|------|------|--------|
| 1 | 子目录不带数字 | 6 个域全部是名词短语，无 `01/02/03` | `ls notes/wiki/` |
| 2 | 每个知识点建立反向连接 | 每篇末尾 `## 相关笔记`（4–8 条，每条附一句关系说明）；每域 MOC 汇总本域；index 有跨域连接表 | `hci_lint.py` 的**孤儿页 = 0** |
| 3 | 不预设场景，引用场景必须完整介绍 | 例子一律从零写全（样本 / 任务 / 每步 / 为什么），禁止"如上例所示"；课件页码只进 frontmatter 溯源 | 抽查笔记正文搜"如上" |
| 4 | 便于复习，不突兀 | 每篇 `> **一句话**：` 开篇 + `## 一句话收束`；每域 MOC 带「复习路线」；[[HCI-自测题库]] 按域出题 + 连线题 | 通读任一篇能独立成立 |

## 整理原则（长期沿用）

- **目录不带数字**，按概念轴划分，便于长期扩展
- **场景不预设**：任何例子都**从零完整解释**。瑞穗证券、AA965、Three Mile Island、送货车、象人椅、斑点狗、巨人与侏儒、动的是哪趟车，全部按此重写
- **每篇自足**：不引用"课件第几页的例子"而不解释它；课件页码只作溯源标注
- **术语中英对照**，便于对照英文考卷（考试是英文的）
- **frontmatter `domain` 纪律** + `course` / `lecture` / `source`（直链 raw 里的 PDF）
- 标记常见错误（`> [!warning]` callout）
- 跨域的关联集中列在 [[index]] 的「跨域的关键连接」表，避免每篇都重复
