# 正向推理与反向推理

> **一句话**：正向推理是 **if cause, then effect**，反向推理是 **if effect, then cause**；两者都是**递归推理原理，只能用于有形式化限制的良定义问题** —— 所以**已知问题**两个方向都能推，**未知问题**（现象有多个可能原因）**两个方向都不许推，必须逐个原因做经验验证直到只剩一个**。

课件 Human Part 1 p52、p54、p55 这几页。原始 PDF 见 [Human Part 1](<../../raw/02 COMP3423 Human Part 1 2026 09 13.pdf>)。

## 两个方向

| | 正向推理 Forward reasoning | 反向推理 Backward reasoning |
|---|---|---|
| 句式 | **if cause, then effect** | **if effect, then cause** |
| 走的方向 | 原因 → 结果 | 结果 → 原因 |
| 输入 | 已知一个**原因** | 已知一个**结果 / 现象** |
| 输出 | 推出可能的**结论** | 推出可能的**原因** |
| 课件标的用途 | **Data mining**（数据挖掘） | 课件标注为"诊断"方向（见下文已知问题一节） |
| 共同点 | 都是 **rule-oriented reasoning**（规则式推理） | |

> [!warning] 常见错误
> 课件在反向推理那一页加了一句限定：*"Depends on **formal relationship between variables**. If there are more explanations for the same phenomenon, see next slide…"* —— **反向推理能不能用，取决于变量之间的形式关系是不是一对一**。看到"现象"就想"反推原因"，是这个方向最常见的越界。

## 硬性限制：只能解良定义问题

课件把这句放在 p52 单独一页，因为它限定了前面所有内容：

> *"Forward and backward reasoning are **recursive inference principles**. Used to solve **well-defined problems**, which **explicitly have formal limitations (chess, maths)**."*

拆成三个约束：

1. **递归推理原理** —— 反复套用同一条规则直到不能再套。规则是有限的、封闭的。
2. **只解良定义问题** —— 见 [[问题空间与目标状态]]：数据、动作、策略、目标状态都**完整规定**、能在问题空间里表示的那种。
3. **必须有显式的形式化限制** —— 课件点名**国际象棋、数学**。这两个领域的共同点是：规则写死了、合法状态有限、走一步之后哪些走法仍合法是确定的。

**"有形式化限制"是真正的门槛，"我知道这个领域"不是。** 一个领域可以很熟悉但没有形式化限制（比如判断一篇文章好不好），那样的经验不能反向推。

## 玩具规则：反向推理在多解时会退化

课件用一组评分规则演示边界。**这组分数的作用是"给一个社交孤立程度打分"**，从 1 到 6：

| 变量 | 含义 | 取值 |
|---|---|---|
| A | lonely | 1 |
| B | socially isolated | 2 |
| C | need for relationship | 3 |
| D | social robot | 4 |
| — | social media | 5 |
| — | dating site | 6 |

课件给出的两条规则只有两条：

```
if A = 1 ∧ B = 2 then C = 3;
if C = 3, then D = 4
```

### 正向推：可以

已知 $A=1$、$B=2$：

$$
A=1 \wedge B=2 \;\Rightarrow\; C=3 \;\Rightarrow\; D=4
$$

**结果唯一，链条干净。** 这就是正向推理的理想状态：给足前提，顺着推到底。

### 反向推：退化

只知道 $D=4$，问"是因为什么"：

$$
D=4 \;\Leftarrow\; C=3 \;\Leftarrow\; ?\quad\text{即}\quad A=1 \text{ 或 } B=2 \text{ 还是两者都成立？}
$$

课件把这一步写成三个并列的疑问：**A = 1 ? / or B = 2 ? / Both?**

**规则本身没有变，方向一变就退化了。** 原因不是推理能力不足，而是那条规则的**前提是"与"（$\wedge$）**：$A=1 \wedge B=2$ 才推出 $C=3$。已知 $C=3$ 时，我们**无法确定这个"与"的两项各自是否为真** —— 它们可以同时为真，也可以只有一项为真（只要规则写的是"足以"，不是"必要"）。**从合取结论回推，只能得到"至少有一项"的弱结论。**

> [!important] 这就是"1 对 1 关系"的意思
> 课件在 p55 的收尾框里写：*"Logic reasoning — **Only allowed for known problems (must have 1 to 1 relationship)**; Else, **guess and test empirically**."* —— **能推 ⟺ 已知原因和已知结果之间是一对一。** 反向推理不是"更聪明的推理"，它只是**在结果确定指向唯一原因时才合法**。

## 两种情形：已知问题 vs 未知问题

课件用同一个情境（用户刚装了 NVIDIA 的新驱动）分出两种情形，判断依据是**现象有几个可能原因**。

### 情形一：已知问题 → 两个方向都允许

用户说的原话是 *"I just installed that new NVIDIA driver"*（我刚装了那个新的 NVIDIA 驱动）。

**为什么算已知？** 因为**原因已经由用户自己指定了**，而且该原因与某个已知后果之间是"这一台机器的、这一个版本的"具体对应关系，不是"某一类原因指向某一类现象"。

- 正向推：NVIDIA 驱动 → 会出现哪些后果。可推。
- 反向推：出了某个后果 → 是不是这个驱动。**在这个具体范围内也成立**，课件把它标成 **diagnostics（诊断）**。

**这就是"已知"的含义：现象与原因在这个语境下是 1 对 1。** 不是世界上只有这一个原因，而是**在用户已经框定的范围里它是唯一候选**。

### 情形二：未知问题 → 两个方向都不许推

课件紧接着翻到 p54，标题是 *"If the problem is unknown…"*，并先给出限定条件：*(more explanations for the same phenomenon)* —— **同一个现象有多个解释**。

正文是全课件最硬的一句规定：

> *"… you are **NEITHER allowed to reason forward NOR backward** without **empirical validation**, **excluding all causes but 1**."*

拆开看：

- **不许正向推** —— 你不知道原因，无从推起
- **也不许反向推** —— 现象确定，但候选原因不止一个
- **除非做了经验验证**
- **验证的目标是逐个排除，直到只剩一个原因**

**"直到只剩一个"就是退回 [[问题空间与目标状态]] 的那把尺子**：良定义问题要求 $X\cap Y\neq\varnothing$ 可判定；这里的做法就是**用实验把候选集从 N 个缩到 1 个**，然后那个 1 对 1 关系才成立，推理才重新被允许。

## 完整场景：蓝屏死机

课件 p55 把两种情形画在同一张图上：

```
            Cause 1 ──▶ Effect (symptom) 1 ──┐
  Forward reasoning (if cause, then effect)  ├──▶ Logic reasoning
            Cause ? ──▶ Effect               ─┘   只对已知问题允许
  Backward reasoning (if effect, then cause)         （必须是 1 对 1 关系）
                                                  否则：guess and test empirically
```

**情境从头讲起。** 一位用户在自己的机器上装了 NVIDIA 的新驱动。过了一段时间，机器开始出现**蓝屏死机**（blue screen of death，BSOD）—— 屏幕变蓝并显示一串错误代码，机器当场停住。

现在的问题是：**是新驱动引起的吗？**

- 这个"蓝屏"**不是单一现象的唯一原因**。驱动版本冲突、内存故障、硬盘坏道、系统文件损坏、其他设备的驱动问题，**都可能产生同样的蓝屏**。所以它是情形二：**同一个现象有多个解释**。
- 于是**正向和反向都不许推**。用户说"我装了驱动"并不能自动推出"就是驱动的错"，也不能从"蓝屏"自动推出"是驱动的错"。

**课件给出的唯一出路**：*"Else, **guess and test empirically**"* —— **猜，然后实测**。也就是把候选原因一个个当成待验假设，逐个改配置、逐个看蓝屏还发不发生：

| 步 | 动作 | 蓝屏还发生吗 |
|---|---|---|
| 1 | 换回旧版驱动，观察 | 不再蓝屏 → **只剩这一个原因** |
| 1' | 若仍蓝屏，则旧版驱动不是原因 | 保留其余候选 |
| 2 | 逐个排除内存、硬盘、系统文件…… | 直到候选集只剩 1 个 |

**只有当蓝屏消失、原因被锁定为"新驱动"之后，1 对 1 关系才建立起来，反向推理才重新合法**（"有 BSOD 的那台机器，就是装了这个驱动的那台"）。

课件在这一页的图上标着 *"Installed NVIDIA driver"*（作为已知条件的注记）与 *"NVIDIA driver¹"*（脚注 1，指向"只对已知问题允许"那条规则），正说明：**"已知"是推理的许可证，不是推理的结论。**

> [!tip] 一个更老的例子
> 课件在同一张图上放了一条更简单的因果链：*smoke → fire*（烟 → 火）。有烟**不必然**有火（也可能是蒸汽）；有火**可能**是因为烟，也可能是别的。**正向"烟⇒火"不成立，反向"火⇒烟"也不成立。** 这条链是"1 对 1 关系不成立"的最短反例。

## 一句话收束

> 正向 if cause then effect、反向 if effect then cause，两者都是只对**良定义且有形式化限制**的问题有效的递归推理；**多解时反向推理退化成猜测**，所以"1 对 1 关系"是推理的许可证 —— 拿不到许可证时，唯一的合法动作是**逐个猜、逐个实测、排到只剩一个**。
