# 类比推理

> **一句话**：类比推理**不找相似的东西，它找关系** —— 在"特征与类别"之间建立一条关系 $R$，使得另一组"特征与类别"之间的关系与 $R$ 相似；而这条**关系必须由人自己填进去**（课件标成 `<void>` + *fill in*），**填错整条类比就垮**。

课件 Human Part 1『Analogical reasoning』起的一组页。原始 PDF 见 [Human Part 1](<../../raw/02 COMP3423 Human Part 1 2026 09 13.pdf>)。

## 定义：找的是关系，不是相似

课件的定义原句：

> *"Analogical reasoning looks for **relations between features and categories** that are **similar to relations between other features and categories**."*

这句话要把三层拆开才读得懂：

| 层 | 是什么 | 例子中的取值 |
|---|---|---|
| **特征 features** | 某一方的可观察属性 | pulse（搏动） |
| **类别 category** | 特征所属的那个整体 | computer / human being |
| **关系 relation** | 特征与类别之间的那个说法 | **要人来填** |

**两边的"特征–类别"关系要相似，而不是两边的特征要相似。** 一台计算机不搏动，一个死人不思考，**它们本身毫无共同点**；让它们产生可比性的是那条被填进去的关系。**"相似"发生在关系层面，不在特征层面。**

## 完整例子：时钟信号是计算机的心跳

### 情境

一台 UNIX 机器上有个硬件叫**时钟信号**（clock signal）—— 一个周期性脉冲，用来给整台机器的电路排时。UNIX 手册里有一句话这么向使用者解释它：

> *"The clock signal is the **heartbeat** of your computer."*（时钟信号是你计算机的心跳。）

用户看到这句话，脑子里发生了一次类比推理。课件把这张图逐步填满，我们跟着它填。

### 第 1 步：摆出两侧

```
        clock signal            heartbeat
             =                      ?
```

左边的对象是时钟信号，右边的对象是心跳。课件接下来给两侧各贴一个类别标签：

```
        clock signal            heartbeat
             =                      ?
     Category: Computer       Category: Human being
```

**两边的类别不同**（一个是机器，一个是人），这正是类比推理的用武之地 —— 如果类别相同，那就不是类比，是同类比较。

### 第 2 步：给两侧同一个特征

```
      Features: pulse        Features: pulse
```

**两侧的特征是同一个词：pulse。** 时钟信号是周期脉冲，心跳也是周期脉冲。**到这里类比已经成立了** —— 但课件说这还不是类比推理的**全部**。

### 第 3 步：关系留空，由人来填

```
      Features: pulse        Features: pulse
      Relation: <void>       Relation: <void>
                                      fill in
```

课件在两边各写一个 **`<void>`（空）**，在人体那侧标 **fill in**。这就是这一页最关键的一个动作：

> **类比推理不会自动给出关系。** 手册给了"心跳"这个词，特征"pulse"是人自己认出来的，**而"搏动"与所属整体之间到底是什么关系** —— 是"维持"、"节律"、"生命体征"、"被整个系统依赖"？—— **课件不提供，必须人自己补。**

### 第 4 步：补上关系，整条类比才成立

```
   clock signal : computer :: heartbeat : human being
```

**这一行就是补完的类比。** 读法是：`时钟信号`之于`计算机`，如同`心跳`之于`人`。中间那条被填进去的关系，两边确实相似 —— 都是**维持所属整体正常运转的周期性节律**。

> [!important] 为什么"关系留空"是这一页的考点
> 因为**特征"pulse"相同并不能保证类比有效**。如果人把关系填成"两者都会发出声音"，这条类比立刻垮掉 —— 时钟信号在正常工作时根本不发出可听的声音。**关系填错，特征再像，结论也是错的。** 这也是类比推理**容易出错**的根源：它在 [[问题解决的策略谱系]] 的连续谱上横跨智能与创造两端，因为它**一半是可检查的（关系填对了吗），一半是不可检查的（该找哪两个领域来比）**。

## 基于案例的推理：类比推理的一种

课件紧接着给了一条格式串，并明确它是类比推理的一个子类：

> *"**Case-based reasoning is a type of analogical reasoning**"*
> *"Old solution : old problem :: **adapted solution** : new problem"*

**注意第三个位置写的是"改造后的解"（adapted solution），不是"解"。** 这是它与上一节那个类比的唯一区别，也是它更实用的原因：**结论不是"照抄"，是"改造过"。**

### 完整的六步流程

课件画了一张流程图，标了 (1) 到 (5) 五步。把左右两栏对起来读：

```
  ① Case base（案例库）          ④ Similar problem（相似问题）
     ├─ 具体问题 Specific problem │    └─ 具体解 Specific solution
     └─ 具体解   Specific solution│
  ② Reasoning (from first principles)
     └─ 沿案例库的推理
  ③ Adaptation（改造）
     ├─ 相似解 Similar solution
     └─ Does same reasoning apply?（同样的推理还成立吗？）
```

逐条说明这五步各自在干什么：

| 步 | 名称 | 做什么 |
|---|---|---|
| (1) | 案例库 Case base | 存着过去解决过的问题及其解，每条都是"具体问题 → 具体解" |
| (2) | 推理 Reasoning (**from first principles**) | 拿着新问题去案例库里比，**从第一性原理重新推**一遍，而不是背结论 |
| (3) | 相似问题 Similar problem | 在案例库里找到结构最像的那一条 |
| (4) | 相似解 Similar solution | 取出那条的解 |
| (5) | **改造 Adaptation** | **关键的第 5 步**：问一句 *"Does same reasoning apply?"*（同样的推理还成立吗？），然后把它改造成新问题的解 |

**整套流程里唯一不可省的是第 5 步。** 第 2 步特意标注 **from first principles**（从第一性原理出发），是为了防止把旧解当成可以直接用的答案；而第 5 步的设问是逼你回答"**这次也一样吗**"。

> [!tip] 类比
> 这一步与 [[问题解决的策略谱系]] 里的问题空间是同一件事的两面：案例库是一个**已经走过的路径集合**，Adaptation 是**在新空间里对应地改一步**。相似度判断错了，第 5 步就是错的。

## 完整拆解：斧头与啄木鸟

课件的例子里有一件真实设计作品：**一把受啄木鸟启发的营用斧（woodpecker-inspired camp axe）**，被用作 "more balanced swing and more efficient blow"（挥动更平衡、劈砍更高效）。

课件给了五步，从头走一遍：

### 第 1 步：说出毛病

> 1) **Axe imbalance and inefficiency** —— 这把斧子**不平衡，而且效率低**。

只陈述缺陷，不提任何解法。**这是关键的第一步：起点是问题，不是灵感。**

### 第 2 步：找联想

> 2) **Who in nature works like an axe? (association)** —— **自然界里谁像这把斧子？**（联想）

课件在这一步后面专门注了 **association**（联想）两个字。**这是类比推理"创造的那一半"**：从"一把不平衡的斧子"跳到"自然界里某个东西"。

> [!warning] 这一步没有任何保证
> 联想**可以跳到任何地方**，包括跳到一个完全无关的东西上。课件把这步标成 association 而不是 reasoning，就是在提示：**它的产物需要下一步验证。** 这也是它同时属于智能与创造两端的原因。

### 第 3 步：看它怎么做的

> 3) **How does he do it?** —— 它是怎么做到这一点的？

**从"像"追问到"怎么做到的"。** 这一步把第 2 步的模糊相似，逼成一个**可观察的机制**。若这一步走不动（只相似但说不清怎么运作），整条类比就只是巧合。

### 第 4 步：改造过来

> 4) **Adapt woodpecker neck form to fit my camp axe** —— **把啄木鸟脖子的形状改造到我的营用斧上**。

产物是一件真实存在的设计件。**注意"改造"这个动词**：不是复制一只鸟，是把**脖子那个部位的形状**搬到斧头上。

### 第 5 步：抽出原理

> 5) **It is probably for the same reason that it works so well (energy absorption)** —— **它之所以这么有效，很可能是因为同一个原理（能量吸收）**。

**注意 `probably`。** 第 5 步给出的是**一个可能成立的解释**，不是被证明的定律。**类比推理的产出是一台"很像对的机器"，不是一个"已被证明的机制"。**

### 课件的收尾

> *"The creative combination is in the **abstraction of finding similar/same principles in otherwise unrelated domains**."*（创造性的结合在于：**在毫不相干的领域里找到相同原理的那个抽象**。）

**关键词是 abstraction（抽象），不是 similarity（相似）。** 斧头和啄木鸟的脖子在物理上毫无共同点；**真正被搬过来的是"如何吸收冲击能量"这个抽象原理。** 创造性不在于找到两个相像的东西（那不需要创造），而在于**识别出那个跨领域的共同原理**。

## 一半智能，一半创造

课件给了这一节的总评：

> *"Analogical reasoning is **halfway intelligent and creative problem solving**: It has a **reasoning** and an **associative** side."*

| | 推理的一面 | 联想的一面 |
|---|---|---|
| 出现在第几步 | 第 1、3、5 步 | 第 2 步（association） |
| 可检查吗 | 可检查：关系填对了吗 / 机制说得清吗 / 原理抽得出来吗 | **不可检查**：为什么偏偏想到这个领域 |
| 属于 | 智能 · 收敛 | 创造 · 发散 |
| 失败的表现 | 关系填错 → 类比垮 | 跳到无关领域 → 浪费一次尝试 |

**这解释了类比为什么在 [[问题解决的策略谱系]] 的连续谱上横跨中段**：它有可检查的内核，也有不可检查的入口。**类比推理的可靠性不均匀 —— 它的后半段（验证）比前半段（联想）可靠得多。**

## 一句话收束

> 类比推理找的是**关系**而不是相似；特征和类别是给定的，**关系必须人自己填，填错整条垮**；基于案例的推理是它的一个子类，格式是 `旧解 : 旧问题 :: 改造后的解 : 新问题`；创造性的部分在"在毫不相干的领域找到相同原理的那个抽象"。
