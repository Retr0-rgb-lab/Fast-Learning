# 类与对象 · Classes and Objects

> **一句话**：**类（Class）≈ 对象（Object）** 就像 **类型（Type）≈ 变量（Variable）**。类封装**状态（属性）**与**行为（操作）**。

课件原文见 [05. System Modelling](<../../raw/05. System Modelling.pdf>)。所属视角见 [[系统建模-定义与视角]]。

## 类与对象的类比

> **Class ≈ Object，其地位相当于 Type ≈ Variable**（例如 `int x` 中 `int` 是 type，`x` 是 variable）

| | 是什么 |
|---|---|
| **类 Class（蓝图）** | 定义**抽象数据类型**，规定被创建的对象将具有**哪些属性（状态）和方法（行为）** |
| **对象 Object（实例）** | 内存中分配的**具体运行期实体**，其中持有那些属性的**真实数据值** |

## 类图的作用

**类图展示面向对象系统的静态结构** —— 画出它的**类（classes）及其关系（relationships）**。

- **类**：定义某一类系统对象的**模板或数据类型**；具体的数据条目被**实例化为该类的对象（objects）**。
- **应用范围**：贯穿软件开发的三个阶段 ——
  - **分析**阶段的**领域建模（domain modeling）**
  - **设计**阶段的**系统结构（system structure）**
  - **实现**阶段的**代码架构（code architecture）**

## 类的组成

**一个类封装了状态（attributes）与行为（operations）。**

- **每个属性都有类型（type）**
- **每个操作都有签名（signature）**
- **类名是唯一强制的信息** —— 属性和操作都可以省略

### 记号约定

| 记号 | 含义 |
|---|---|
| `-` | private 私有 |
| `+` | public 公开 |
| `#` | protected 受保护 |
| `/` | derived 导出（派生属性） |
| *下划线* | static 静态 |

### 一个完整的类记号（自行补全）

某个 `Octopus` 类有属性 `amount`、`ID`，有操作 `getAmount()`、`getID()`、`withdraw(int)`。按上述记号画出这个类。

> 练习要点：**类名是唯一必填项**。如果你在设计时写不出属性和操作，说明对类的职责还没想清楚 —— 这本身就是一次有用的检验。
