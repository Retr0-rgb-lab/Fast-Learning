# 类之间的关系 · Relationships

> **一句话**：类之间有两类关系 —— **实例级（instance-level）** 的依赖、关联、聚合、组合；**类级（class-level）** 的泛化、实现/实现化。**判断聚合与组合靠生命周期，不靠多重性。**

课件原文见 [05. System Modelling](<../../raw/05. System Modelling.pdf>)。所属视角见 [[系统建模-定义与视角]]。

## 关系分类

| 层次 | 关系 | 英文 |
|---|---|---|
| **实例级**（对象也称为**实例** instance） | 依赖 | Dependency |
| | 关联 | Association |
| | 聚合 | Aggregation |
| | 组合 | Composition |
| **类级** | 泛化 | Generalization |
| | 实现 / 实现化 | Realization / Implementation |

## 依赖 · Dependency

**依赖 = 依赖方（dependent）与独立方（independent）之间的一种语义联系（模块之间）。**

- 如果对**一个类（模块）的定义**（服务器方 / 目标方）发生变化，**可能导致另一个类（客户方 / 源方）发生变化**，就存在依赖。

> 判据是**"改 A 会不会牵连 B"**，而不是"运行时会不会互相调用"。

## 关联 · Association

**关联 = 类实例之间的一种关系类型。** 类的对象**可以使用该关联进行通信**，例如：

- 类 A **有一个类型为 B 的属性**
- 类 A **创建 B 的实例**
- 类 A **收到一个以 B 为参数的消息**

### 关联上的可选元素

- **名称 name**（可选）
- **阅读方向 reading direction**（可选）
- **角色 role**（可选）
- **多重性 multiplicity**（可选）

## 关联的多重性 · Multiplicity

**多重性表示该类的对象中有多少个参与到这个关系中。**

| 类型 | 示例 |
|---|---|
| 一对一 | 1-to-1 |
| 一对多 | 1-to-many |
| 多对多 | many-to-many |

### 完整示例（自行补全）

一个公司有员工，员工在公司工作（`Person` 与 `Company`，多对多，"works for"）。
一位母亲有孩子（`Mother` 对 `Child`，"1..\*"）。
一个城市是某个国家的首都，一个国家有一个首都（`City` 对 `Country`）。

> [!important] 读法：数字标在哪一端，就算的是**哪一端的类**的实例数
> `City 1` —— `Country 0..1`「is capital of」，含义是：
> **对每一个 Country，有 1 个 City**（一个国家恰有一个首都）；
> **对每一个 City，有 0 或 1 个 Country**（一个城市最多是一个国家的首都）。
>
> **这是最容易读反的地方。** 读多重性时，永远先问："我现在是以哪一个类为**'一个'**？"

## 泛化 · Generalization

**泛化关系表达一种 "is-a"（是一种）关系。**

- **泛化通过继承（inheritance）实现**
- **子类继承父类的属性和操作**
- **泛化通过消除冗余来简化模型**
