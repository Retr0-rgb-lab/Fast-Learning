# 软件过程 · Software Process

> **一句话**：软件过程是**开发一个软件系统所需的一组有组织的活动**。它是软件工程的支柱 —— 把"个人英雄式发挥"变成"组织能力"，同时为审计、合规提供基线，并让系统随时间推移的众多变动保持可控。

课件原文见 [02. Software Processes](<../../raw/02. Software Processes.pdf>)。

## 过程描述包含什么

描述一个过程时，除了**活动**（做什么）和**活动的顺序**，通常还包括三类信息：

| 要素 | 英文 | 含义 |
|---|---|---|
| 产物 | Products / deliverables | 某个过程活动的**产出** |
| 角色 | Roles | 参与该活动的人所承担的**职责** |
| 前置/后置条件 | Pre-/post-conditions | 活动被执行前 / 产物被产出后**成立的事实** |

> **要点**：只说"活动 + 顺序"是不完整的描述。条件（condition）常常才是判断"这次执行和上次执行有何不同"的关键。

## 两类风格

| 风格 | 英文 | 特点 |
|---|---|---|
| 计划驱动 | Plan-driven | 所有过程活动**事先全部计划好**，进度对照该计划度量 |
| 敏捷 | Agile | 计划是**增量的**，改变过程以反映变化的需求更容易 |

- 实践中多数过程**同时含有两者的成分**。
- **没有"正确"或"错误"的软件过程**；只有是否适合当前情境。

## 四类基本活动

任何软件过程都会涉及这四类活动，它们是理解后面所有内容的骨架：

| 活动 | 英文 | 做什么 | 详见 |
|---|---|---|---|
| 规格 | Specification | 定义系统**应该做什么** | [[需求工程-定义与过程]] |
| 开发 | Development | 产出满足规格的**软件** | [[软件过程-四活动]] |
| 验证与确认 | Verification and validation | 检查它**符合规格**且**满足用户需求** | [[软件过程-四活动]] |
| 演化 | Evolution | 修订系统以**修错**并适应**业务/技术需求的变化** | [[软件过程-四活动]] |

## 关键结论

- **V&V 的目的是"符合规格"且"满足用户需求"两件事** —— 这是 [[软件过程-四活动]] 中 verification 与 validation 的分工依据。
- 过程应当包含**原型化**和**增量交付**这类活动来应对变更，见 [[应对变更]]。
- **通用过程模型**描述的是软件过程如何组织，主要有三种：**瀑布模型**、**增量开发**、**复用式开发**。
